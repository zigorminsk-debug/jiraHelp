## 1. Что это за программа

### 1.1 Одна фраза

**KerioCertManager** — это «швейцарский нож» для администратора **Kerio Connect**: одна программа на Windows, которая:

- делает и ставит **SSL-сертификат** (чтобы браузер и почтовые клиенты не ругались «сайту нельзя доверять»);
- **проверяет почту** по 20+ параметрам и пишет по-русски, что именно сломано и как починить;
- помогает **выйти из спам-чёрных списков**, генерируя готовые письма в поддержку;
- проверяет **санкционные и гео-ограничения** для домена и IP;
- **ставит и обновляет антиспам-базу** в Kerio Connect с GitHub.

### 1.2 Аналогии, чтобы стало понятно

| Слово | Простая аналогия |
|---|---|
| **SSL-сертификат** | Пломба на двери магазина + паспорт сайта. Без неё браузер пишет «небезопасно», а Outlook — «сертификат недействителен» |
| **Домен** (`mail.company.by`) | Адрес дома, понятный людям |
| **IP-адрес** (`93.125.10.25`) | Координаты дома, понятные компьютерам |
| **DNS** | Телефонная книга интернета: «домен → IP» |
| **A-запись** | Строка в этой книге: «mail.company.by живёт по адресу 93.125.10.25» |
| **MX-запись** | Строка «кто принимает почту для company.by» |
| **PTR-запись** | Обратная строка: «по адресу 93.125.10.25 живёт mail.company.by». Это как обратный адрес на конверте |
| **SPF** | Список тех, кому разрешено отправлять письма от имени вашего домена |
| **DKIM** | Печать/подпись на каждом письме: «это правда от нас и письмо не подменили» |
| **DMARC** | Инструкция «что делать, если печать не совпала» — в спам, в карантин или удалить |
| **RBL / DNSBL** | Чёрные списки плохих IP-адресов, которыми пользуются почтовые серверы всего мира |
| **ACME / Let's Encrypt** | Автоматическая служба выдачи бесплатных SSL-сертификатов |
| **Порт** | Дверь в доме. Порт 443 — «дверь для сайта», 25 — «дверь для почты», 4040 — «служебная дверь Kerio» |
| **SHA-256** | Отпечаток пальца файла. Если файл подменили — отпечаток изменится |

### 1.3 Восемь вкладок = восемь отделов

| Вкладка | Когда открывать |
|---|---|
| 🔐 **Выпуск сертификата (IP + Домен)** | Нужен новый SSL-сертификат для сайта или почты |
| 📬 **Установка в Kerio Connect** | Сертификат есть, надо поставить его в Kerio |
| 📨 **Проверка почты и Антиспам** | «Письма не доходят», «попадают в спам», «что у нас с почтой» |
| 🚑 **Выход из Блэклистов и Письма** | Сервер попал в чёрный список, нужны готовые письма на разблокировку |
| 🌍 **Санкции и Гео-блокировки** | Не выдаётся сертификат, домен не виден за границей, «нас заблокировали» |
| 📂 **Выпущенные сертификаты и Автопродление** | Посмотреть, что уже выпущено, и включить автообновление |
| 🛡️ **Антиспам-база KCM (GitHub)** | Надо усилить защиту от спама/фишинга и держать базу свежей |
| 🧰 **Инструменты админа** | Разобрать заголовки письма, собрать DNS-записи |

### 1.4 Что программа НЕ делает

- ❌ **Не заменяет админа.** Она показывает проблему и даёт инструкцию, но DNS-записи и настройки Kerio всё равно вносятся руками (в панели регистратора и в Kerio WebAdmin).
- ❌ **Не является антивирусом.** Антиспам-база — это правила для спама/фишинга, а не защита от вирусов.
- ❌ **Не отправляет письма от вашего имени** без вашего действия: тестовое письмо уходит только по нажатию кнопки.
- ❌ **Не платит и не подаёт заявки автоматически** в Spamhaus/Microsoft: она готовит письмо и открывает портал, отправляете вы.

## 2. Первый запуск

### 2.1 Откуда взять

В репозитории проекта лежат два файла:

- **`KerioCertManager.exe`** — сама программа (один файл, ~10,5 МБ, ничего ставить не нужно);
- **`KerioCertManager-Windows-x64.zip`** — архив: программа, инструкция `README-Инструкция.md`, этот ФАК (`FAQ-Полная-инструкция.md`) и 4 значка на выбор.

Ссылки для скачивания:

- https://github.com/zigorminsk-debug/jiraHelp/raw/arena/f70f3591-jirahelp/KerioCertManager.exe
- https://github.com/zigorminsk-debug/jiraHelp/raw/arena/f70f3591-jirahelp/KerioCertManager-Windows-x64.zip

### 2.2 Что нужно на компьютере

| Требование | Подробности |
|---|---|
| Windows | Windows 10 / 11 или Windows Server 2012 R2 и новее, 64-бит |
| WebView2 | Обычно уже установлен (вместе с Windows или Edge). Если нет — программа откроет интерфейс в обычном браузере |
| Права | Для большинства действий — **локальный администратор** |
| Интернет | Нужен для Let's Encrypt, проверок, GitHub. Для локального (self-signed) сертификата — не нужен |
| .NET / Python / OpenSSL | **Не нужны.** Всё внутри одного `.exe` |

### 2.3 Запуск

1. Скопируйте `KerioCertManager.exe` в **постоянную папку**, например `C:\KerioCertManager\`. Не запускайте из архива и не из «Загрузок»: рядом с программой создаются папки `certs` и файлы настроек.
2. Нажмите по файлу **правой кнопкой → «Запуск от имени администратора»**.
3. Если Windows покажет синее окно «SmartScreen» — нажмите **«Подробнее» → «Выполнить в любом случае»**. Это нормально для программ без платной подписи Microsoft.
4. Откроется окно программы (1380×940). Внутри — обычная веб-страница, но она работает **локально**: адрес `http://127.0.0.1:17840`, снаружи он недоступен.

> ⚠️ Если окно не открылось, а в браузере появилась страница — значит, WebView2 не установлен, и программа открыла интерфейс в Edge/Chrome. Так работать можно, но лучше поставить «Microsoft Edge WebView2 Runtime» — окно будет отдельным.

### 2.4 Права администратора: зачем и как проверить

Без прав администратора вы **сможете**: смотреть, проверять почту, строить отчёты, выпускать сертификат в папку пользователя.

Без прав **не сможете**: писать в `C:\Program Files\Kerio\...`, перезапускать службу `KerioMailServer`, открывать порт 80/443, создавать задания Планировщика, менять значок окна Windows.

**Как понять, что права есть:** в шапке нет предупреждения о правах, а операции с Kerio проходят. Если что-то не так — закройте программу и запустите снова «от имени администратора» (либо воспользуйтесь кнопкой повышения прав в шапке, если она показана).

### 2.5 Что происходит при первом запуске

- Программа создаёт рядом с собой папку **`certs`** — там будут сертификаты, настройки и база.
- Подставляет вашу последнюю почту/домен, если они уже вводились раньше (настройки сохраняются автоматически).
- Пытается определить **внешний IP** — для этого она делает несколько запросов (DNS DoH → SPF → внешние сервисы). Это нормально.
- В журнале внизу появляется строка «Программа … готова к работе».

### 2.6 Как закрыть

- Кнопка **⏻ Выход** в правом верхнем углу — корректно закрывает окно и локальный сервер.
- Крестик окна — то же самое.
- ❌ Не оставляйте программу запущенной «на всякий случай» на годы: она держит локальный порт. Закрывайте после работы.

## 3. Вкладка 1 — Выпуск сертификата

Это самая первая и самая важная вкладка. Здесь создаётся SSL-сертификат.

### 3.1 Что заполнять (сверху вниз)

Поля сгруппированы в три карточки: **«1 Доменное имя и IP-адрес почтового сервера»**, **«2 Режим выпуска и способ подтверждения Let's Encrypt»**, **«3 Параметры ключа (.key) и установка в Kerio Connect»**. Ниже — все поля по порядку.

| Поле | Что писать | Пример |
|---|---|---|
| **Доменное имя сервера (CN / DNS) *** | Имя, на которое нужен сертификат. Обычно `mail.вашдомен` | `mail.company.by` |
| **Дополнительные домены (SAN — только те, для которых есть A-запись в DNS)** | Другие имена, которые будут работать по тому же сертификату. Добавляются кнопками `webmail`, `autodiscover`, `smtp`, `imap`, `pop3`; крестик **✕ Очистить** убирает все | `webmail.company.by` |
| **IP-адрес сервера *** | Внешний (белый) IP, на который указывает домен. Можно IPv4 или IPv6 | `93.125.10.25` |
| **Email администратора** | Куда Let's Encrypt пришлёт письмо, если сертификат перестанет продлеваться | `postmaster@company.by` |
| **Метод подтверждения (ACME Challenge)** | Как вы докажете, что домен ваш (см. 3.3) | HTTP-01 (порт 80) |
| **Локальный порт приёма проверки** | Порт, на котором программа поднимет временный сервер проверки | `80` |
| **Путь к корневой папке веб-сайта (Webroot)** | Только для метода Webroot | `C:\inetpub\wwwroot` |
| **Срок действия сертификата (дней)** | Только для локального (self-signed) режима | `365` |
| **Алгоритм и формат приватного ключа** | Для Kerio — RSA 2048 в формате PKCS#1 | оставить по умолчанию |
| **Пароль для PFX-архива** | Необязательно. Пусто = `.pfx` без пароля | — |
| **Папка сохранения сгенерированных ключей и сертификатов** | Куда сложить результат. По умолчанию `certs` рядом с программой | `C:\KerioCertManager\certs` |
| **Путь к папке sslcert Kerio Connect** | Куда Kerio ставит сертификаты | `C:\Program Files\Kerio\MailServer\sslcert` |

> 💡 **Совет.** Если нужен только `mail.company.by`, оставьте SAN пустым. Добавляйте SAN заранее: сертификат на 5 имён ничем не хуже, а перевыпускать не придётся.

### 3.2 Три режима — какой выбрать

| Режим | Что даёт | Когда использовать |
|---|---|---|
| 🟢 **Let's Encrypt** | Настоящий доверенный сертификат на 90 дней (или 6 дней для сертификата с IP) | Всегда в «бою» |
| 🧪 **LE Staging** | Точно такой же процесс, но сертификат тестовый, браузер ему не доверяет. **Лимитов нет** | Сначала потренироваться, чтобы не исчерпать лимиты Let's Encrypt |
| ⚡ **Локальный (Kerio)** | Мгновенный «самоподписанный» сертификат без интернета | Тесты, внутренняя сеть, когда LE недоступен |

> ⚠️ **Лимиты Let's Encrypt.** На один домен можно выпускать ограниченное число сертификатов в неделю. Если вы «пробуете и не получается», сначала используйте **🧪 LE Staging**, а на боевой режим переходите, когда всё заработало.

### 3.3 Четыре способа подтверждения (главная таблица)

Let's Encrypt должен убедиться, что домен действительно ваш. Есть 4 способа:

| Способ | Что нужно | Плюсы | Минусы |
|---|---|---|---|
| **HTTP-01 (порт 80)** | Открытый из интернета порт 80, домен указывает на ваш IP | Работает почти всегда, просто | Если порт 80 занят Kerio — программа на 5–10 секунд остановит службу и сразу запустит её снова |
| **TLS-ALPN-01 (порт 443)** | Открытый порт 443 | Не нужен 80 | Порт 443 тоже часто занят |
| **HTTP-01 Webroot** | Порт 80 свободен, есть папка сайта (IIS/nginx) | Ничего не останавливает | Нужен настроенный веб-сервер |
| **DNS-01 (TXT-запись)** | Доступ к панели DNS домена | **Работает даже при полностью закрытых портах**, за NAT, из закрытой сети | Нужно вручную добавить TXT-запись и подождать DNS |

**Как выбрать:**

- Порт 80 открыт и свободен → **HTTP-01**.
- Порт 80 занят Kerio → **HTTP-01** с галочкой авто-остановки службы, либо **TLS-ALPN-01** (порт 443).
- Порты закрыты / сервер за NAT / нужно выпустить сертификат «откуда угодно» → **DNS-01**.
- Есть свой веб-сервер и не хочется трогать службы → **Webroot**.

### 3.4 Что делают кнопки

**✨ Найти существующие поддомены в DNS** — программа спрашивает DNS: «есть ли у домена `webmail`, `autodiscover`, `smtp`, `imap`, `pop3`?» и добавляет в SAN только те, что реально существуют. Это защищает от ошибки «домен не существует» при выпуске.

**Кнопки `+ webmail`, `+ autodiscover`, `+ smtp`, `+ imap`, `+ pop3`** — быстро добавляют стандартные имена Kerio.

**🌐 Внешний IP** — программа определяет ваш белый IP. Полезно, если сервер за NAT и вы не знаете, какой адрес видят снаружи.

**🔍 Проверить DNS, IP и порт** — предпроверка. Ничего не выпускает, только проверяет:
- существует ли домен и на какой IP он указывает;
- совпадает ли этот IP с тем, что вы ввели;
- открыт ли порт 80/443 из интернета;
- не мешает ли NAT.

**🔐 Сгенерировать ключ и выпустить сертификат** — главная кнопка: создаёт ключ, проходит проверку ACME, сохраняет сертификат.

**📬 Установить в Kerio Connect** — мгновенно переходит к установке (см. раздел 4).

### 3.5 Как читать предпроверку

| Что показывает | Что значит | Что делать |
|---|---|---|
| ✅ «DNS A-запись совпадает с IP» | Всё правильно | Продолжать |
| 🔴 «A-запись указывает на другой IP» | Домен ведёт не туда | Исправить A-запись в панели DNS, подождать 5–30 минут |
| 🔴 «Домен не существует» | Опечатка или запись ещё не создана | Проверить написание, создать A-запись |
| 🔴 «Порт 80 закрыт» | Проверка снаружи не пройдёт | Открыть порт на роутере/файрволе или выбрать DNS-01 |
| 🟠 «Порт 80 занят Kerio» | Kerio сам держит 80 | Включить авто-остановку службы или использовать DNS-01 |
| 🟠 «NAT: внешний IP не совпадает с локальным» | Сервер за роутером | Убедиться, что проброс портов 80/443 сделан на сервер Kerio |

### 3.6 DNS-01: пошагово

1. Выберите метод **DNS-01**. Появятся кнопки **📋 Открыть окно с TXT-записью**, **🔍 Проверить TXT в публичном DNS (Google 8.8.8.8 / Cloudflare 1.1.1.1)** и **✅ Подтвердить TXT-записи и выпустить сертификат**. Если хотите выпустить сертификат прямо с этого компьютера, минуя порты 80/443, нажмите **🌐 Выпустить сертификат прямо с этого ПК через DNS-01 (без портов 80/443) →**.
2. Программа покажет **имя записи** (`_acme-challenge.вашдомен`) и **значение TXT**; кнопкой **📋 Копировать TXT** его можно забрать в буфер.
3. Откройте панель DNS вашего регистратора (например, `hoster.by`, Cloudflare, reg.ru) и создайте запись:
   - Тип: `TXT`
   - Имя/Хост: `_acme-challenge`
   - Значение: длинная строка из программы (копировать целиком, без пробелов)
   - TTL: 300 (5 минут) или минимум, который разрешён
4. Сохраните. Подождите 5–15 минут (иногда до часа).
5. Нажмите **🔍 Проверить TXT в публичном DNS (Google 8.8.8.8 / Cloudflare 1.1.1.1)** — программа спросит оба резолвера. Должно быть «найдено».
6. Нажмите **✅ Подтвердить TXT-записи и выпустить сертификат**.

> ⚠️ Если добавляете несколько доменов, TXT-записей будет несколько (по одной на имя). Все они должны существовать одновременно — не удаляйте предыдущую, пока не выпустите сертификат.

### 3.7 Что вы получите в итоге

Файлы складываются в подпапку с именем домена: `certs\mail.company.by\` (если домена нет — `ip-93.125.10.25`).

| Файл | Что это | Куда |
|---|---|---|
| `server.key` | Приватный ключ. **Никому не передавать!** | В Kerio вместе с `server.crt` |
| `server.crt` | Сертификат + вся цепочка CA (fullchain) | В Kerio |
| `mail.company.by.key` | Тот же ключ под именем домена | Для nginx/apache |
| `mail.company.by-fullchain.crt` | Сертификат + цепочка под именем домена | Для nginx/apache |
| `chain.crt` | Только промежуточные CA | Для nginx/apache |
| `cert-only.crt` | Только ваш сертификат без цепочки | Для некоторых систем |
| `mail.company.by.csr` | Запрос на сертификат | Если выпускаете в другом месте |
| `mail.company.by.pfx` | Всё вместе (ключ + сертификат) в одном файле | Для Windows/IIS/Exchange |
| `install-kerio.bat` | Готовый скрипт установки | Запустить от админа |
| `README-KERIO.txt` | Шпаргалка «что куда класть» | Прочитать при ручной установке |
| `mail.company.by-kerio-bundle.zip` | Всё вышеперечисленное в архиве | Для передачи коллеге |

> 💡 **Почему `server.crt` — это «fullchain».** Если положить только ваш сертификат без промежуточного CA, Outlook и телефоны будут писать «цепочка не доверена». Программа всегда кладёт полную цепочку — это правильно.

### 3.8 Частые ошибки этой вкладки

| Ошибка в окне | Причина | Решение |
|---|---|---|
| `DNS problem: NXDOMAIN looking up A` | Домена нет в DNS | Создать A-запись |
| `Invalid response ... 404` | Проверка не дошла до программы | Открыть порт 80, проверить NAT |
| `ПУСТОЙ ОТВЕТ (got "")` | Порт 80 на роутере проброшен **не на этот компьютер**, а на другой сервер с Kerio | Пробросить 80 на нужный сервер, остановить на нём Kerio (программа сделает это сама от админа) или выпустить через **DNS-01** |
| `Timeout during connect (likely firewall)` | Порт закрыт файрволом | Открыть порт на роутере и в Windows Firewall |
| `too many certificates already issued` | Исчерпан лимит LE | Подождать неделю или использовать **Staging** |
| `Policy forbids issuing for name` | Домен под санкциями (OFAC) | См. вкладку «Санкции» |
| `Кириллический домен` | `.бел`, `.рф` | Ничего не делать: программа сама переведёт в Punycode (`xn--...`) |
| `Сертификат не принят Kerio` | Неверный формат ключа | Использовать «Локальный (Kerio)» или RSA 2048 PKCS#1 |

## 4. Вкладка 2 — Установка в Kerio Connect

Здесь сертификат попадает внутрь Kerio. Есть **два способа**, между ними переключает поле «Способ установки в Kerio Connect».

### 4.1 Способ 1 — «Файловый метод — Копирование в sslcert + авто-бэкап + перезапуск KerioMailServer» (простой и надёжный)

**Что делает:** копирует `server.crt` и `server.key` в папку `MailServer\sslcert`, предварительно сделав резервную копию старых файлов, прописывает активный профиль в `mailserver.cfg` и перезапускает службу `KerioMailServer`.

Есть галочка **«Перезапустить службу Windows `KerioMailServer` после копирования»** (включена по умолчанию). Если её снять, файлы обновятся, но Kerio продолжит отдавать старый сертификат до перезапуска.

**Плюсы:** работает всегда, даже без пароля администратора Kerio.
**Минусы:** служба почты перезапускается — 5–20 секунд письма копятся в очереди.

**Что заполнить:**

| Поле | Что писать |
|---|---|
| **Выберите выпущенный сертификат для установки** | Домен из списка уже выпущенных сертификатов (например `mail.company.by — 89 дней`) |
| **Путь к папке MailServer\sslcert на сервере Windows** | `C:\Program Files\Kerio\MailServer\sslcert` |

### 4.2 Способ 2 — «Через Kerio Connect Admin API (порт 4040) — Онлайн без перезапуска службы почты!»

**Что делает:** входит в Kerio по JSON-RPC на порт 4040, загружает файл, импортирует его и делает активным — **без перезапуска службы**.

**Что заполнить:**

| Поле | Что писать |
|---|---|
| **Хост / IP админки Kerio** | Локальный IP сервера, например `10.146.100.14` или `127.0.0.1`, если программа на том же сервере |
| **Порт Admin API** | `4040` (по умолчанию) |
| **Логин администратора** | `Admin` (или другой админ Kerio) |
| **Пароль администратора** | Пароль Kerio. **Программа его не сохраняет** |

> ⚠️ **Порт 4040 нельзя открывать в интернет.** Это полный доступ к серверу. Если вы «снаружи» — сначала подключите VPN, и укажите внутренний IP Kerio.

### 4.3 Кнопки

| Кнопка | Что делает |
|---|---|
| **Обзор...** | Выбрать папку `sslcert` в проводнике |
| **Проверить папку** | Проверяет, что путь существует и похож на папку Kerio; показывает найденные сертификаты |
| **🩺 Диагностика подключения к Kerio (найти точную причину)** | Проходит 9 шагов: DNS → TCP :4040 → TLS → веб-админка → вход → права → версия → список сертификатов → загрузка файла. Показывает, **на каком именно шаге** всё сломалось |
| **🌐 Найти Kerio в сети** | Сканирует подсеть и типовые адреса, находит сервер Kerio |
| **📜 Только список сертификатов** | Ничего не меняет, просто показывает, что уже установлено |
| **📬 Установить выбранный ключ и сертификат в Kerio Connect** | Основное действие |
| **🔄 Перезапустить службу** | Перезапуск `KerioMailServer` вручную |

### 4.4 Как убедиться, что сертификат встал

1. Откройте Kerio WebAdmin: `https://<сервер>:4040/admin/`.
2. **Конфигурация (Configuration) → Сертификаты SSL (SSL Certificates)**.
3. Найдите активный сертификат: в колонке дат должен быть **новый срок** (например, +90 дней).
4. Откройте `https://mail.вашдомен` в браузере — замочек должен быть зелёным, без предупреждений.
5. В Outlook/телефоне переподключите учётную запись, если клиент кэшировал старый сертификат.

**Если ставите вручную (через WebAdmin), а не программой** — внутри вкладки есть кнопка **📖 Куда нажимать в Kerio Connect**. Порядок такой:

1. **Конфигурация (Configuration) → Сертификаты SSL (SSL Certificates)**.
2. Кнопка **Импорт (Import) → Импортировать новый сертификат… (Import New Certificate…)**.
3. В поле **Сертификат (Certificate)** выберите `server.crt` — он уже содержит ваш сертификат + промежуточный сертификат Let's Encrypt.
4. В поле **Приватный ключ (Private key)** выберите `server.key` (незашифрованный RSA-ключ).
5. Выделите добавленный сертификат в таблице и нажмите **Использовать (Set as Active)** — готово.

### 4.5 Частые ошибки

| Сообщение | Причина | Решение |
|---|---|---|
| `HTTP 401 Unauthorized` | Неверный логин/пароль админа Kerio | Проверить пароль; логин — именно администратор Kerio, не почтовый ящик |
| `HTTP 404` | Порт 4040 — это не Kerio / неверный путь | Проверить, что открыт `https://IP:4040/admin/` |
| `таймаут подключения` | Порт 4040 закрыт или неверный IP | VPN, файрвол, внутренний IP вместо внешнего |
| `недостаточно прав` | Учётка не администратор | Дать права администратора Kerio |
| `Unable to import certificate, the content is invalid` | Ключ/сертификат не в формате Kerio | Использовать файловый метод или перевыпустить в режиме «Локальный (Kerio)» |
| `служба не найдена` | Kerio стоит на другом сервере | Установить сертификат через Admin API |
| `Access denied` при копировании в sslcert | Нет прав администратора Windows | Запустить программу от имени администратора |

## 5. Вкладка 3 — Проверка почты и антиспам

Это «медосмотр» почтового сервера: 20+ проверок за один запуск, с оценкой и инструкцией по каждой проблеме.

### 5.1 Что вводить

| Поле | Что писать | Пример |
|---|---|---|
| **Почтовый домен компании или email *** | Домен, на котором живёт почта | `company.by` |
| **Хост почтового сервера** | Необязательно, определится сам | `mail.company.by` |
| **🌐 Внешний белый IP** | Необязательно. Если пусто — программа определит сама (5 способами, не боясь Split-DNS) | `93.125.10.25` |
| **🔌 Локальный / VPN IP Kerio** | Если порты снаружи закрыты — укажите внутренний IP, проверка пойдёт по нему | `10.146.100.14` |
| **Селектор DKIM** | Обычно `mail`. Программа ищет его сама среди 12 стандартных | `mail` |

**Кнопка 🌐 Авто-IP** — принудительно переопределить внешний IP.

### 5.2 Что именно проверяется

| Проверка | Простыми словами | Что бывает при проблеме |
|---|---|---|
| **MX и A-запись** | Кто принимает почту и куда ведёт имя сервера | Письма «пропадают»: отправители не знают, куда их слать |
| **PTR / FCrDNS** | Обратный адрес IP. Половина мировых серверов требует, чтобы он совпадал с именем | Gmail/Mail.ru режут письма, RBL добавляют IP |
| **SPF** | Список серверов, которым можно отправлять от вашего домена | Письма в спаме; `+all` — дыра, любой может писать от вас |
| **SPF > 10 DNS-запросов** | Технический лимит RFC 7208 | Часть получателей считает SPF «сломанным» |
| **DKIM** | Цифровая печать письма | Подделки не отличить от настоящих писем, спам-фильтры недовольны |
| **DMARC** | Что делать получателю, если SPF/DKIM не совпали | Нет защиты от подмены домена |
| **Порт 25 и EHLO** | Сервер вообще принимает почту из интернета? | Внешние серверы не могут доставить письма |
| **Open Relay** | Не пересылает ли сервер чужие письма | 🔴 Критическая уязвимость: сервер используют спамеры, IP мгновенно в RBL |
| **SSL на портах 25/465/587/993/995** | Шифрование на всех почтовых портах и доверена ли цепочка | Клиенты ругаются, часть писем уходит без шифрования |
| **RBL-базы (Spamhaus ZEN, Barracuda, SpamCop, SORBS, UCEPROTECT, PSBL, WPBL, Mailspike, NiX Spam, SpamRATS, 0SPAM)** | Не в чёрных ли списках IP | Письма блокируются у получателей |
| **Доменные списки (Spamhaus DBL, SURBL, URIBL, SpamEatingMonkey)** | Не в чёрном ли список сам домен и ссылки в письмах | Письма уходят в спам даже при чистом IP |
| **Autodiscover / TLS-RPT** | Автонастройка Outlook и отчёты о TLS | Пользователи мучаются с настройкой, нет отчётов |
| **Опасные порты (3389/4040/445)** | Не открыты ли наружу RDP, админка Kerio, SMB | 🔴 Сервер могут взломать |
| **TLS 1.0 / 1.1** | Устаревшее шифрование | Не соответствие PCI DSS, часть клиентов не подключается |
| **CAA / MTA-STS / BIMI** | Кто имеет право выпускать сертификаты, строгий TLS, логотип в почте | Риск поддельного сертификата, нет логотипа |

### 5.3 Оценка, фильтры и история

- Оценка **0–100** и буквенная оценка:

| Оценка | Баллы | Что означает (текст программы) |
|---|---|---|
| **A+** | 95–100 | Эталонная настройка, высочайшая доставляемость во Входящие |
| **A** | 82–94 | Хорошая настройка, почта ходит стабильно |
| **B** | 65–81 | Работает, но часть писем может попадать в «Спам» |
| **C** | 45–64 | Высокий риск попадания в «Спам» и отказов доставки |
| **F** | 0–44 | Критические ошибки DNS/сервера |

- Счётчики: ✅ в порядке, 🟠 важные замечания, 🔴 критические проблемы.
- Фильтры: **Все проверки**, **🔴🟠 Только проблемы**, **✅ Успешные**.
- Если проверяли раньше, под полями появится строка **🕒 История проверок на этом компьютере**: чипы вида `@company.by: 68/100 (B) • 24.10.2026 14:05`. **Клик по чипу** подставит домен и хост в поля — удобно сравнивать результаты до и после исправлений.

### 5.4 Подробные инструкции

У каждой проблемной карточки **внутри** есть раскрывающийся блок с пошаговым исправлением — что открыть в Kerio WebAdmin, какую DNS-запись создать, какой командой проверить. Не нужно искать инструкцию на стороне.

Кнопка **📄 Сохранить полный HTML-отчёт с инструкциями** — делает файл, который можно приложить к заявке или отдать коллеге/руководителю (со всеми статусами и текстами исправлений).

### 5.5 Тестовая отправка письма

Внизу вкладки — блок SMTP:

| Поле | Значение |
|---|---|
| **SMTP сервер (внешний или VPN IP) *** | `mail.company.by` или внутренний IP |
| **Порт *** | `465` (SSL) — рекомендуется для Kerio; `587`/`25` для STARTTLS |
| **Шифрование** | SSL/TLS сразу / STARTTLS / без шифрования |
| **Логин ящика Kerio (email отправителя) *** | полный адрес ящика, например `test@company.by` |
| **Пароль от этого почтового ящика *** | пароль этого ящика (не сохраняется) |
| **От кого (From) *** / **Кому отправить тестовое письмо (To) *** | адреса для теста |

Нажмите **🚀 Отправить контрольное письмо и показать лог SMTP**. В логе видно всю сессию: подключение, TLS, авторизацию, ответ сервера. Это лучший способ понять, почему «письма не уходят»: ошибка авторизации, блокировка порта, неверный сертификат и т. д.

### 5.6 Что делать после проверки — порядок действий

1. Сначала **🔴 критические** (Open Relay, опасные порты, MX, порт 25).
2. Потом **🟠 важные** (SPF, DKIM, DMARC, PTR, RBL).
3. В конце — «улучшения» (CAA, MTA-STS, BIMI, TLS 1.0).
4. После каждой правки подождите 10–30 минут (DNS кэшируется) и нажмите проверку снова — история покажет рост оценки.

Внизу вкладки есть быстрые переходы: **🌍 Карта санкций и УЦ (Домен + IP) →**, **🚑 Центр вывода из блэклистов и готовые письма (8 шаблонов) →** и **🚑 Готовые письма разблокировки →** — они переносят вас на нужную вкладку с уже заполненными полями.

## 6. Вкладка 4 — Выход из блэклистов

Если сервер уже попал в чёрный список — здесь готовят **письма на разблокировку** и расшифровывают ошибки.

### 6.1 Что вводить

| Поле | Пример |
|---|---|
| **Ваш почтовый домен** | `company.by` |
| **Имя SMTP-сервера (HELO / PTR)** | `mail.company.by` |
| **Внешний белый IP** | `93.125.10.25` |
| **Текст ошибки 550/554** | Вставить из лога Kerio или из письма-возврата (необязательно) |

### 6.2 Восемь готовых пакетов

Программа формирует готовые письма и пошаговые инструкции для:

1. **Microsoft Outlook / Hotmail / Office 365** — ошибки `550 5.7.1 S3150/S3140` (закрытая база Microsoft, в обычных RBL её не видно).
2. **Mail.ru / BK.ru / List.ru / Inbox.ru / VK WorkMail** — `550 spam message rejected`.
3. **Google Gmail / Workspace** — `550-5.7.1`, `550-5.7.26`.
4. **Яндекс Почта / Яндекс 360** — `554 5.7.1 Message rejected under suspicion of SPAM`.
5. **Spamhaus** (SBL/XBL/CBL/PBL и доменный DBL).
6. **Barracuda Central** — корпоративные шлюзы банков и госорганов.
7. **SpamCop / SORBS / Backscatterer / UCEPROTECT**.
8. **Ваш интернет-провайдер** (Белтелеком, A1, МТС, «Деловая сеть», хостер VPS) — письмо на настройку PTR и проверку порта 25.

Плюс автоматически добавляются пакеты для тех RBL, где реально найден ваш IP.

### 6.3 Кнопки

- **🔄 Обновить и сгенерировать все письма** — перепроверяет RBL и формирует тексты под ваш домен/IP.
- **🔎 Расшифровать ошибку и сформировать готовые письма разблокировки** — вставьте текст `550/554`, программа скажет, **кто именно заблокировал** и что делать.
- **📋 Копировать команды MikroTik** — готовые команды для настройки NAT/портов, если у вас MikroTik.

### 6.4 Как отправить апелляцию

1. Откройте нужную карточку и нажмите **📋 Копировать** рядом с текстом письма.
2. Перейдите по кнопке портала (ссылка есть в карточке).
3. Заполните форму и вставьте текст. Где требуется — укажите IP, домен, контактный email.
4. **Ответ придёт на email** (для Microsoft — обязательно укажите ящик на другом домене, например Gmail, чтобы ответ дошёл).
5. Сохраните номер тикета.

### 6.5 Сколько ждать

| Кто | Срок |
|---|---|
| Microsoft Office 365 (sender.office.com) | 15–30 минут |
| Microsoft Outlook/Hotmail (olcsupport) | до 24 часов |
| Mail.ru / Яндекс | 1–3 рабочих дня |
| Spamhaus | от нескольких часов до 2 суток |
| Barracuda / SpamCop / SORBS | 1–3 суток |

> ⚠️ Пока идёт разбор, **устраните причину**: проверьте SPF/DKIM/DMARC, PTR, отсутствие рассылок, вирусов и открытого релея. Иначе IP забанят снова через день.

### 6.6 Чего делать нельзя

- ❌ Отправлять одну и ту же апелляцию по 10 раз — это ускоряет повторный бан.
- ❌ Платить «сервисам разблокировки за 100$» — 95% из них просто отправляют то же бесплатное письмо.
- ❌ Менять IP каждый раз вместо исправления причины — новый IP тоже быстро попадёт в список.

## 7. Вкладка 5 — Санкции и гео-блокировки

Проверяет, не мешают ли домену и IP санкционные списки и география.

### 7.1 Что вводить

| Поле | Пример |
|---|---|
| **Проверяемый домен или сайт *** | `company.by` |
| **Почтовый хост / поддомен SSL** | `mail.company.by` (подставится сам) |
| **🌐 Внешний белый IPv4** | пусто = определить автоматически |

Кнопка запуска: **🌍 Проверить домен и IP на санкционные и гео-блокировки**.

### 7.2 Что проверяется

| Блок | Смысл |
|---|---|
| **OFAC в Let's Encrypt** | Пробует «всерьёз» заказать сертификат в LE Staging. Если LE отвечает `Policy forbids issuing for name` — домен в санкционном списке |
| **Зона домена** | Есть ли у зоны ограничения (например, `.by`, `.ru` и т. п. в разных УЦ) |
| **Матрица центров сертификации** | Какие CA (Let's Encrypt, DigiCert, Sectigo, Google Trust, ZeroSSL…) выдадут сертификат для вашего домена/IP |
| **RIPE / ASN** | Кому принадлежит IP, из какой страны, есть ли ограничения |
| **Видимость DNS из США и Европы** | Видят ли ваш домен Google DNS, Cloudflare, Quad9. Если нет — зарубежные контрагенты не смогут вам написать |
| **Доступность мировых УЦ, CDN и почтовых шлюзов** | Может ли сервер достучаться до Let's Encrypt, Microsoft, Google и т. д. |

### 7.3 Как читать

- ✅ — ограничений нет.
- 🟠 — есть риск, но работать можно (например, один CA не выдаёт, другой выдаёт).
- 🔴 — блокировка: сертификат не получить или письма за границу не дойдут.

Внизу — блок **«Детальное заключение и рабочие схемы обхода»** с конкретными шагами: перенос DNS на облачный провайдер, смена CA, использование релея, настройка в рамках Указа № 60 РБ.

> ⚠️ Программа не даёт юридических консультаций. Решения о схемах обхода принимает организация; технические шаги — подсказка, а не приказ.

## 9. Вкладка 7 — Антиспам-база KCM

Это самая новая часть программы. Разберём максимально подробно.

### 9.1 Что это такое

Представьте, что каждое утро выходит свежий **список плохих отправителей и плохих сайтов в письмах**: домены мошенников, адреса, темы «вы выиграли приз», фразы «оплатите комиссию», IP-адреса спам-ботов и ссылки на фишинговые страницы.

Программа скачивает этот список с GitHub и кладёт его в Kerio Connect как **правила SpamAssassin**. Дальше Kerio сам складывает очки: если письмо пришло с «плохого» домена и содержит «плохую» ссылку — оно получает много очков и уходит в спам.

**Ключевое:** база **не заменяет** встроенные проверки Kerio (SPF/DKIM/DMARC, DNSBL, байесовский фильтр) — она **добавляется** к ним.

Внизу вкладки есть карточка **📖 Что именно делает база и как её обслуживать** — короткая встроенная шпаргалка, если этот ФАК не под рукой.

### 9.2 Что внутри базы и сколько очков

| Группа | Правило | Очки |
|---|---|---|
| Домены отправителей | `From` содержит домен из базы | **+3.2** |
| Конкретные адреса отправителей | `From` совпал с адресом | **+4.5** |
| Мотивы в теме письма | «выиграли», «аккаунт заблокирован» и др. | **+1.8** |
| Фразы в теле письма | «оплатите комиссию», «CVV код» и др. | **+1.5** |
| Домены фишинговых ссылок | ссылка в письме ведёт на домен из базы | **+2.5** |
| IP/CIDR источников | IP из заголовка `Received` | **+3.0** |
| Белый список | доверенный отправитель (банки, госсервисы, крупные провайдеры) | **−6.0** |

> 💡 Порог отказа Kerio по умолчанию — около **5.0 очков**. То есть одного «плохого домена» (+3.2) и «плохой темы» (+1.8) уже достаточно.

### 9.3 Откуда берутся данные

База собирается автоматически каждый день в 03:17 UTC из открытых источников:

- **Phishing.Database** (MIT) — активные фишинговые домены;
- **OpenPhish** — публичный фид фишинга;
- **ShadowWhisperer BlockLists** (Scam и Malware) — мошеннические и вредоносные домены;
- **HaGeZi TIF** — threat intelligence;
- **Dogino Discord-Phishing** — фишинг и скам-ссылки;
- **Spamhaus DROP** и **FireHOL level1** — IP-адреса ботнетов;
- **URLhaus** (abuse.ch) — включается, если в репозитории задан бесплатный ключ `ABUSECH_AUTH_KEY`.

Результат публикуется в двух местах: **GitHub Releases** (`antispam-db-latest`) и ветка **`antispam-db`**. Программа сначала пробует релиз, потом ветку.

### 9.4 Первый запуск вкладки

Откройте вкладку — сверху появятся плашки статуса:

| Плашка | Что показывает |
|---|---|
| **Версия базы в Kerio** | `не установлена` или номер вида `2026.10.24-0851` |
| **Правил в базе** | Сколько правил внутри `.cf` (например 944) |
| **Размер файла правил** | Размер `kerio-antispam.cf` в КБ |
| **Служба Kerio** | `RUNNING` / `STOPPED` / `NOT_FOUND` |
| **Последняя проверка GitHub** | Когда проверяли и какая версия лежит на GitHub |

Ниже — блок **Пути**: папка Kerio (и как она найдена), папка правил SpamAssassin, путь к файлу базы, папка локальных списков («✓ доступны» или «появятся после установки»), количество резервных копий и дата последней. Ещё ниже — **История операций** (последние 6 действий) и, если что-то падало, **Последняя ошибка**.

В таблице групп правил видно, сколько правил каждой группы и сколько очков они дают.

Есть два поля с путями:

| Поле | Что писать |
|---|---|
| **Папка установки Kerio Connect** | `C:\Program Files\Kerio\MailServer` |
| **Папка правил SpamAssassin** | Заполняется сама: `<Kerio>\plugins\spamassassin\rules`. Менять только если Kerio установлен нестандартно |

Если Kerio не найден, впишите путь вручную или нажмите **🪄 Определить автоматически** / **📁 Выбрать папку Kerio…**.

### 9.5 Установка: 3 шага

**Шаг 1. 🔎 Проверить обновления на GitHub**

Программа скачивает `manifest.json` и показывает:

- установленную версию и версию на GitHub;
- дату сборки и количество записей;
- **здоровье источников**: «Источники базы: 9 активны, 1 требуют ключа (urlhaus)», а также недоступные источники с причиной.

Если стоит актуальная версия — будет «✅ Установлена актуальная версия». Если нет — «🔔 Доступно обновление» и кнопки **👁 Проверить, что изменится** и **⬇️ Установить версию «…»**.

**Шаг 2. 👁 Предпросмотр установки (dry-run)**

Скачивает файл, проверяет **SHA-256** и показывает таблицу:

| Группа | Будет в базе | Сейчас | Очки |
|---|---|---|---|
| Домены отправителей | 7 446 | 0 (+7 446) | +3.2 |
| Фишинговые ссылки | 30 000 | 0 (+30 000) | +2.5 |
| … | … | … | … |

Плюс примеры новых правил и строка «Источники базы: …».

**Важно:** на этом шаге **в Kerio ещё ничего не записано**. Это «примерка».

**Шаг 3. ⬇️ Установить / Обновить базу в Kerio**

Нажмите **⬇️ Установить / Обновить базу в Kerio**. Программа спросит подтверждение («⚠️ Установка выполнится в папку Kerio…») — проверьте путь и нажмите **⬇️ Подтвердить установку**. Дальше программа:

1. скачивает файл и проверяет SHA-256;
2. находит папку `plugins\spamassassin\rules`;
3. сохраняет локальные списки (`certs\antispam\lists`) для проверки писем;
4. делает **резервную копию** предыдущей базы в `certs\antispam\backup`;
5. проверяет синтаксис правил (чтобы битый файл не попал в Kerio);
6. атомарно записывает `kerio-antispam.cf`;
7. читает файл обратно и сверяет SHA-256;
8. перезапускает службу `KerioMailServer` (если включена галочка).

Внизу — отчёт по шагам: что скачано, куда записано, создана ли копия, перезапущена ли служба.

### 9.6 Галочка «Перезапускать службу Kerio MailServer»

- ✅ **Включена** — правила начинают работать сразу. Почта недоступна 5–20 секунд.
- ⬜ **Выключена** — файл записан, но правила **не активны**, пока служба не перезапустится.

**Как применить без перезапуска:** Kerio WebAdmin → **Configuration → Content Filter → Spam Filter** → переключите любую галочку (например, SURBL) → **Apply**. Kerio перечитает правила SpamAssassin.

### 9.7 Автообновление

1. Выберите расписание: **каждые 6 часов**, **каждые 12 часов** (по умолчанию) или **раз в сутки (04:10)**.
2. Нажмите **✅ Включить автообновление**.
3. Создаётся задание Планировщика `KerioCertManager_AntiSpamDB`, которое запускает `KerioCertManager.exe --antispam-update`.
4. Кнопка **🚀 Проверить и обновить сейчас** — немедленный запуск.
5. **⏸ Выключить** — удалить задание.

Как это работает внутри: задача проверяет GitHub; если версия на GitHub новее — устанавливает, если такая же — пишет в журнал «актуальна» и ничего не трогает. Перезапуск службы делается только при реальном обновлении.

> ⚠️ Для создания задания нужны права администратора. Без них программа честно скажет: «запустите от имени Администратора».

### 9.8 Откат и удаление

- **⏪ Откатить** — берёт последнюю резервную копию из `certs\antispam\backup` и возвращает её в Kerio. Полезно, если новая база дала ложные срабатывания.
- **🗑 Удалить базу** — убирает `kerio-antispam.cf` из папки правил. Копия остаётся в резервных, так что можно вернуть.

### 9.9 Проверка письма (dry-run, без отправки)

Вставьте исходник письма в большое поле и нажмите **🔬 Проверить письмо по антиспам-базе**.

Что показать:

- **От кого**, домен отправителя;
- **сколько очков** набрало письмо;
- **какие правила сработали** (таблица: группа, совпадение, очки);
- вердикт:
  - ✅ «ЧИСТО» (< 3 очков),
  - ⚠️ «ВЕРОЯТНО СПАМ» (3–5),
  - 🚫 «СПАМ» (5+).

Кнопка **📋 Вставить пример** подставит демонстрационное фишинговое письмо — удобно проверить, что база вообще работает.

> 💡 Расчёт предварительный: Kerio добавляет к этим очкам свои (SPF/DKIM, DNSBL, байесовский фильтр). Точный итог смотрите в заголовке `X-Spam-Score` доставленного письма.

### 9.10 Где увидеть результат в Kerio

- В заголовках письма: `X-Spam-Status` содержит правила `KCM_*`, `X-Spam-Score` — итог.
- В Kerio WebAdmin: **Content Filter → Spam Filter** — общий порог срабатывания.
- В логах Kerio: `MailServer\logs\` — записи о spam score.

### 9.11 Если правила не применяются

| Симптом | Причина | Что делать |
|---|---|---|
| Файл установлен, но `KCM_*` в письмах нет | Служба не перезапускалась | Перезапустить `KerioMailServer` или переключить SURBL + Apply |
| «Не найден каталог SpamAssassin» | Неверный путь Kerio | Указать `C:\Program Files\Kerio\MailServer`, проверить наличие `plugins\spamassassin\rules` |
| «Нет доступа к папке» | Нет прав | Запустить от имени администратора |
| «SHA-256 не совпала» | Файл подменён или скачался битым | Повторить установку; если повторяется — проверить прокси/антивирус |
| «Не удалось получить базу с GitHub» | Нет интернета / GitHub закрыт | Скачать `kerio-antispam.cf` вручную и использовать **импорт файла** (см. ниже) |
| Правила есть, но спама больше не стало | Порог Kerio слишком высокий | Content Filter → Spam Filter → снизить порог (например, до 5) |
| Слишком много ложных срабатываний | Агрессивная база / легитимный домен в списке | Откатить базу; добавить домен в `allowlist` через GitHub; удалить базу |

### 9.12 Импорт файла вручную (закрытый контур)

Если сервер вообще без доступа к GitHub:

1. На любом компьютере с интернетом откройте https://github.com/zigorminsk-debug/jiraHelp/releases/tag/antispam-db-latest
2. Скачайте файл **`kerio-antispam.cf`**.
3. Перенесите его на сервер.
4. В программе: скопируйте `kerio-antispam.cf` в папку `plugins\spamassassin\rules\` и перезапустите службу — **это всё, что нужно**. Либо используйте API импорта в программе, если он доступен в вашей сборке.

> 💡 Программа поддерживает и полностью ручную установку: один файл в одну папку. Ничего больше не меняется — ни `mailserver.cfg`, ни пользователи.

### 9.13 Как добавить свои домены в базу

Если у вас есть свой «чёрный список» (например, домены, которые атакуют именно вас):

1. Форкните репозиторий на GitHub.
2. Добавьте строки в нужный файл папки `antispam-db/sources/`:

| Файл | Что добавлять | Что даёт |
|---|---|---|
| `scam-domains.txt` | домены отправителей | +3.2 очка на письмах с этого домена в `From` |
| `scam-emails.txt` | полные адреса | +4.5 |
| `phishing-links.txt` | домены ссылок и лендингов | +2.5 |
| `scam-subjects.txt` | шаблоны тем | +1.8 |
| `scam-phrases-ru.txt` | фразы в теле письма | +1.5 |
| `threat-ips.txt` | IP и подсети ботнетов (/16, /24, /32) | +3.0 |
| `allowlist.txt` | доверенные домены | −6.0 (защита от ложных срабатываний) |

3. Отправьте pull request.
4. После принятия — база соберётся автоматически (в 03:17 UTC или вручную через Actions), и программа её подхватит.

Домены из белого списка (`sources/allowlist.txt`) никогда не попадут в чёрный — это защита от ошибок.

### 9.14 Про URLhaus и «🔑 нужен ключ»

abuse.ch 21 октября 2026 закрыл бесплатные выгрузки без ключа (`410 Gone`). Официальный путь — личный **Auth-Key** (бесплатный, только некоммерческое использование).

Чтобы включить:

1. Зарегистрируйтесь на abuse.ch и получите Auth-Key.
2. В репозитории GitHub: **Settings → Secrets and variables → Actions → New repository secret**.
3. Имя: `ABUSECH_AUTH_KEY`, значение: ваш ключ.
4. Следующая сборка базы подхватит его автоматически.

Без ключа всё остальное работает: база собирается из 9 источников, URLhaus просто помечается как «требует ключа».

### 9.15 Если источник «0 записей»

Программа честно показывает ошибку источника: «HTML/анти-бот страница», «HTTP 404», «HTTP 410». Это значит, что владелец фида изменил адрес или закрыл доступ. База при этом **не ломается** — собирается из остальных источников. Такие случаи исправляются в репозитории (замена адреса фида).

## 10. Вкладка 8 — Инструменты админа

### 10.1 Анализатор заголовков письма (RFC-822)

**Зачем:** понять, почему письмо шло 40 минут или попало в спам.

1. Откройте проблемное письмо в Outlook/Thunderbird/WebMail → «Свойства» / «Показать оригинал» / `View Source`.
2. Скопируйте **все служебные заголовки** (начиная с `Return-Path`/`Received`).
3. Вставьте в поле и нажмите **🔬 Разобрать маршрут письма, задержки и заголовки антиспама**.

Программа покажет:

- все узлы (`Received`) по порядку — от отправителя к получателю;
- сколько времени письмо провело на каждом узле;
- **какой узел виноват в задержке**;
- результаты `SPF / DKIM / DMARC`;
- `SpamScore` и признаки спама.

### 10.2 Конструктор DNS-зоны

**Зачем:** собрать правильные DNS-записи для почты без ошибок.

1. Укажите **почтовый домен**, **хост почтового сервера**, **внешний белый IPv4** и, если нужно, **доп. IP веб-сайта/CRM** (когда формы на сайте шлют письма с другого хостинга).
2. Выберите **режим строгости SPF**: `~all` (SoftFail — рекомендуется) или `-all` (HardFail — жёстко отклонять чужих).
3. Выберите **политику DMARC**: `p=quarantine` (в «Спам» — оптимально), `p=reject` (полная блокировка подделок) или `p=none` (мягкий мониторинг отчётов).
4. Отметьте галочками сервисы, которым разрешено отправлять письма от вашего домена (рядом показана «цена» в DNS-запросах):
   - **Kerio Connect** (MX + `mail.хост`) — +2 запроса, плюс прямой `ip4` (0 запросов);
   - **Битрикс24 CRM** — `include:spf.bitrix24.com` (~2);
   - **Яндекс 360 для бизнеса** — `include:_spf.yandex.net` (+1);
   - **VK WorkSpace / Mail.ru Бизнес** — `include:_spf.mail.ru` (+1);
   - **Google Workspace** — `include:_spf.google.com` (+4);
   - **Microsoft 365 / Exchange Online** — `spf.protection.outlook.com` (+2);
   - **UniSender** — `include:spf.unisender.com` (+2);
   - **SendPulse** — `include:mx.sendpulse.com` (+2).
5. Программа соберёт `A`, `MX`, `SPF` (с контролем лимита **не более 10 DNS-запросов**, RFC 7208), `DKIM` (куда вставить открытый ключ из Kerio), `DMARC`, `autodiscover`, `CAA`, `TLS-RPT` и предупредит, если сумма запросов превышает лимит.
6. **💾 Скачать готовый пакет DNS-записей (.txt)** — файл, по которому можно вносить записи в панель регистратора.

> ⚠️ SPF должен быть **один** на домен. Если записей две — часть получателей проигнорирует обе.

## 14. Частые проблемы и решения

| Проблема | Что делать |
|---|---|
| **Windows не запускает exe** («SmartScreen») | «Подробнее» → «Выполнить в любом случае». Либо ПКМ по файлу → Свойства → «Разблокировать» |
| **Окно пустое / белое** | Установить «Microsoft Edge WebView2 Runtime»; либо запустить с `--server-only` и открыть адрес из консоли в браузере |
| **Программа не открывается совсем** | Проверить, что антивирус не заблокировал; запустить от имени администратора; посмотреть, не занят ли порт 17840 |
| **«Недостаточно прав» при установке в Kerio** | Запустить от имени администратора Windows |
| **Порт 80 занят Kerio** | Использовать DNS-01, TLS-ALPN-01 или включить авто-остановку службы |
| **Let's Encrypt: «too many certificates»** | Подождать или потренироваться в **Staging** |
| **DNS-запись «не найдена»** | Подождать 15–60 минут (кэш DNS), проверить в публичном DNS кнопкой проверки |
| **Kerio не подключается по 4040** | Открыть `https://IP:4040/admin/` в браузере; проверить VPN/файрвол; нажать «🩺 Диагностика подключения» |
| **Kerio не принимает сертификат** | Использовать файловый метод; перевыпустить в режиме «Локальный (Kerio)» |
| **Письма не уходят** | Проверить порт 25 у провайдера (часто закрыт), SMTP-тест в программе, PTR |
| **Письма в спаме у получателей** | SPF/DKIM/DMARC + PTR + RBL (вкладка «Проверка почты»), затем Delist Center |
| **`550 5.7.1 S3150` от Microsoft** | Вкладка «Выход из блэклистов» → пакет Microsoft (sender.office.com + olcsupport) |
| **Домен не виден за границей** | Вкладка «Санкции» → блок «Видимость DNS из США и Европы» |
| **Антиспам-база не ставится** | Проверить путь Kerio, права администратора, интернет/GitHub |
| **Антиспам-база не действует** | Перезапустить `KerioMailServer` или переключить SURBL + Apply |
| **После базы слишком много спама в карантине/ложных** | Снизить/повысить порог спама в Kerio, откатить базу, добавить домены в allowlist |
| **Автопродление не сработало** | Проверить задание в `taskschd.msc`; сервер должен быть включён; проверить, что exe лежит по тому же пути |
| **Антивирус ругается на exe** | Это ложное срабатывание (Go-бинарник без подписи). Добавить в исключения; собрать самому из исходников при недоверии |
| **Забыл пароль администратора Kerio** | Программа его не хранит. Сброс — через Kerio WebAdmin/службу, не через программу |
| **Кириллический домен не принимается** | Программа сама переводит в Punycode; убедитесь, что в DNS создана запись для `xn--...` |

## 15. Безопасность и приватность

- **Никакой телеметрии.** Программа не отправляет «статистику» и не звонит домой.
- **Что уходит в интернет:** DNS-запросы (проверка доменов), запросы к Let's Encrypt, запросы к GitHub (база), запросы к RBL-спискам (проверка репутации IP), запросы к вашим почтовым портам.
- **Что остаётся локально:** сертификаты, настройки, история проверок, база, резервные копии.
- **Пароли в память, не на диск.** Пароль Kerio и почтового ящика не сохраняются в файлах.
- **Порт интерфейса** — только `127.0.0.1` (этот компьютер). Снаружи он недоступен.
- **Порт 4040** — только через VPN/локальную сеть. Никогда не публикуйте его в интернет.
- **Целостность базы** — каждый файл проверяется по SHA-256 перед установкой: подменённый файл не попадёт в Kerio.
- **Права:** запускайте от администратора только когда это нужно; читать отчёты можно и без него.

## 17. Словарик

| Термин | Простыми словами |
|---|---|
| **SSL/TLS-сертификат** | Электронный «паспорт» сервера. Доказывает, что вы — это вы, и включает шифрование |
| **CA (центр сертификации)** | Организация, которая выдаёт паспорта и проверяет документы (Let's Encrypt, DigiCert…) |
| **Let's Encrypt** | Бесплатный CA, который выдаёт сертификаты автоматически |
| **ACME** | Протокол, по которому программа общается с Let's Encrypt |
| **DNS** | Телефонная книга интернета: домен → IP |
| **A-запись** | «Домен живёт по такому-то IP» |
| **AAAA-запись** | То же для IPv6 |
| **MX** | «Кто принимает почту для домена» |
| **TXT-запись** | Свободный текст в DNS — так хранят SPF, DKIM, DMARC, подтверждения |
| **PTR** | Обратная запись: «этот IP принадлежит такому-то имени» |
| **SPF** | Список серверов, которым разрешено отправлять от вашего домена |
| **DKIM** | Цифровая подпись письма |
| **DMARC** | Правило «что делать, если SPF/DKIM не совпали» |
| **RBL/DNSBL** | Чёрные списки IP-адресов |
| **DBL** | Чёрный список доменов |
| **Open Relay** | Открытый почтовый сервер, через который может писать кто угодно — серьёзная уязвимость |
| **NAT** | Когда много устройств выходят в интернет через один IP (роутер) |
| **Порт** | «Дверь» сервера. 80 — сайт, 443 — сайт с шифрованием, 25 — почта, 4040 — админка Kerio |
| **Firewall** | Программа/устройство, которое закрывает «двери» |
| **Split-DNS** | Когда внутри сети домен ведёт на внутренний IP, а снаружи — на внешний |
| **Punycode** | Способ записать кириллический домен латиницей (`xn--...`) |
| **SHA-256** | «Отпечаток пальца» файла для проверки целостности |
| **SpamAssassin** | Антиспам-движок, который Kerio использует внутри. Правила `.cf` — его «мозги» |
| **Рабочая станция / сервер** | Ваш компьютер / машина, где стоит Kerio |
