# Ключ подписи приложения

`kcm-release.p12` — постоянный ключ, которым подписываются все релизные APK
начиная с версии **4.9.3**. Благодаря нему обновления устанавливаются «поверх»
уже установленного приложения: Android принимает APK только с той же подписью.

| Параметр | Значение |
|---|---|
| Файл | `kcm-release.p12` (PKCS#12) |
| Псевдоним | `keriocertmanager` |
| Алгоритм | RSA 2048, SHA-384, срок 12 000 дней |
| Владелец | `CN=KerioCertManager Mobile, O=Zakharevich I., C=BY` |
| SHA-256 сертификата | `48:C1:65:A7:7A:34:2A:66:C5:B7:89:71:B8:E5:BD:D9:BC:57:36:0C:31:6D:90:B0:67:5A:5B:39:4F:3E:78:18` |

Пароль хранится рядом в `keystore.properties` — он же используется скриптом
`android/build-apk.sh`.

## Почему ключ лежит в репозитории

GitHub Secrets доступны не всегда (у бота Arena нет прав на
`actions/secrets`), а без постоянного ключа каждая сборка получала бы новый
сертификат, и обновление «поверх» было бы невозможно — пришлось бы каждый раз
удалять приложение.

Репозиторий публичный, поэтому ключ фактически открыт. Для этого приложения
риск умеренный: APK распространяется только через GitHub Releases, а Android
всё равно проверяет подпись при установке. Но помните: **если ключ
скомпрометирован, любой может выпустить APK, который установится поверх**.
Если это станет проблемой — сгенерируйте новый ключ, замените файл и
предупредите пользователей, что установить обновление можно только после
удаления приложения.

Скрипт сборки сверяет SHA-256 подписи с указанным выше и **падает**, если
ключ подменили.

## Как перейти на свой ключ (необязательно)

Если в репозитории настроены секреты, они имеют приоритет:

```bash
gh secret set KCM_KEYSTORE_BASE64 < <(base64 -w0 my-release.p12)
gh secret set KCM_KEYSTORE_PASS   # пароль хранилища
gh secret set KCM_KEY_ALIAS       # псевдоним ключа
```

Тогда файл в этом каталоге можно удалить, а отпечаток в
`keystore.properties` заменить на свой (иначе сборка остановится на проверке).
