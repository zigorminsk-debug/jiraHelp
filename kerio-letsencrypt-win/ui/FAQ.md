## 1. Что это за программа

### 1.1 Одна фраза

**KerioCertManager** — это «швейцарский нож» для администратора **Kerio Connect**: одна программа на Windows, которая:

- делает и ставит **SSL-сертификат** (чтобы браузер и почтовые клиенты не ругались «сайту нельзя доверять»);
- **проверяет почту** по 20+ параметрам и пишет по-русски, что именно сломано и как починить;
- помогает **выйти из спам-чёрных списков**, генерируя готовые письма в поддержку;
- проверяет **санкционные и гео-ограничения** для домена и IP;
- **ставит и обновляет антиспам-базу** в Kerio Connect с GitHub;
- **работает с Kerio Connect на Linux** — и на самом Linux-сервере, и по SSH с Windows-машины;
- **сама проверяет обновления** и обновляется в один клик (или ставится установщиком `Setup.exe`).

### 1.2 Аналогии, чтобы стало понятно

| Слово | Простая аналогия |
|---|---|
| **SSL-сертификат** | Пломба на двери магазина + паспорт сайта. Без неё браузер пишет «небезопасно», а Outlook — «сертификат недействителен» |
| **Домен** (`mail.company.by`) | Адрес дома, понятный людям |
| **IP-адрес** (`93.125.10.25`) | Координаты дома, понятные компьютерам |
| **DNS** | Телефонная книга интернета: «домен → IP» |
| **A-запись** | Строка в этой книге: «mail.company.by живёт по адресу 93.125.10.25» |
| **MX-запись** | Строка «кто принимает почту для company.by» |
| **PTR-запись** | Обратная строка: «по адресу 93.125.10.25 живёт mail.company.by». Это как обратный адрес на конверте |
| **SPF** | Список тех, кому разрешено отправлять письма от имени вашего домена |
| **DKIM** | Печать/подпись на каждом письме: «это правда от нас и письмо не подменили» |
| **DMARC** | Инструкция «что делать, если печать не совпала» — в спам, в карантин или удалить |
| **RBL / DNSBL** | Чёрные списки плохих IP-адресов, которыми пользуются почтовые серверы всего мира |
| **ACME / Let's Encrypt** | Автоматическая служба выдачи бесплатных SSL-сертификатов |
| **Порт** | Дверь в доме. Порт 443 — «дверь для сайта», 25 — «дверь для почты», 4040 — «служебная дверь Kerio» |
| **SHA-256** | Отпечаток пальца файла. Если файл подменили — отпечаток изменится |

### 1.3 Восемь вкладок = восемь отделов

| Вкладка | Когда открывать |
|---|---|
| 🔐 **Выпуск сертификата (IP + Домен)** | Нужен новый SSL-сертификат для сайта или почты |
| 📬 **Установка в Kerio Connect** | Сертификат есть, надо поставить его в Kerio |
| 📨 **Проверка почты и Антиспам** | «Письма не доходят», «попадают в спам», «что у нас с почтой» |
| 🚑 **Выход из Блэклистов и Письма** | Сервер попал в чёрный список, нужны готовые письма на разблокировку |
| 🌍 **Санкции и Гео-блокировки** | Не выдаётся сертификат, домен не виден за границей, «нас заблокировали» |
| 📂 **Выпущенные сертификаты и Автопродление** | Посмотреть, что уже выпущено, и включить автообновление |
| 🛡️ **Антиспам-база KCM (GitHub)** | Надо усилить защиту от спама/фишинга и держать базу свежей |
| 🧰 **Инструменты админа** | Разобрать заголовки письма, собрать DNS-записи |

### 1.4 Что программа НЕ делает

- ❌ **Не заменяет админа.** Она показывает проблему и даёт инструкцию, но DNS-записи и настройки Kerio всё равно вносятся руками (в панели регистратора и в Kerio WebAdmin).
- ❌ **Не является антивирусом.** Антиспам-база — это правила для спама/фишинга, а не защита от вирусов.
- ❌ **Не отправляет письма от вашего имени** без вашего действия: тестовое письмо уходит только по нажатию кнопки.
- ❌ **Не платит и не подаёт заявки автоматически** в Spamhaus/Microsoft: она готовит письмо и открывает портал, отправляете вы.

## 2. Первый запуск

### 2.1 Откуда взять

В репозитории проекта лежат два файла:

- **`KerioCertManager.exe`** — сама программа (один файл, ~10,5 МБ, ничего ставить не нужно);
- **`KerioCertManager-Windows-x64.zip`** — архив: программа, инструкция `README-Инструкция.md`, этот ФАК (`FAQ-Полная-инструкция.md`) и 4 значка на выбор.

Ссылки для скачивания:

- https://github.com/zigorminsk-debug/jiraHelp/raw/arena/f70f3591-jirahelp/KerioCertManager.exe
- https://github.com/zigorminsk-debug/jiraHelp/raw/arena/f70f3591-jirahelp/KerioCertManager-Windows-x64.zip

### 2.2 Что нужно на компьютере

| Требование | Подробности |
|---|---|
| Windows | Windows 10 / 11, Windows Server 2016 и новее, 64-бит. На Server 2012 R2 тоже работает, но интерфейс откроется в браузере (WebView2 там не поддерживается) |
| WebView2 | Обычно уже установлен (вместе с Windows или Edge). Если нет — программа откроет интерфейс в обычном браузере |
| Права | Для большинства действий — **локальный администратор** |
| Интернет | Нужен для Let's Encrypt, проверок, GitHub. Для локального (self-signed) сертификата — не нужен |
| .NET / Python / OpenSSL | **Не нужны.** Всё внутри одного `.exe` |

### 2.3 Запуск

1. Скопируйте `KerioCertManager.exe` в **постоянную папку**, например `C:\KerioCertManager\`. Не запускайте из архива и не из «Загрузок»: рядом с программой создаются папки `certs` и файлы настроек.
2. Нажмите по файлу **правой кнопкой → «Запуск от имени администратора»**.
3. Если Windows покажет синее окно «SmartScreen» — нажмите **«Подробнее» → «Выполнить в любом случае»**. Это нормально для программ без платной подписи Microsoft.
4. Откроется окно программы (до 1380×940; на маленьком экране — меньше, см. п. 2.8). Внутри — обычная веб-страница, но она работает **локально**: адрес `http://127.0.0.1:17840`, снаружи он недоступен.

> ⚠️ Если окно не открылось, а в браузере появилась страница — значит, WebView2 не установлен, и программа открыла интерфейс в Edge/Chrome. Так работать можно, но лучше поставить «Microsoft Edge WebView2 Runtime» — окно будет отдельным.

### 2.4 Как проверить, что у вас правильная сборка

Версию можно посмотреть в трёх местах — они всегда должны совпадать:

1. **В окне программы** — плашка в шапке: `Windows Native GUI v4.6.0` и та же версия в подвале.
2. **По файлу** — правой кнопкой по `KerioCertManager.exe` → **Свойства → Подробно**: `Версия файла` и `Версия продукта` = **4.6.0.0**.
3. **В интерфейсе Kerio** — в журнале подключения: `KerioCertManager/4.6.0 (Windows)`.

Если версии не совпадают, значит файл скачан не оттуда или сборка устарела — скачайте заново и замените `.exe` целиком (рядом лежащая папка `certs` сохранится).

### 2.5 Права администратора: зачем и как проверить

Без прав администратора вы **сможете**: смотреть, проверять почту, строить отчёты, выпускать сертификат в папку пользователя.

Без прав **не сможете**: писать в `C:\Program Files\Kerio\...`, перезапускать службу `KerioMailServer`, открывать порт 80/443, создавать задания Планировщика, менять значок окна Windows.

**Как понять, что права есть:** в шапке нет предупреждения о правах, а операции с Kerio проходят. Если что-то не так — закройте программу и запустите снова «от имени администратора» (либо воспользуйтесь кнопкой повышения прав в шапке, если она показана).

### 2.6 Что происходит при первом запуске

- Программа создаёт рядом с собой папку **`certs`** — там будут сертификаты, настройки и база.
- Подставляет вашу последнюю почту/домен, если они уже вводились раньше (настройки сохраняются автоматически).
- Пытается определить **внешний IP** — для этого она делает несколько запросов (DNS DoH → SPF → внешние сервисы). Это нормально.
- В журнале внизу появляется строка «Программа … готова к работе».
- Над вкладками появляется синяя подсказка **«Впервые здесь?»** — она ведёт на вкладку **📖 ФАК** с этой самой инструкцией. Подсказка показывается один раз: после нажатия «Понятно» или перехода в инструкцию она больше не появляется.

### 2.7 Как закрыть

- Кнопка **⏻ Выход** в правом верхнем углу — корректно закрывает окно и локальный сервер.
- Крестик окна — то же самое.
- ❌ Не оставляйте программу запущенной «на всякий случай» на годы: она держит локальный порт. Закрывайте после работы.

### 2.8 Шапка и меню всегда сверху

При прокрутке длинной страницы **шапка с кнопками и полоса вкладок остаются на месте** — переключаться между разделами и проверять обновления можно с любого места страницы, не возвращаясь наверх.

- Высота «прилипшей» области измеряется автоматически: если окно узкое и шапка переносится на две строки, вкладки встают ровно под ней, ничего не перекрывая.
- Когда полоса вкладок отделяется от содержимого, у неё появляется мягкая тень — видно, что она закреплена.
- Переходы по оглавлению инструкции (`📖 ФАК`) учитывают эту высоту: заголовок не прячется под шапкой.
- Если окно очень маленькое по высоте (RDP, 768 px), «липкая» область остаётся компактной: длинный бейдж версии и подзаголовок скрываются автоматически.

### 2.9 Маленький экран, ноутбук 1366×768, RDP или увеличенный масштаб Windows

Интерфейс подстраивается сам — ничего настраивать не нужно:

- **Размер окна подбирается под экран.** На 1920×1080 программа открывается в привычном размере 1380×940, а на маленьком экране или в RDP-сессии окно автоматически становится меньше, чтобы не уезжать за края.
- **Вкладки не обрезаются.** На обычных экранах они подписаны коротко — `Сертификат`, `Kerio`, `Почта`, `Блэклисты`, `Санкции`, `Хранилище`, `Антиспам`, `Инструменты` (полное название видно во всплывающей подсказке при наведении). Если места совсем мало, вкладки переносятся на вторую строку, а не уезжают за правый край. На мониторах 4K и шире показываются полные названия.
- **Поля и кнопки перестраиваются.** Уже на ширине меньше 1180 px двухколоночная раскладка становится одноколоночной, а ниже 900 px поля ввода, кнопки и карточки занимают всю ширину; шапка на очень узких окнах показывает только значки.
- **Окно можно тянуть за угол** — вёрстка перестроится на лету. Горизонтальной прокрутки у панели вкладок больше нет.

Если что-то всё равно не помещается: разверните окно на весь экран (двойной клик по заголовку) или уменьшите масштаб Windows (Параметры → Дисплей → Масштаб 100%).

### 2.10 Большие экраны: 2K, 4K и ultrawide

На широком мониторе страница больше не жмётся в узкую колонку по центру — рабочая область растёт вместе с окном (до 1880 px) и заполняет экран.

- **Две колонки на всю ширину.** На вкладке «Выпуск сертификата» слева форма, справа — подсказки, результаты и журнал. Раньше правая колонка при ширине больше 1300 px уезжала вниз и половина экрана оставалась пустой; теперь обе колонки делят ширину поровну (на 1600 px и шире) и растут вместе с окном.
- **Правая колонка никогда не пустует.** До первого выпуска в ней показана карточка **🧭 Быстрый старт**: три шага, живая сводка (домен, IP, режим, способ проверки) и кнопка **🩺 Проверить готовность**. Как только сертификат выпущен, карточка уступает место файлам и журналу.
- **Поля не растягиваются в бесконечную ленту.** Внутри карточек сетки полей остаются двух- и трёхколоночными, поэтому ввод не прыгает в одну строку на 40 см.
- **Баннеры и подвал** выровнены по той же ширине, что и карточки.
- Масштаб Windows (125 %, 150 %) учитывается автоматически: раскладка считается от реальных пикселей окна.

> 💡 Если на 4K всё выглядит мелко — увеличьте масштаб Windows (Параметры → Дисплей → Масштаб 150 %) или растяните окно: вёрстка перестроится без перезапуска.

## 3. Вкладка 1 — Выпуск сертификата

Это самая первая и самая важная вкладка. Здесь создаётся SSL-сертификат.

Слева — форма в три шага, справа — живая колонка: карточка **🧭 Быстрый старт** (план, сводка параметров и кнопка «Проверить готовность»), затем результаты предпроверки, готовые файлы и журнал выполнения. Пока сертификат не выпущен, справа видна именно подсказка, поэтому место не пустует.

### 3.1 Что заполнять (сверху вниз)

Поля сгруппированы в три карточки: **«1 Доменное имя и IP-адрес почтового сервера»**, **«2 Режим выпуска и способ подтверждения Let's Encrypt»**, **«3 Параметры ключа (.key) и установка в Kerio Connect»**. Ниже — все поля по порядку.

| Поле | Что писать | Пример |
|---|---|---|
| **Доменное имя сервера (CN / DNS) *** | Имя, на которое нужен сертификат. Обычно `mail.вашдомен` | `mail.company.by` |
| **Дополнительные домены (SAN — только те, для которых есть A-запись в DNS)** | Другие имена, которые будут работать по тому же сертификату. Добавляются кнопками `webmail`, `autodiscover`, `smtp`, `imap`, `pop3`; крестик **✕ Очистить** убирает все | `webmail.company.by` |
| **IP-адрес сервера *** | Внешний (белый) IP, на который указывает домен. Можно IPv4 или IPv6 | `93.125.10.25` |
| **Email администратора** | Куда Let's Encrypt пришлёт письмо, если сертификат перестанет продлеваться | `postmaster@company.by` |
| **Метод подтверждения (ACME Challenge)** | Как вы докажете, что домен ваш (см. 3.3) | HTTP-01 (порт 80) |
| **Локальный порт приёма проверки** | Порт, на котором программа поднимет временный сервер проверки | `80` |
| **Путь к корневой папке веб-сайта (Webroot)** | Только для метода Webroot | `C:\inetpub\wwwroot` |
| **Срок действия сертификата (дней)** | Только для локального (self-signed) режима | `365` |
| **Алгоритм и формат приватного ключа** | Для Kerio — RSA 2048 в формате PKCS#1 | оставить по умолчанию |
| **Пароль для PFX-архива** | Необязательно. Пусто = `.pfx` без пароля | — |
| **Папка сохранения сгенерированных ключей и сертификатов** | Куда сложить результат. По умолчанию `certs` рядом с программой | `C:\KerioCertManager\certs` |
| **Путь к папке sslcert Kerio Connect** | Куда Kerio ставит сертификаты | `C:\Program Files\Kerio\MailServer\sslcert` |

> 💡 **Совет.** Если нужен только `mail.company.by`, оставьте SAN пустым. Добавляйте SAN заранее: сертификат на 5 имён ничем не хуже, а перевыпускать не придётся.

### 3.2 Три режима — какой выбрать

| Режим | Что даёт | Когда использовать |
|---|---|---|
| 🟢 **Let's Encrypt** | Настоящий доверенный сертификат на 90 дней (или 6 дней для сертификата с IP) | Всегда в «бою» |
| 🧪 **LE Staging** | Точно такой же процесс, но сертификат тестовый, браузер ему не доверяет. **Лимитов нет** | Сначала потренироваться, чтобы не исчерпать лимиты Let's Encrypt |
| ⚡ **Локальный (Kerio)** | Мгновенный «самоподписанный» сертификат без интернета | Тесты, внутренняя сеть, когда LE недоступен |

> ⚠️ **Лимиты Let's Encrypt.** На один домен можно выпускать ограниченное число сертификатов в неделю. Если вы «пробуете и не получается», сначала используйте **🧪 LE Staging**, а на боевой режим переходите, когда всё заработало.

### 3.3 Четыре способа подтверждения (главная таблица)

Let's Encrypt должен убедиться, что домен действительно ваш. Есть 4 способа:

| Способ | Что нужно | Плюсы | Минусы |
|---|---|---|---|
| **HTTP-01 (порт 80)** | Открытый из интернета порт 80, домен указывает на ваш IP | Работает почти всегда, просто | Если порт 80 занят Kerio — программа на 5–10 секунд остановит службу и сразу запустит её снова |
| **TLS-ALPN-01 (порт 443)** | Открытый порт 443 | Не нужен 80 | Порт 443 тоже часто занят |
| **HTTP-01 Webroot** | Порт 80 свободен, есть папка сайта (IIS/nginx) | Ничего не останавливает | Нужен настроенный веб-сервер |
| **DNS-01 (TXT-запись)** | Доступ к панели DNS домена | **Работает даже при полностью закрытых портах**, за NAT, из закрытой сети | Нужно вручную добавить TXT-запись и подождать DNS |

**Как выбрать:**

- Порт 80 открыт и свободен → **HTTP-01**.
- Порт 80 занят Kerio → **HTTP-01** с галочкой авто-остановки службы, либо **TLS-ALPN-01** (порт 443).
- Порты закрыты / сервер за NAT / нужно выпустить сертификат «откуда угодно» → **DNS-01**.
- Есть свой веб-сервер и не хочется трогать службы → **Webroot**.

### 3.4 Что делают кнопки

**✨ Найти существующие поддомены в DNS** — программа спрашивает DNS: «есть ли у домена `webmail`, `autodiscover`, `smtp`, `imap`, `pop3`?» и добавляет в SAN только те, что реально существуют. Это защищает от ошибки «домен не существует» при выпуске.

**Кнопки `+ webmail`, `+ autodiscover`, `+ smtp`, `+ imap`, `+ pop3`** — быстро добавляют стандартные имена Kerio.

**🌐 Внешний IP** — программа определяет ваш белый IP. Полезно, если сервер за NAT и вы не знаете, какой адрес видят снаружи.

**🔍 Проверить DNS, IP и порт** — предпроверка. Ничего не выпускает, только проверяет:
- существует ли домен и на какой IP он указывает;
- совпадает ли этот IP с тем, что вы ввели;
- открыт ли порт 80/443 из интернета;
- не мешает ли NAT.

**🔐 Сгенерировать ключ и выпустить сертификат** — главная кнопка: создаёт ключ, проходит проверку ACME, сохраняет сертификат.

**📬 Установить в Kerio Connect** — мгновенно переходит к установке (см. раздел 4).

### 3.5 Как читать предпроверку

| Что показывает | Что значит | Что делать |
|---|---|---|
| ✅ «DNS A-запись совпадает с IP» | Всё правильно | Продолжать |
| 🔴 «A-запись указывает на другой IP» | Домен ведёт не туда | Исправить A-запись в панели DNS, подождать 5–30 минут |
| 🔴 «Домен не существует» | Опечатка или запись ещё не создана | Проверить написание, создать A-запись |
| 🔴 «Порт 80 закрыт» | Проверка снаружи не пройдёт | Открыть порт на роутере/файрволе или выбрать DNS-01 |
| 🟠 «Порт 80 занят Kerio» | Kerio сам держит 80 | Включить авто-остановку службы или использовать DNS-01 |
| 🟠 «NAT: внешний IP не совпадает с локальным» | Сервер за роутером | Убедиться, что проброс портов 80/443 сделан на сервер Kerio |

### 3.6 DNS-01: пошагово

1. Выберите метод **DNS-01**. Появятся кнопки **📋 Открыть окно с TXT-записью**, **🔍 Проверить TXT в публичном DNS (Google 8.8.8.8 / Cloudflare 1.1.1.1)** и **✅ Подтвердить TXT-записи и выпустить сертификат**. Если хотите выпустить сертификат прямо с этого компьютера, минуя порты 80/443, нажмите **🌐 Выпустить сертификат прямо с этого ПК через DNS-01 (без портов 80/443) →**.
2. Программа покажет **имя записи** (`_acme-challenge.вашдомен`) и **значение TXT**; кнопкой **📋 Копировать TXT** его можно забрать в буфер.
3. Откройте панель DNS вашего регистратора (например, `hoster.by`, Cloudflare, reg.ru) и создайте запись:
   - Тип: `TXT`
   - Имя/Хост: `_acme-challenge`
   - Значение: длинная строка из программы (копировать целиком, без пробелов)
   - TTL: 300 (5 минут) или минимум, который разрешён
4. Сохраните. Подождите 5–15 минут (иногда до часа).
5. Нажмите **🔍 Проверить TXT в публичном DNS (Google 8.8.8.8 / Cloudflare 1.1.1.1)** — программа спросит оба резолвера. Должно быть «найдено».
6. Нажмите **✅ Подтвердить TXT-записи и выпустить сертификат**.

> ⚠️ Если добавляете несколько доменов, TXT-записей будет несколько (по одной на имя). Все они должны существовать одновременно — не удаляйте предыдущую, пока не выпустите сертификат.

### 3.7 Что вы получите в итоге

Файлы складываются в подпапку с именем домена: `certs\mail.company.by\` (если домена нет — `ip-93.125.10.25`).

| Файл | Что это | Куда |
|---|---|---|
| `server.key` | Приватный ключ. **Никому не передавать!** | В Kerio вместе с `server.crt` |
| `server.crt` | Сертификат + вся цепочка CA (fullchain) | В Kerio |
| `mail.company.by.key` | Тот же ключ под именем домена | Для nginx/apache |
| `mail.company.by-fullchain.crt` | Сертификат + цепочка под именем домена | Для nginx/apache |
| `chain.crt` | Только промежуточные CA | Для nginx/apache |
| `cert-only.crt` | Только ваш сертификат без цепочки | Для некоторых систем |
| `mail.company.by.csr` | Запрос на сертификат | Если выпускаете в другом месте |
| `mail.company.by.pfx` | Всё вместе (ключ + сертификат) в одном файле | Для Windows/IIS/Exchange |
| `install-kerio.bat` | Готовый скрипт установки | Запустить от админа |
| `README-KERIO.txt` | Шпаргалка «что куда класть» | Прочитать при ручной установке |
| `mail.company.by-kerio-bundle.zip` | Всё вышеперечисленное в архиве | Для передачи коллеге |

> 💡 **Почему `server.crt` — это «fullchain».** Если положить только ваш сертификат без промежуточного CA, Outlook и телефоны будут писать «цепочка не доверена». Программа всегда кладёт полную цепочку — это правильно.

### 3.8 Частые ошибки этой вкладки

| Ошибка в окне | Причина | Решение |
|---|---|---|
| `DNS problem: NXDOMAIN looking up A` | Домена нет в DNS | Создать A-запись |
| `Invalid response ... 404` | Проверка не дошла до программы | Открыть порт 80, проверить NAT |
| `ПУСТОЙ ОТВЕТ (got "")` | Порт 80 на роутере проброшен **не на этот компьютер**, а на другой сервер с Kerio | Пробросить 80 на нужный сервер, остановить на нём Kerio (программа сделает это сама от админа) или выпустить через **DNS-01** |
| `Timeout during connect (likely firewall)` | Порт закрыт файрволом | Открыть порт на роутере и в Windows Firewall |
| `too many certificates already issued` | Исчерпан лимит LE | Подождать неделю или использовать **Staging** |
| `Policy forbids issuing for name` | Домен под санкциями (OFAC) | См. вкладку «Санкции» |
| `Кириллический домен` | `.бел`, `.рф` | Ничего не делать: программа сама переведёт в Punycode (`xn--...`) |
| `Сертификат не принят Kerio` | Неверный формат ключа | Использовать «Локальный (Kerio)» или RSA 2048 PKCS#1 |

## 4. Вкладка 2 — Установка в Kerio Connect

Здесь сертификат попадает внутрь Kerio. Есть **два способа**, между ними переключает поле «Способ установки в Kerio Connect».

В самом верху вкладки находится карточка **🔐 Вход под администратором Kerio Connect** — быстрая проверка логина и пароля администратора с разбором причин неудачи (раздел 4.6). Если она зелёная, способ 2 (через Admin API) точно сработает.

### 4.1 Способ 1 — «Файловый метод — Копирование в sslcert + авто-бэкап + перезапуск KerioMailServer» (простой и надёжный)

**Что делает:** копирует `server.crt` и `server.key` в папку `MailServer\sslcert`, предварительно сделав резервную копию старых файлов, прописывает активный профиль в `mailserver.cfg` и перезапускает службу `KerioMailServer`.

Есть галочка **«Перезапустить службу Windows `KerioMailServer` после копирования»** (включена по умолчанию). Если её снять, файлы обновятся, но Kerio продолжит отдавать старый сертификат до перезапуска.

**Плюсы:** работает всегда, даже без пароля администратора Kerio.
**Минусы:** служба почты перезапускается — 5–20 секунд письма копятся в очереди.

**Что заполнить:**

| Поле | Что писать |
|---|---|
| **Выберите выпущенный сертификат для установки** | Домен из списка уже выпущенных сертификатов (например `mail.company.by — 89 дней`) |
| **Путь к папке MailServer\sslcert на сервере Windows** | `C:\Program Files\Kerio\MailServer\sslcert` |

### 4.2 Способ 2 — «Через Kerio Connect Admin API (порт 4040) — Онлайн без перезапуска службы почты!»

**Что делает:** входит в Kerio по JSON-RPC на порт 4040, загружает файл, импортирует его и делает активным — **без перезапуска службы**.

**Что заполнить:**

| Поле | Что писать |
|---|---|
| **Хост / IP админки Kerio** | Локальный IP сервера, например `10.146.100.14` или `127.0.0.1`, если программа на том же сервере |
| **Порт Admin API** | `4040` (по умолчанию) |
| **Логин администратора** | `Admin` (или другой админ Kerio) |
| **Пароль администратора** | Пароль Kerio. **Программа его не сохраняет** |

> ⚠️ **Порт 4040 нельзя открывать в интернет.** Это полный доступ к серверу. Если вы «снаружи» — сначала подключите VPN, и укажите внутренний IP Kerio.

### 4.3 Кнопки

| Кнопка | Что делает |
|---|---|
| **Обзор...** | Выбрать папку `sslcert` в проводнике |
| **Проверить папку** | Проверяет, что путь существует и похож на папку Kerio; показывает найденные сертификаты |
| **🩺 Диагностика подключения к Kerio (найти точную причину)** | Проходит 9 шагов: DNS → TCP :4040 → TLS → веб-админка → вход → права → версия → список сертификатов → загрузка файла. Показывает, **на каком именно шаге** всё сломалось |
| **🌐 Найти Kerio в сети** | Сканирует подсеть и типовые адреса, находит сервер Kerio |
| **📜 Только список сертификатов** | Ничего не меняет, просто показывает, что уже установлено |
| **📬 Установить выбранный ключ и сертификат в Kerio Connect** | Основное действие |
| **🔄 Перезапустить службу** | Перезапуск службы Kerio вручную: имя службы определяется автоматически, состояние показывается по-русски |

**Что происходит при нажатии «🔄 Перезапустить службу» (v4.9.1).** Программа запрашивает у Windows список служб, находит службу Kerio Connect (обычно `KerioMailServer`, на нестандартной установке — своё имя), выполняет `sc stop` и `sc start`, а затем **ждёт фактического состояния** `STOPPED`/`RUNNING` и показывает его в журнале и всплывающем сообщении. Сообщения читаются по-русски: вывод консоли Windows (кодировка CP866) декодируется, а строки вида `NET HELPMSG 2185` убираются.

| Что вы увидите | Что это значит |
|---|---|
| `Служба «KerioMailServer»: действие «restart» выполнено, состояние — RUNNING` | всё в порядке, Kerio снова принимает почту |
| `Служба не установлена` | программа не нашла службу Kerio на этом компьютере — управлять можно только на самом сервере Kerio |
| `Нужны права администратора` | закройте программу и запустите `KerioCertManager.exe` от имени администратора |
| `служба не перешла в состояние RUNNING за 90 с` | посмотрите журнал Kerio: служба запускается, но падает — причина в самом Kerio, а не в программе |

### 4.4 Как убедиться, что сертификат встал

1. Откройте Kerio WebAdmin: `https://<сервер>:4040/admin/`.
2. **Конфигурация (Configuration) → Сертификаты SSL (SSL Certificates)**.
3. Найдите активный сертификат: в колонке дат должен быть **новый срок** (например, +90 дней).
4. Откройте `https://mail.вашдомен` в браузере — замочек должен быть зелёным, без предупреждений.
5. В Outlook/телефоне переподключите учётную запись, если клиент кэшировал старый сертификат.

**Если ставите вручную (через WebAdmin), а не программой** — внутри вкладки есть кнопка **📖 Куда нажимать в Kerio Connect**. Порядок такой:

1. **Конфигурация (Configuration) → Сертификаты SSL (SSL Certificates)**.
2. Кнопка **Импорт (Import) → Импортировать новый сертификат… (Import New Certificate…)**.
3. В поле **Сертификат (Certificate)** выберите `server.crt` — он уже содержит ваш сертификат + промежуточный сертификат Let's Encrypt.
4. В поле **Приватный ключ (Private key)** выберите `server.key` (незашифрованный RSA-ключ).
5. Выделите добавленный сертификат в таблице и нажмите **Использовать (Set as Active)** — готово.

### 4.5 Частые ошибки

| Сообщение | Причина | Решение |
|---|---|---|
| `HTTP 401 Unauthorized` | Неверный логин/пароль админа Kerio | Проверить пароль; логин — именно администратор Kerio, не почтовый ящик |
| `HTTP 404` | Порт 4040 — это не Kerio / неверный путь | Проверить, что открыт `https://IP:4040/admin/` |
| `таймаут подключения` | Порт 4040 закрыт или неверный IP | VPN, файрвол, внутренний IP вместо внешнего |
| `недостаточно прав` | Учётка не администратор | Дать права администратора Kerio |
| `Unable to import certificate, the content is invalid` | Ключ/сертификат не в формате Kerio | Использовать файловый метод или перевыпустить в режиме «Локальный (Kerio)» |
| `служба не найдена` | Kerio стоит на другом сервере | Установить сертификат через Admin API |
| `Access denied` при копировании в sslcert | Нет прав администратора Windows | Запустить программу от имени администратора |

### 4.6 Вход под администратором Kerio Connect — проверка и разбор ошибок

Отдельная карточка **🔐 Вход под администратором Kerio Connect** в самом верху вкладки отвечает на один вопрос: **подходит ли этот логин и пароль администратору Kerio Connect?** Она не трогает сертификаты и ничего не меняет на сервере — только входит и выходит.

**Когда это нужно:**

- перед установкой через API — убедиться, что пароль верный, и не гадать, почему импорт не проходит;
- после смены пароля администратора — проверить, что новый пароль работает;
- когда «программа не подключается к Kerio» — за 3 секунды понять, дело в пароле, в правах или в сети;
- при передаче сервера коллеге — показать, под какой учёткой работает автоматизация.

**Что заполнить:**

| Поле | Что писать |
|---|---|
| **Хост / IP админки Kerio** | Внутренний IP сервера (`10.146.100.14`) или `127.0.0.1`, если программа стоит на самом сервере Kerio |
| **Порт Admin API** | `4040` (по умолчанию). Kerio Control — `4081`, Kerio Operator — `4021` |
| **Логин администратора** | Короткое имя администратора Kerio (`admin`, `kerioapi`). **Не почтовый ящик** `info@company.by` |
| **Пароль администратора** | Тот же, что на `https://<сервер>:4040/admin/`. **Программа его не сохраняет** |
| **Проверять права на SSL-сертификаты** | Галочка: дополнительно читает список сертификатов, чтобы сразу знать, сможет ли эта учётка их устанавливать |

Кнопка **↧ Взять из блока установки** копирует адрес, порт и логин из соседнего блока — если вы уже заполнили его.

**Что делает проверка (по шагам):**

1. **Параметры** — есть ли пароль, нет ли пробелов по краям, не похож ли логин на почтовый ящик.
2. **DNS** — разрешается ли имя сервера (если указан IP — шаг сразу зелёный).
3. **TCP-порт** — принимает ли сервер соединения на 4040.
4. **TLS** — поднимается ли шифрование и что за сертификат отдаёт сервер.
5. **Веб-админка** — открывается ли `/admin/` (ловушка «на порту не Kerio»).
6. **Вход** — `Session.login` с перебором разумных вариантов логина (`admin`, `admin@домен`, …). В отчёте видно **каждую** попытку.
7. **Сессия** — пришёл ли `X-Token` и cookie `SESSION_CONNECT_WEBADMIN` (прокси иногда вырезает cookie).
8. **Права** — `Session.whoAmI`: роль и признак администратора.
9. **Версия продукта** — `Kerio Connect 9.4.1`, API v8 (и предупреждение, если это Kerio Control).
10. **Сертификаты** — реальная проверка прав: читается список SSL-сертификатов (`Certificates.get`, а если сборка его не знает — `ConnectCertificate.get`).

**При успехе** карточка показывает зелёную плашку: под какой учёткой вошли, роль, версию Kerio, длину и края токена, количество сертификатов на сервере. Например:

```
✅ Вход выполнен: admin (администратор). Пароль администратора верный. Сервер: Kerio Connect 9.4.1. Права на сертификаты есть (видно 3).
```

Дополнительно появляется подсказка: этот же логин можно использовать в блоке «Через Kerio Connect Admin API» для установки сертификата.

**При неудаче** карточка не ограничивается словом «ошибка»: она называет **причину**, объясняет её простыми словами и даёт нумерованный план устранения + строку «🔎 Где проверить».

| Что показала проверка | Настоящая причина | Что делать |
|---|---|---|
| `Invalid user name or password` | Неверная пара логин/пароль | Войти тем же паролем на `https://<сервер>:4040/admin/`; проверить Caps Lock и раскладку; попробовать `admin` без домена |
| `Two-factor authentication is required` | У администратора включена 2FA, а Admin API её не поддерживает | Создать отдельного администратора **без 2FA** (Configuration → Administration → Administrators → Add) и использовать его |
| Вошли, но роль `user` | Учётка не администратор (например почтовый ящик) | **Accounts → Users** → учётка → вкладка **Rights** → **Whole server read/write** (подробно — §4.6.1) |
| `Access denied` при чтении сертификатов | Вход есть, но прав «весь сервер, чтение и запись» нет | Пошагово — **§4.6.1** ниже: включить встроенную учётку `Admin` или выдать права `Whole server read/write` |
| `Kerio временно заблокировал вход` | Сработала защита от подбора после нескольких неудач | Подождать 10–30 минут, не жать проверку подряд; посмотреть Logs → Security |
| Порт 4040 не отвечает | Служба Kerio остановлена, порт закрыт файрволом или указан внешний адрес | Запустить Kerio, разрешить TCP 4040 в локальной сети, использовать VPN |
| Cookie сессии не пришёл | Прокси/антивирус вырезает cookie | Отключить SSL-инспекцию для адреса Kerio или запустить программу на самом сервере |
| Ответ HTML вместо JSON | Адрес API неверный или это не Kerio Connect | Проверить, что открывается `https://<сервер>:4040/admin/` и порт соответствует продукту |

#### 4.6.1 Вход есть, а SSL-сертификаты не читаются

Карточка входа может сказать «Вход выполнен» и одновременно показать причину **«Учётка вошла, но у неё нет прав на SSL-сертификаты»**. Это нормальное сочетание: логин и пароль верные, Kerio пустил вас в админку, но уровень доступа учётной записи не позволяет читать и менять сертификаты. Ничего не сломано — это настройка прав в самом Kerio.

**Простыми словами.** В Kerio Connect «администратор» — это не отдельная роль, а уровень доступа у обычной учётной записи. Почтой может управлять и администратор домена, а вот SSL-сертификаты доступны только уровню «весь сервер, чтение и запись».

| Уровень в поле «Server administration» | Что разрешает | Сертификаты |
|---|---|---|
| **No rights** | ничего в админке | ❌ |
| **<домен> accounts** | только пользователей своего домена | ❌ |
| **Whole server read only** | смотреть всю админку, менять нельзя | ❌ (API тоже откажет) |
| **Whole server read/write** | всё, включая Configuration → SSL Certificates | ✅ |

Нужен именно **Whole server read/write** — «только чтение» для установки сертификата не подойдёт.

##### Способ 1 — встроенная учётка Admin (самый быстрый, 30 секунд)

1. Откройте веб-админку: `https://<сервер>:4040/admin/` и войдите учёткой с полными правами.
2. **Configuration → Administration Settings**.
3. Поставьте галочку **Enable built-in administrator account**.
4. Задайте пароль и нажмите **Apply**.
5. В карточке входа введите логин `Admin` (именно так, с большой буквы) и этот пароль.

У встроенной учётки всегда права `Whole server read/write`, она **не занимает лицензию** и не имеет почтового ящика — это лучший вариант для автоматизации. Если обычный пользователь тоже зовётся `admin`, при входе ему нужно указывать домен (`admin@company.by`), а встроенному — просто `Admin`.

##### Способ 2 — выдать права существующей учётке

1. В веб-админке: **Accounts → Users** (в части сборок путь **Configuration → Administration → Administrators**).
2. Двойной клик по нужной учётке (или кнопка **Edit**).
3. Вкладка **Rights**.
4. В разделе **Server administration** выберите **Whole server read/write**.
5. **OK**. Перезапускать Kerio не нужно — права действуют сразу.

##### Как убедиться, что получилось

1. В веб-админке должен открываться раздел **Configuration → SSL Certificates** (если его нет — прав всё ещё нет).
2. В программе нажмите **🔓 Проверить вход** ещё раз.
3. В блоке «Что проверено» должно появиться «**Сертификаты: доступ есть, найдено N**», а в зелёной плашке — «права на сертификаты есть».
4. Если написано «найдено 0» — это нормально: на сервере просто нет сертификатов, установка создаст первый.

##### Если давать полные права не хотите

Установка **файловым методом** прав администратора Kerio не требует: файлы копируются в папку `sslcert` прямо на сервере (раздел 4.1). Через API — только с полными правами.

##### Что ещё может дать отказ при чтении сертификатов

| Что показывает программа | Причина | Что делать |
|---|---|---|
| `Access denied` / `Permission denied` | у учётки нет прав на весь сервер | способы 1 или 2 выше |
| `Method not found` / `Invalid params` (метод есть, но параметры ему не подошли) | **это не права**, а разница версий API: у Kerio Connect 9.2+/10.x интерфейс сертификатов другой, чем у 8.5–9.1 | нажать **🧪 Проверить API сертификатов** и установить сертификат ещё раз — программа сама выберет рабочий интерфейс (§4.6.2) |
| `Method not found` на всех вариантах | Kerio очень старой версии (до 8.5) или это не Kerio Connect | файловый метод (раздел 4.1) |
| Ответ HTML вместо JSON | на порту 4040 не Admin API | открыть `https://<сервер>:4040/admin/` и убедиться, что это Kerio Connect |
| Программа не подключается вовсе на 4081/4021 | это Kerio Control / Kerio Operator — другой продукт и другое API | программа их не настраивает; для Kerio Connect используйте порт 4040 |

> 💡 В карточке входа под причиной показывается **точный ответ Kerio** («Ответ Kerio: …») — по нему всегда видно, это отказ в правах или не тот адрес API. Кнопка **📖 Как исправить по шагам** открывает этот раздел.

**Кнопки карточки:**

| Кнопка | Что делает |
|---|---|
| **🔓 Проверить вход** | Запускает все шаги. В любом поле карточки работает клавиша **Enter** |
| **🌐 Открыть WebAdmin** | Открывает `https://<сервер>:<порт>/admin/` в браузере — чтобы проверить тот же пароль руками |
| **📋 Копировать отчёт** | Копирует текстовый отчёт (вердикт, попытки, причины, шаги) — удобно приложить к заявке. **Пароль и полный токен в отчёт не попадают** |
| **👁** | Показать/скрыть введённый пароль (проверка раскладки) |
| **📖 Как это работает** | Открывает этот раздел инструкции |

> ⚠️ **Пароль нигде не сохраняется** — ни в `ui_settings.json`, ни в журналах, ни в отчёте. Он живёт в памяти только на время запроса к Kerio.
>
> 🔒 **Порт 4040 не открывайте в интернет.** Это полный доступ к почтовому серверу. Снаружи — только VPN.

💡 **Если нужна полная картина** (DNS, TLS, веб-админка, права, загрузка файлов, список сертификатов вместе) — используйте кнопку **🩺 Диагностика подключения к Kerio** в блоке установки (раздел 4.3). Карточка входа — это быстрая проверка именно логина и пароля.

#### 4.6.2 «Раздел SSL открывается, права выданы, а добавление сертификата падает» (Kerio Connect 10)

Самая частая ситуация на **Kerio Connect 10.0.0**: в веб-админке **Configuration → SSL Certificates** открывается, учётка `Admin` с ролью `BuiltinAdmin`, сертификаты видны — но импорт из программы заканчивается ошибкой. Причина почти всегда одна: у Kerio **два разных интерфейса сертификатов**, и конкретная сборка понимает только один из них. Это **не про права**.

| Интерфейс Admin API | Где встречается | Как выглядит импорт |
|---|---|---|
| `Certificates.*` | Kerio Connect 9.2+ и 10.x — его использует веб-админка новых сборок | `importPrivateKey{fileId}` → `{keyId}`; затем `importCertificate{keyId, fileId, name, type:"InactiveCertificate"}`; активация `setActive{id}` |
| `ConnectCertificate.*` | Kerio Connect 8.5–9.1 | `importPrivateKey{fileId}` → `{id}`; затем `importCertificate{id, fileId, password:""}`; активация `setActive{id}` |

**Что делает программа начиная с v4.9.1:**

1. При чтении списка перебирает **оба** интерфейса и несколько форм запроса (`get` с параметром `query` и без него) — используется тот, который ответил.
2. При установке сначала пробует интерфейс, который ответил на чтении, а при ошибке «метод не найден»/«неверные параметры» — второй. Ошибка формы запроса больше не останавливает установку.
3. Если Kerio не вернул ID нового сертификата, программа находит его в списке по отпечатку **SHA-256**.
4. Активирует сертификат (`Certificates.setActive` или `ConnectCertificate.setActive`) и перечитывает список: при успехе в отчёте будет **«Kerio подтвердил активный сертификат «…» (действует до …)»**.
5. Если активация не удалась, установка всё равно считается выполненной (сертификат уже на сервере), а в отчёте — точный путь, где включить его вручную.
6. Если не сработали оба интерфейса — в тексте ошибки будут **оба ответа Kerio**, а не общая фраза «проверьте права».

**Как узнать, что именно отвечает ваш сервер:**

1. Заполните карточку **🔐 Вход под администратором Kerio Connect** (адрес, порт, логин, пароль).
2. Нажмите **🧪 Проверить API сертификатов** — рядом с кнопкой «📋 Копировать отчёт».
3. В отчёте будет строка на каждый запрос, например `[ OK ] Certificates.get {query…} — сертификатов: 4` или `[FAIL] ConnectCertificate.get` + строка **Ответ Kerio** с сырым JSON.
4. Кнопка **📋 Скопировать отчёт по API** копирует весь отчёт в буфер обмена — его можно приложить к заявке.

**Как читать отчёт:**

| Что в отчёте | Что это значит | Что делать |
|---|---|---|
| `[ OK ] Certificates.get … сертификатов: N` | сервер использует современный интерфейс, установка пойдёт через него | повторить установку |
| `[ OK ] ConnectCertificate.get …` | сервер старый (8.5–9.1), используется старый интерфейс | повторить установку |
| Все `[FAIL] … Method not found` | методов сертификатов нет вовсе: не Kerio Connect или очень старая версия | файловый метод (раздел 4.1) либо обновить Kerio |
| `[FAIL] … Access denied` / код `1004` | настоящий отказ в правах | раздел §4.6.1 |
| `[FAIL] … Invalid params` / `-32602` | сборка ждёт другую форму запроса, чем знает программа | обновить программу и приложить отчёт к заявке |
| Строка `… — МЕТОДА НЕТ на этом сервере` | метод отсутствует именно в этой сборке | использовать тот интерфейс, у которого стоит «метод есть» |

**Если установка всё равно не проходит — три рабочих пути:**

1. **Вручную в веб-админке:** Configuration → SSL Certificates → **Import** → выберите `server.crt` (или `fullchain.crt`) и `server.key` из папки выпуска → выделите новый сертификат → **Set as Active**.
2. **Файловый метод** (раздел 4.1): скопируйте файлы в папку `sslcert` на сервере Kerio и перезапустите службу кнопкой **🔄 Перезапустить службу**.
3. **Проверка результата:** Configuration → SSL Certificates — у активного сертификата должен быть новый срок действия; в браузере `https://mail.вашдомен` — зелёный замочек.

> ⚠️ Не путайте «нет прав» и «другая версия API». `Method not found` и `Invalid params` означают, что программа и Kerio не сошлись в форме запроса; `Access denied` и `1004` — что учётке действительно не хватает прав. Лечатся эти случаи по-разному.

## 5. Вкладка 3 — Проверка почты и антиспам

Это «медосмотр» почтового сервера: 20+ проверок за один запуск, с оценкой и инструкцией по каждой проблеме.

### 5.1 Что вводить

| Поле | Что писать | Пример |
|---|---|---|
| **Почтовый домен компании или email *** | Домен, на котором живёт почта | `company.by` |
| **Хост почтового сервера** | Необязательно, определится сам | `mail.company.by` |
| **🌐 Внешний белый IP** | Необязательно. Если пусто — программа определит сама (5 способами, не боясь Split-DNS) | `93.125.10.25` |
| **🔌 Локальный / VPN IP Kerio** | Если порты снаружи закрыты — укажите внутренний IP, проверка пойдёт по нему | `10.146.100.14` |
| **Селектор DKIM** | Обычно `mail`. Программа ищет его сама среди 12 стандартных | `mail` |

**Кнопка 🌐 Авто-IP** — принудительно переопределить внешний IP.

### 5.2 Что именно проверяется

| Проверка | Простыми словами | Что бывает при проблеме |
|---|---|---|
| **MX и A-запись** | Кто принимает почту и куда ведёт имя сервера | Письма «пропадают»: отправители не знают, куда их слать |
| **PTR / FCrDNS** | Обратный адрес IP. Половина мировых серверов требует, чтобы он совпадал с именем | Gmail/Mail.ru режут письма, RBL добавляют IP |
| **SPF** | Список серверов, которым можно отправлять от вашего домена | Письма в спаме; `+all` — дыра, любой может писать от вас |
| **SPF > 10 DNS-запросов** | Технический лимит RFC 7208 | Часть получателей считает SPF «сломанным» |
| **DKIM** | Цифровая печать письма | Подделки не отличить от настоящих писем, спам-фильтры недовольны |
| **DMARC** | Что делать получателю, если SPF/DKIM не совпали | Нет защиты от подмены домена |
| **Порт 25 и EHLO** | Сервер вообще принимает почту из интернета? | Внешние серверы не могут доставить письма |
| **Open Relay** | Не пересылает ли сервер чужие письма | 🔴 Критическая уязвимость: сервер используют спамеры, IP мгновенно в RBL |
| **SSL на портах 25/465/587/993/995** | Шифрование на всех почтовых портах и доверена ли цепочка | Клиенты ругаются, часть писем уходит без шифрования |
| **16 RBL-баз (Spamhaus ZEN, Barracuda, SpamCop, SORBS, Backscatterer, BlockList.de, UCEPROTECT, PSBL, WPBL, Mailspike, NiX Spam, SpamRATS, 0SPAM, Truncate GBUdb, LashBack, DroneBL)** | Не в чёрных ли списках IP | Письма блокируются у получателей |
| **4 доменных списка (Spamhaus DBL, SURBL, URIBL, SpamEatingMonkey)** | Не в чёрном ли список сам домен и ссылки в письмах | Письма уходят в спам даже при чистом IP |
| **Autodiscover / TLS-RPT** | Автонастройка Outlook и отчёты о TLS | Пользователи мучаются с настройкой, нет отчётов |
| **Опасные порты (3389/4040/445)** | Не открыты ли наружу RDP, админка Kerio, SMB | 🔴 Сервер могут взломать |
| **TLS 1.0 / 1.1** | Устаревшее шифрование | Не соответствие PCI DSS, часть клиентов не подключается |
| **CAA / MTA-STS / BIMI** | Кто имеет право выпускать сертификаты, строгий TLS, логотип в почте | Риск поддельного сертификата, нет логотипа |

### 5.3 Оценка, фильтры и история

- Оценка **0–100** и буквенная оценка:

| Оценка | Баллы | Что означает (текст программы) |
|---|---|---|
| **A+** | 95–100 | Эталонная настройка, высочайшая доставляемость во Входящие |
| **A** | 82–94 | Хорошая настройка, почта ходит стабильно |
| **B** | 65–81 | Работает, но часть писем может попадать в «Спам» |
| **C** | 45–64 | Высокий риск попадания в «Спам» и отказов доставки |
| **F** | 0–44 | Критические ошибки DNS/сервера |

- Счётчики: ✅ в порядке, 🟠 важные замечания, 🔴 критические проблемы.
- Фильтры: **Все проверки**, **🔴🟠 Только проблемы**, **✅ Успешные**.
- Если проверяли раньше, под полями появится строка **🕒 История проверок на этом компьютере**: чипы вида `@company.by: 68/100 (B) • 24.10.2026 14:05`. **Клик по чипу** подставит домен и хост в поля — удобно сравнивать результаты до и после исправлений.

### 5.4 Подробные инструкции

У каждой проблемной карточки **внутри** есть раскрывающийся блок с пошаговым исправлением — что открыть в Kerio WebAdmin, какую DNS-запись создать, какой командой проверить. Не нужно искать инструкцию на стороне.

Кнопка **📄 Сохранить полный HTML-отчёт с инструкциями** — делает файл, который можно приложить к заявке или отдать коллеге/руководителю (со всеми статусами и текстами исправлений).

### 5.5 Тестовая отправка письма

Внизу вкладки — блок SMTP:

| Поле | Значение |
|---|---|
| **SMTP сервер (внешний или VPN IP) *** | `mail.company.by` или внутренний IP |
| **Порт *** | `465` (SSL) — рекомендуется для Kerio; `587`/`25` для STARTTLS |
| **Шифрование** | SSL/TLS сразу / STARTTLS / без шифрования |
| **Логин ящика Kerio (email отправителя) *** | полный адрес ящика, например `test@company.by` |
| **Пароль от этого почтового ящика *** | пароль этого ящика (не сохраняется) |
| **От кого (From) *** / **Кому отправить тестовое письмо (To) *** | адреса для теста |

Нажмите **🚀 Отправить контрольное письмо и показать лог SMTP**. В логе видно всю сессию: подключение, TLS, авторизацию, ответ сервера. Это лучший способ понять, почему «письма не уходят»: ошибка авторизации, блокировка порта, неверный сертификат и т. д.

### 5.6 Что делать после проверки — порядок действий

1. Сначала **🔴 критические** (Open Relay, опасные порты, MX, порт 25).
2. Потом **🟠 важные** (SPF, DKIM, DMARC, PTR, RBL).
3. В конце — «улучшения» (CAA, MTA-STS, BIMI, TLS 1.0).
4. После каждой правки подождите 10–30 минут (DNS кэшируется) и нажмите проверку снова — история покажет рост оценки.

Внизу вкладки есть быстрые переходы: **🌍 Карта санкций и УЦ (Домен + IP) →**, **🚑 Центр вывода из блэклистов и готовые письма (8 шаблонов) →** и **🚑 Готовые письма разблокировки →** — они переносят вас на нужную вкладку с уже заполненными полями.

## 6. Вкладка 4 — Выход из блэклистов

Если сервер уже попал в чёрный список — здесь готовят **письма на разблокировку** и расшифровывают ошибки.

### 6.1 Что вводить

| Поле | Пример |
|---|---|
| **Ваш почтовый домен** | `company.by` |
| **Имя SMTP-сервера (HELO / PTR)** | `mail.company.by` |
| **Внешний белый IP** | `93.125.10.25` |
| **Текст ошибки 550/554** | Вставить из лога Kerio или из письма-возврата (необязательно) |

### 6.2 Восемь готовых пакетов

Программа формирует готовые письма и пошаговые инструкции для:

1. **Microsoft Outlook / Hotmail / Office 365** — ошибки `550 5.7.1 S3150/S3140` (закрытая база Microsoft, в обычных RBL её не видно).
2. **Mail.ru / BK.ru / List.ru / Inbox.ru / VK WorkMail** — `550 spam message rejected`.
3. **Google Gmail / Workspace** — `550-5.7.1`, `550-5.7.26`.
4. **Яндекс Почта / Яндекс 360** — `554 5.7.1 Message rejected under suspicion of SPAM`.
5. **Spamhaus** (SBL/XBL/CBL/PBL и доменный DBL).
6. **Barracuda Central** — корпоративные шлюзы банков и госорганов.
7. **SpamCop / SORBS / Backscatterer / UCEPROTECT**.
8. **Ваш интернет-провайдер** (Белтелеком, A1, МТС, «Деловая сеть», хостер VPS) — письмо на настройку PTR и проверку порта 25.

Плюс автоматически добавляются пакеты для тех RBL, где реально найден ваш IP.

### 6.3 Кнопки

- **🔄 Обновить и сгенерировать все письма** — перепроверяет RBL и формирует тексты под ваш домен/IP.
- **🔎 Расшифровать ошибку и сформировать готовые письма разблокировки** — вставьте текст `550/554`, программа скажет, **кто именно заблокировал** и что делать.
- **📋 Копировать команды MikroTik** — готовые команды для настройки NAT/портов, если у вас MikroTik.

### 6.4 Как отправить апелляцию

1. Откройте нужную карточку и нажмите **📋 Копировать** рядом с текстом письма.
2. Перейдите по кнопке портала (ссылка есть в карточке).
3. Заполните форму и вставьте текст. Где требуется — укажите IP, домен, контактный email.
4. **Ответ придёт на email** (для Microsoft — обязательно укажите ящик на другом домене, например Gmail, чтобы ответ дошёл).
5. Сохраните номер тикета.

### 6.5 Сколько ждать

| Кто | Срок |
|---|---|
| Microsoft Office 365 (sender.office.com) | 15–30 минут |
| Microsoft Outlook/Hotmail (olcsupport) | до 24 часов |
| Mail.ru / Яндекс | 1–3 рабочих дня |
| Spamhaus | от нескольких часов до 2 суток |
| Barracuda / SpamCop / SORBS | 1–3 суток |

> ⚠️ Пока идёт разбор, **устраните причину**: проверьте SPF/DKIM/DMARC, PTR, отсутствие рассылок, вирусов и открытого релея. Иначе IP забанят снова через день.

### 6.6 Чего делать нельзя

- ❌ Отправлять одну и ту же апелляцию по 10 раз — это ускоряет повторный бан.
- ❌ Платить «сервисам разблокировки за 100$» — 95% из них просто отправляют то же бесплатное письмо.
- ❌ Менять IP каждый раз вместо исправления причины — новый IP тоже быстро попадёт в список.

## 7. Вкладка 5 — Санкции и гео-блокировки

Проверяет, не мешают ли домену и IP санкционные списки и география.

### 7.1 Что вводить

| Поле | Пример |
|---|---|
| **Проверяемый домен или сайт *** | `company.by` |
| **Почтовый хост / поддомен SSL** | `mail.company.by` (подставится сам) |
| **🌐 Внешний белый IPv4** | пусто = определить автоматически |

Кнопка запуска: **🌍 Проверить домен и IP на санкционные и гео-блокировки**.

### 7.2 Что проверяется

| Блок | Смысл |
|---|---|
| **OFAC в Let's Encrypt** | Пробует «всерьёз» заказать сертификат в LE Staging. Если LE отвечает `Policy forbids issuing for name` — домен в санкционном списке |
| **Зона домена** | Есть ли у зоны ограничения (например, `.by`, `.ru` и т. п. в разных УЦ) |
| **Матрица центров сертификации** | Какие CA (Let's Encrypt, DigiCert, Sectigo, Google Trust, ZeroSSL…) выдадут сертификат для вашего домена/IP |
| **RIPE / ASN** | Кому принадлежит IP, из какой страны, есть ли ограничения |
| **Видимость DNS из США и Европы** | Видят ли ваш домен Google DNS, Cloudflare, Quad9. Если нет — зарубежные контрагенты не смогут вам написать |
| **Доступность мировых УЦ, CDN и почтовых шлюзов** | Может ли сервер достучаться до Let's Encrypt, Microsoft, Google и т. д. |

### 7.3 Как читать

- ✅ — ограничений нет.
- 🟠 — есть риск, но работать можно (например, один CA не выдаёт, другой выдаёт).
- 🔴 — блокировка: сертификат не получить или письма за границу не дойдут.

Внизу — блок **«Детальное заключение и рабочие схемы обхода»** с конкретными шагами: перенос DNS на облачный провайдер, смена CA, использование релея, настройка в рамках Указа № 60 РБ.

> ⚠️ Программа не даёт юридических консультаций. Решения о схемах обхода принимает организация; технические шаги — подсказка, а не приказ.

## 9. Вкладка 7 — Антиспам-база KCM

Это самая новая часть программы. Разберём максимально подробно.

### 9.1 Что это такое

Представьте, что каждое утро выходит свежий **список плохих отправителей и плохих сайтов в письмах**: домены мошенников, адреса, темы «вы выиграли приз», фразы «оплатите комиссию», IP-адреса спам-ботов и ссылки на фишинговые страницы.

Программа скачивает этот список с GitHub и кладёт его в Kerio Connect как **правила SpamAssassin**. Дальше Kerio сам складывает очки: если письмо пришло с «плохого» домена и содержит «плохую» ссылку — оно получает много очков и уходит в спам.

**Ключевое:** база **не заменяет** встроенные проверки Kerio (SPF/DKIM/DMARC, DNSBL, байесовский фильтр) — она **добавляется** к ним.

Внизу вкладки есть карточка **📖 Что именно делает база и как её обслуживать** — короткая встроенная шпаргалка, если этот ФАК не под рукой.

### 9.2 Что внутри базы и сколько очков

| Группа | Правило | Очки |
|---|---|---|
| Домены отправителей | `From` содержит домен из базы | **+3.2** |
| Конкретные адреса отправителей | `From` совпал с адресом | **+4.5** |
| Мотивы в теме письма | «выиграли», «аккаунт заблокирован» и др. | **+1.8** |
| Фразы в теле письма | «оплатите комиссию», «CVV код» и др. | **+1.5** |
| Домены фишинговых ссылок | ссылка в письме ведёт на домен из базы | **+2.5** |
| IP/CIDR источников | IP из заголовка `Received` | **+3.0** |
| Белый список | доверенный отправитель (банки, госсервисы, крупные провайдеры) | **−6.0** |

> 💡 Порог отказа Kerio по умолчанию — около **5.0 очков**. То есть одного «плохого домена» (+3.2) и «плохой темы» (+1.8) уже достаточно.

### 9.3 Откуда берутся данные

База собирается автоматически каждый день в 03:17 UTC из открытых источников:

- **Phishing.Database** (MIT) — активные фишинговые домены;
- **OpenPhish** — публичный фид фишинга;
- **ShadowWhisperer BlockLists** (Scam и Malware) — мошеннические и вредоносные домены;
- **HaGeZi TIF** — threat intelligence;
- **Dogino Discord-Phishing** — фишинг и скам-ссылки;
- **Spamhaus DROP** и **FireHOL level1** — IP-адреса ботнетов;
- **URLhaus** (abuse.ch) — включается, если в репозитории задан бесплатный ключ `ABUSECH_AUTH_KEY`.

Результат публикуется в двух местах: **GitHub Releases** (`antispam-db-latest`) и ветка **`antispam-db`**. Программа сначала пробует релиз, потом ветку.

### 9.4 Первый запуск вкладки

Откройте вкладку — сверху появятся плашки статуса:

| Плашка | Что показывает |
|---|---|
| **Версия базы в Kerio** | `не установлена` или номер вида `2026.10.24-0851` |
| **Правил в базе** | Сколько правил внутри `.cf` (например 944) |
| **Размер файла правил** | Размер `kerio-antispam.cf` в КБ |
| **Служба Kerio** | `RUNNING` / `STOPPED` / `NOT_FOUND` |
| **Последняя проверка GitHub** | Когда проверяли и какая версия лежит на GitHub |

Ниже — блок **Пути**: папка Kerio (и как она найдена), папка правил SpamAssassin, путь к файлу базы, папка локальных списков («✓ доступны» или «появятся после установки»), количество резервных копий и дата последней. Ещё ниже — **История операций** (последние 6 действий) и, если что-то падало, **Последняя ошибка**.

В таблице групп правил видно, сколько правил каждой группы и сколько очков они дают.

Есть два поля с путями:

| Поле | Что писать |
|---|---|
| **Папка установки Kerio Connect** | `C:\Program Files\Kerio\MailServer` |
| **Папка правил SpamAssassin** | Заполняется сама: `<Kerio>\plugins\spamassassin\rules`. Менять только если Kerio установлен нестандартно |

Если Kerio не найден, впишите путь вручную или нажмите **🪄 Определить автоматически** / **📁 Выбрать папку Kerio…**.

### 9.5 Установка: 3 шага

**Шаг 1. 🔎 Проверить обновления на GitHub**

Программа скачивает `manifest.json` и показывает:

- установленную версию и версию на GitHub;
- дату сборки и количество записей;
- **здоровье источников**: «Источники базы: 9 активны, 1 требуют ключа (urlhaus)», а также недоступные источники с причиной.

Если стоит актуальная версия — будет «✅ Установлена актуальная версия». Если нет — «🔔 Доступно обновление» и кнопки **👁 Проверить, что изменится** и **⬇️ Установить версию «…»**.

**Шаг 2. 👁 Предпросмотр установки (dry-run)**

Скачивает файл, проверяет **SHA-256** и показывает таблицу:

| Группа | Будет в базе | Сейчас | Очки |
|---|---|---|---|
| Домены отправителей | 7 446 | 0 (+7 446) | +3.2 |
| Фишинговые ссылки | 30 000 | 0 (+30 000) | +2.5 |
| … | … | … | … |

Плюс примеры новых правил и строка «Источники базы: …».

**Важно:** на этом шаге **в Kerio ещё ничего не записано**. Это «примерка».

**Шаг 3. ⬇️ Установить / Обновить базу в Kerio**

Нажмите **⬇️ Установить / Обновить базу в Kerio**. Программа спросит подтверждение («⚠️ Установка выполнится в папку Kerio…») — проверьте путь и нажмите **⬇️ Подтвердить установку**. Дальше программа:

1. скачивает файл и проверяет SHA-256;
2. находит папку `plugins\spamassassin\rules`;
3. сохраняет локальные списки (`certs\antispam\lists`) для проверки писем;
4. делает **резервную копию** предыдущей базы в `certs\antispam\backup`;
5. проверяет синтаксис правил (чтобы битый файл не попал в Kerio);
6. атомарно записывает `kerio-antispam.cf`;
7. читает файл обратно и сверяет SHA-256;
8. перезапускает службу `KerioMailServer` (если включена галочка).

Внизу — отчёт по шагам: что скачано, куда записано, создана ли копия, перезапущена ли служба.

### 9.6 Галочка «Перезапускать службу Kerio MailServer»

- ✅ **Включена** — правила начинают работать сразу. Почта недоступна 5–20 секунд.
- ⬜ **Выключена** — файл записан, но правила **не активны**, пока служба не перезапустится.

**Как применить без перезапуска:** Kerio WebAdmin → **Configuration → Content Filter → Spam Filter** → переключите любую галочку (например, SURBL) → **Apply**. Kerio перечитает правила SpamAssassin.

### 9.7 Автообновление

1. Выберите расписание: **каждые 6 часов**, **каждые 12 часов** (по умолчанию) или **раз в сутки (04:10)**.
2. Нажмите **✅ Включить автообновление**.
3. Создаётся задание Планировщика `KerioCertManager_AntiSpamDB`, которое запускает `KerioCertManager.exe --antispam-update`.
4. Кнопка **🚀 Проверить и обновить сейчас** — немедленный запуск.
5. **⏸ Выключить** — удалить задание.

Как это работает внутри: задача проверяет GitHub; если версия на GitHub новее — устанавливает, если такая же — пишет в журнал «актуальна» и ничего не трогает. Перезапуск службы делается только при реальном обновлении.

> ⚠️ Для создания задания нужны права администратора. Без них программа честно скажет: «запустите от имени Администратора».

### 9.8 Откат и удаление

- **⏪ Откатить** — берёт последнюю резервную копию из `certs\antispam\backup` и возвращает её в Kerio. Полезно, если новая база дала ложные срабатывания.
- **🗑 Удалить базу** — убирает `kerio-antispam.cf` из папки правил. Копия остаётся в резервных, так что можно вернуть.

### 9.9 Проверка письма (dry-run, без отправки)

Вставьте исходник письма в большое поле и нажмите **🔬 Проверить письмо по антиспам-базе**.

Что показать:

- **От кого**, домен отправителя;
- **сколько очков** набрало письмо;
- **какие правила сработали** (таблица: группа, совпадение, очки);
- вердикт:
  - ✅ «ЧИСТО» (< 3 очков),
  - ⚠️ «ВЕРОЯТНО СПАМ» (3–5),
  - 🚫 «СПАМ» (5+).

Кнопка **📋 Вставить пример** подставит демонстрационное фишинговое письмо — удобно проверить, что база вообще работает.

> 💡 Расчёт предварительный: Kerio добавляет к этим очкам свои (SPF/DKIM, DNSBL, байесовский фильтр). Точный итог смотрите в заголовке `X-Spam-Score` доставленного письма.

### 9.10 Где увидеть результат в Kerio

- В заголовках письма: `X-Spam-Status` содержит правила `KCM_*`, `X-Spam-Score` — итог.
- В Kerio WebAdmin: **Content Filter → Spam Filter** — общий порог срабатывания.
- В логах Kerio: `MailServer\logs\` — записи о spam score.

### 9.11 Если правила не применяются

| Симптом | Причина | Что делать |
|---|---|---|
| Файл установлен, но `KCM_*` в письмах нет | Служба не перезапускалась | Перезапустить `KerioMailServer` или переключить SURBL + Apply |
| «Не найден каталог SpamAssassin» | Путь другой, Kerio на другом сервере или нестандартная установка | Нажать **🔎 Что проверено** — программа покажет все проверенные пути и что делать (подробно — п. 9.16) |
| «Нет доступа к папке» | Нет прав | Запустить от имени администратора |
| «SHA-256 не совпала» | Файл подменён или скачался битым | Повторить установку; если повторяется — проверить прокси/антивирус |
| «Не удалось получить базу с GitHub» | Нет интернета / GitHub закрыт | Скачать `kerio-antispam.cf` вручную и использовать **импорт файла** (см. ниже) |
| Правила есть, но спама больше не стало | Порог Kerio слишком высокий | Content Filter → Spam Filter → снизить порог (например, до 5) |
| Слишком много ложных срабатываний | Агрессивная база / легитимный домен в списке | Откатить базу; добавить домен в `allowlist` через GitHub; удалить базу |

### 9.12 Импорт файла вручную (закрытый контур)

Если сервер вообще без доступа к GitHub:

1. На любом компьютере с интернетом откройте https://github.com/zigorminsk-debug/jiraHelp/releases/tag/antispam-db-latest
2. Скачайте файл **`kerio-antispam.cf`**.
3. Перенесите его на сервер.
4. В программе: скопируйте `kerio-antispam.cf` в папку `plugins\spamassassin\rules\` и перезапустите службу — **это всё, что нужно**. Либо используйте API импорта в программе, если он доступен в вашей сборке.

> 💡 Программа поддерживает и полностью ручную установку: один файл в одну папку. Ничего больше не меняется — ни `mailserver.cfg`, ни пользователи.

### 9.13 Как добавить свои домены в базу

Если у вас есть свой «чёрный список» (например, домены, которые атакуют именно вас):

Все списки лежат в папке `antispam-db/sources/` — по одному значению в строке:

| Файл | Что добавлять | Что даёт |
|---|---|---|
| `scam-domains.txt` | домены отправителей | +3.2 очка на письмах с этого домена в `From` |
| `scam-emails.txt` | полные адреса | +4.5 |
| `phishing-links.txt` | домены ссылок и лендингов | +2.5 |
| `scam-subjects.txt` | шаблоны тем | +1.8 |
| `scam-phrases-ru.txt` | фразы в теле письма | +1.5 |
| `threat-ips.txt` | IP и подсети ботнетов (/16, /24, /32) | +3.0 |
| `allowlist.txt` | доверенные домены | −6.0 (защита от ложных срабатываний) |

Порядок действий:

1. Форкните репозиторий на GitHub.
2. Добавьте строки в нужный файл из таблицы.
3. Отправьте pull request.
4. После принятия — база соберётся автоматически (в 03:17 UTC или вручную через Actions), и программа её подхватит.

Домены из белого списка (`sources/allowlist.txt`) никогда не попадут в чёрный — это защита от ошибок.

### 9.14 Про URLhaus и «🔑 нужен ключ»

abuse.ch 21 октября 2026 закрыл бесплатные выгрузки без ключа (`410 Gone`). Официальный путь — личный **Auth-Key** (бесплатный, только некоммерческое использование).

Чтобы включить:

1. Зарегистрируйтесь на abuse.ch и получите Auth-Key.
2. В репозитории GitHub: **Settings → Secrets and variables → Actions → New repository secret**.
3. Имя: `ABUSECH_AUTH_KEY`, значение: ваш ключ.
4. Следующая сборка базы подхватит его автоматически.

Без ключа всё остальное работает: база собирается из 9 источников, URLhaus просто помечается как «требует ключа».

### 9.15 Если источник «0 записей»

Программа честно показывает ошибку источника: «HTML/анти-бот страница», «HTTP 404», «HTTP 410». Это значит, что владелец фида изменил адрес или закрыл доступ. База при этом **не ломается** — собирается из остальных источников. Такие случаи исправляются в репозитории (замена адреса фида).

### 9.16 «Не найден каталог SpamAssassin Kerio Connect» — что делать

Это сообщение означает ровно одно: программа не нашла **папку**, в которую кладут правила. Причин всего четыре, и для каждой есть готовое действие.

**Шаг 1. Нажмите «🔎 Что проверено»**

Кнопка находится на вкладке **Антиспам**, рядом с кнопками определения папок. Она показывает:

- какие пути проверены и что в них есть (папка есть / папки нет / есть `plugins`, но нет `spamassassin`);
- какая служба Kerio найдена и с какой командой запуска;
- есть ли права администратора;
- что делать дальше — списком, под вашу конкретную ситуацию.

Ниже в отчёте есть кнопки **«⤵ Подставить папку Kerio»** и **«⤵ Подставить папку правил»** — они заполняют поля автоматически, чтобы не переписывать длинный путь руками.

**Шаг 2. Понять, какой у вас случай**

| Что показывает отчёт | Что это значит | Что делать |
|---|---|---|
| **«Папка Kerio найдена, но папки правил внутри нет»** | Kerio установлен, но подпапка с правилами называется иначе или ещё не создана | Открыть папку установки Kerio → `plugins` и посмотреть имя папки (см. таблицу путей ниже), вписать путь в поле **«Папка правил SpamAssassin»** |
| **«Ни один путь не существует»** | Kerio стоит **на другом компьютере** (это самая частая причина) | Ставить базу нужно **на самом сервере**: либо скопировать программу туда, либо указать сетевой путь (см. ниже) |
| **«Программа запущена не на Windows»** | Программа открыта на Linux/macOS-машине | Скопировать файл на сервер вручную (см. «Kerio на Linux») |
| **«Без прав администратора»** | Windows не даёт писать в `C:\Program Files` | Закрыть программу → правый клик по `KerioCertManager.exe` → **«Запуск от имени администратора»** |

**Шаг 3. Где на самом деле лежат правила SpamAssassin**

Папка зависит от версии и разрядности Kerio — проверьте по порядку:

| Платформа | Типичный путь к правилам |
|---|---|
| Windows, 64-бит | `C:\Program Files\Kerio\MailServer\plugins\spamassassin\rules` |
| Windows, 32-бит Kerio на 64-битной ОС | `C:\Program Files (x86)\Kerio\MailServer\plugins\spamassassin\rules` |
| Windows, Kerio Connect 8+ (часто) | `C:\Program Files (x86)\Kerio\MailServer\plugins\spamserver\spamassassin\rules` |
| Нестандартный диск | `D:\Kerio\MailServer\plugins\spamassassin\rules` (или `E:\…`) |
| Linux | `/opt/kerio/mailserver/plugins/spamassassin/rules` (реже `/usr/local/kerio/mailserver/plugins/…`) |
| Docker / контейнер | внутри контейнера — `<каталог данных>/plugins/spamassassin/rules` |

> 💡 Проще всего не угадывать, а открыть в Проводнике папку `plugins` внутри установленного Kerio: искомая папка называется **`spamassassin`** (иногда лежит внутри `spamserver`). Внутри неё — подпапка `rules`, а в ней файлы `*.cf`. Именно этот путь и нужно вписать.

**Шаг 4. Если Kerio на другом сервере (Windows): сетевой путь**

Поле **«Папка правил SpamAssassin»** понимает сетевые пути (UNC). Пример:

```
\\SERVER-KERIO\c$\Program Files\Kerio\MailServer\plugins\spamassassin\rules
```

или через общую папку:

```
\\SERVER-KERIO\KerioRules
```

Требования: на том сервере у вашей учётной записи должны быть права администратора, а общий доступ (`c$` или созданная папка) — открыт. После ввода пути нажмите **«👁 Предпросмотр установки»**: программа покажет, куда именно будет записан файл.

**Шаг 5. Если Kerio на Linux**

Программа работает в Windows, поэтому файл нужно просто перенести:

1. Нажмите **«⬇ Скачать .cf»** на вкладке «Антиспам» — сохранится `kerio-antispam.cf` (это тот же файл, что ставится автоматически; рядом лежит инструкция).
2. Скопируйте его на сервер: `scp kerio-antispam.cf root@mail.company.by:/opt/kerio/mailserver/plugins/spamassassin/rules/`
3. Перезапустите Kerio: `systemctl restart kerio-connect` (в старых сборках — `/etc/init.d/kerio-connect restart`).
4. Проверьте, что файл на месте: `ls -l /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf`

Дальше Kerio сам применяет правила: отдельной «установки» не требуется.

**Шаг 6. Если папки `rules` нет вообще**

Так бывает на свежих установках: папка `spamassassin` есть, а `rules` внутри ещё не создана. Ничего вручную создавать не нужно — впишите в поле «Папка правил SpamAssassin» путь до `…\spamassassin` и нажмите «Установить»: программа создаст `rules` сама, ровно в нужном месте дерева Kerio.

**Шаг 7. Проверка после установки**

1. В отчёте установки должен быть путь вида `…\plugins\spamassassin\rules\kerio-antispam.cf` и строка «SHA-256 подтверждён».
2. Перезапустите службу (галочка в программе или `services.msc` → `KerioMailServer` → «Перезапустить»).
3. Отправьте себе тестовое письмо — в его заголовках появится `X-Spam-Status` со счётчиком `KCM_*` (см. п. 9.9 и 9.10).

> ⚠️ **Чего делать не нужно:** создавать папки «наугад» в других местах, копировать файл в `C:\Program Files\Kerio\MailServer` без подпапки `plugins\…\rules` и править `mailserver.cfg`. Kerio читает правила только из своей папки `rules` — в остальных местах файл просто лежит и ни на что не влияет.

> 💡 **Почему поиск теперь надёжнее.** Программа определяет путь по цепочке: ваш ручной ввод → команда запуска службы `KerioMailServer` (реестр и `sc qc`) → значения реестра Kerio → стандартные каталоги на всех дисках → обход дерева Kerio с поиском папки `spamassassin` или файлов `*.cf`. Поэтому нестандартный диск, 32-битная установка и папка `spamserver` больше не «ломают» установку.

### 9.17 Включение и управление базой из Kerio WebAdmin

> ⚠️ **Главное, что нужно понять сразу.** База KCM — это **не отдельный модуль Kerio** и не галочка в его интерфейсе. Это файл правил `kerio-antispam.cf` для встроенного SpamAssassin. В Kerio такой галочки нет и не будет: «включение» = файл лежит в папке правил + служба перезапущена + **сам спам-фильтр Kerio включён**. Управлять базой (обновлять, откатывать, удалять) нужно из программы, а из Kerio — настраивать, **как её очки влияют на письма**.

#### Шаг 1. Включить сам спам-фильтр (это обязательный выключатель)

Судя по вашему скриншоту, галочка **«Включить оценку пригодности сообщений к спаму»** не отмечена — а без неё SpamAssassin (и вместе с ним наша база) **не считает очки вообще**, письма проходят без проверки.

1. Откройте `https://<IP-сервера>:4040/admin/` → в дереве слева **Конфигурация → Спам-фильтр → Фильтр спама**.
2. Вкладка **«Оценка пригодности сообщений к спаму»** (она у вас открыта).
3. Поставьте галочку **«Включить оценку пригодности сообщений к спаму»**.
4. При необходимости — **«Включить оценку сообщений, отправленных с доверенных агентов ретрансляции…»** (только если через Kerio шлют письма ваши же сервисы).
5. Нажмите **«Сохранить»** (кнопка внизу страницы, за пределами видимой области на скриншоте).

#### Шаг 2. Убедиться, что файл базы на месте

В программе: вкладка **Антиспам** → кнопка **«🔎 Что проверено»**. В отчёте должно быть:

```
✅ Каталог правил найден: …\plugins\spamassassin\rules
```

и в статусе — «База установлена, версия …». Если файла нет — установите базу кнопкой **«⬇️ Установить / Обновить базу в Kerio»** (см. п. 9.5 и 9.16, если путь не находится).

Проверить вручную на сервере можно так: в папке правил должен лежать **`kerio-antispam.cf`** (1 МБ, начинается с комментариев `# KCM`). ⚠️ Kerio читает **только** файлы из своей папки `plugins\spamassassin\rules`: если положить `.cf` в корень установки или в `plugins`, он просто будет лежать и ни на что не влиять.

#### Шаг 3. Перезапустить службу (Kerio не перечитывает правила на лету)

1. В WebAdmin: **Службы** (в дереве слева, самый верх) → выберите **Kerio Connect Engine** → **«Остановить»**, через 2–3 секунды **«Запустить»**.
   Либо на сервере Windows: `services.msc` → **KerioMailServer** → «Перезапустить».
   Либо из программы: на вкладке «Антиспам» включите галочку **«Перезапускать службу Kerio MailServer»** — она сделает это автоматически после установки.
2. Почта недоступна 5–15 секунд — это нормально, предупредите пользователей.

#### Шаг 4. Настроить, как очки базы влияют на письма

На той же странице, блок **«Ограничения оценки пригодности сообщений к спаму»**:

| Поле на экране | Что означает | Как подобрать с базой KCM |
|---|---|---|
| **Показатель маркировки** (у вас `6`) | при каком количестве очков Kerio пометит письмо как спам | оставьте 5–6. Правила базы дают 1.5–4.5 очка за признак, они складываются с очками Kerio Anti-spam, SPF и DNSBL — одного совпадения обычно недостаточно, это и нужно (меньше ложных срабатываний) |
| **Показатель блокировки** (у вас `6`) | при каком количестве очков письмо считается спамом | ⚠️ **не ставьте 6**: одно-два правила KCM + чужой SPF уже дадут 6, и вы начнёте терять нормальную почту. Рекомендуется **10–15** |
| **«Добавить префикс в тему»** + `**SPAM**` | помечает письмо в списке | включите — пользователи сразу увидят и смогут настроить папку |
| **«Возвращать сообщение отправителю»** | отказ на SMTP | включать не советуем: на легитимные письма вы ответите отказом |
| **«Переадресовать сообщение на адрес карантинной зоны»** (у вас `admin@niz.by`) | складывает заблокированное в ящик | хороший вариант: письма не теряются, их можно разобрать и при необходимости ослабить порог |

Логика простая: **чем ниже порог — тем агрессивнее фильтр**. База KCM добавляет очки, а порог решает, что с ними сделать.

#### Шаг 5. Что можно и чего нельзя управлять из Kerio

| Действие | Где | Комментарий |
|---|---|---|
| **Включить / выключить весь спам-фильтр** | Конфигурация → Фильтр спама → «Оценка пригодности…» → верхняя галочка | выключает и Kerio Anti-spam, и базу KCM |
| **Изменить пороги маркировки/блокировки** | там же, блок «Ограничения» | самый простой способ «сделать базу мягче/жёстче» |
| **Карантин, префикс темы** | там же, блоки «Действие по достижении показателя…» | письма сохраняются, их видно |
| **Белый список отправителей** (обходят и базу KCM) | вкладка **«Черные списки»** — в Kerio это список исключений: адреса и домены, которые **не** проверяются | добавьте туда банки, рассылки, 1С-сервисы, если они ложно срабатывают |
| **Свои правила с очками** (+/− очки за условие) | вкладка **«Пользовательские правила»** | например, «письма с этого домена: −5 очков» или «тема содержит X: +3» |
| **Маршрутизация по результату** | Конфигурация → **Фильтры сообщений** | правило «заголовок `X-Spam-Status` содержит `KCM_`» → переместить в папку «Спам» / переслать / удалить |
| **Обновить / откатить / удалить базу** | ❌ **в Kerio нельзя** — только в программе (кнопки «Установить», «Откатить», «Удалить базу») | в Kerio нет интерфейса для содержимого `.cf` |
| **Посмотреть отдельные правила базы (KCM_…)** | ❌ в Kerio нельзя | их видно в заголовках письма и в логах; список — в программе, блок «Группы правил» и в файле `kerio-antispam.cf` |

> 💡 **Как «выключить базу», не трогая остальной антиспам.** Три способа, от простого к полному:
> 1. Кнопка **🗑 Удалить базу** в программе (файл уходит в резервные копии, Kerio перезапускается).
> 2. Переименовать файл на сервере: `kerio-antispam.cf` → `kerio-antispam.cf.disabled`, перезапустить службу. Kerio читает только `*.cf`.
> 3. Поднять «Показатель блокировки» до 15–20 и «Показатель маркировки» до 10 — база останется, но её очки почти не будут ничего менять.

#### Шаг 6. Проверить, что база реально работает

1. Отправьте себе тестовое письмо с «подозрительным» содержимым (или перешлите старое спам-письмо) на ящик в Kerio.
2. Откройте письмо в **Kerio WebMail** → меню письма → **«Показать исходное сообщение»** / «Показать оригинал» (в Outlook — «Свойства → Заголовки Интернета», в Thunderbird — `Ctrl+U`).
3. Найдите строку **`X-Spam-Status`**. Если база работает, в ней будут метки **`KCM_…`**:
   ```
   X-Spam-Status: Yes, hits=7.4 required=6.0 tests=KCM_SPAM_FROM_DOMAIN_001,KCM_PHISH_URL…
   ```
   Расшифровка: `hits=` — сколько очков набрало письмо, `required=` — ваш «Показатель блокировки», `tests=` — какие правила сработали (в том числе `KCM_*` из базы).
4. Если `KCM_` нет вообще — проверьте по порядку: галочка в шаге 1, файл на месте (шаг 2), служба перезапущена (шаг 3). Ещё вариант — письмо попало под белый список (вкладка «Черные списки»).
5. Журнал: **Журналы → Почта** (или файл `logs/mail/…` на сервере) — там у каждого письма виден spam score.

> 💡 **Пользовательские настройки.** Каждый пользователь может в Kerio WebMail (Настройки → Правила) сделать правило «если `X-Spam-Status` содержит `KCM_` → переместить в папку Спам» — база при этом остаётся общей, меняется только раскладка писем у него.

#### Шаг 7. После обновления Kerio Connect

Обновление Kerio обычно сохраняет `plugins\spamassassin\rules`, но **переустановка «с нуля»** может пересоздать папку. После любого апгрейда Kerio откройте программу → «🔎 Что проверено»: если версия базы пропала, нажмите «⬇️ Установить / Обновить базу в Kerio». Проверка занимает 5 секунд.

### 9.18 Куда именно класть антиспам-базу на Linux

Это самый частый вопрос: «файл скачал, а куда его положить?». Ответ короткий — в каталог **правил SpamAssassin**, который находится внутри каталога Kerio Connect.

**Основной путь (99 % установок):**

```
/opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
```

**Если такого каталога нет** (старые сборки Kerio 8–9):

```
/opt/kerio/mailserver/plugins/spamserver/spamassassin/rules/kerio-antispam.cf
```

Если Kerio ставили не в `/opt`, смотрите `/usr/local/kerio/mailserver/...` — программа проверяет оба варианта автоматически.

**Как убедиться, что вы нашли правильное место**

Выполните на сервере от root:

```bash
ls -la /opt/kerio/mailserver/plugins/spamassassin/rules | head -30
```

В этой папке уже лежат штатные файлы Kerio (`*.cf`, `*.cf.new`, иногда `user_prefs`). Если папка пустая — перепутали путь. Быстрая проверка «где вообще лежат правила»:

```bash
find /opt /usr/local -type d -path "*spamassassin/rules" 2>/dev/null
```

#### Права и владелец — самое важное

Kerio Connect на Linux работает **не от root**, а от пользователя `kerio` (иногда `kerio-connect`). Поэтому:

```bash
# владелец файла и папки
chown kerio:kerio /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
chown kerio:kerio /opt/kerio/mailserver/plugins/spamassassin/rules

# права: файл читают все служебные процессы Kerio → 644, каталог → 755
chmod 644 /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
chmod 755 /opt/kerio/mailserver/plugins/spamassassin/rules
```

| Права | Почему так | Что будет при других |
|---|---|---|
| файл `644` (`-rw-r--r--`) | Kerio читает его под своим пользователем | `600` — Kerio не увидит файл, правило «молча не работает» |
| каталог `755` (`drwxr-xr-x`) | нужно право «войти» в каталог | `700` — чтение изнутри запрещено для не-владельца |
| владелец `kerio:kerio` | так живут все штатные файлы Kerio | `root:root` при `644` тоже работает, но при обновлении Kerio права могут сброситься |

Проверить, от кого работает сервер:

```bash
ps -o user,cmd -C mailserver
# или
systemctl show kerio-connect -p User
```

💡 **Про `sudo -u`.** Класть файл нужно **от root** (только root может писать в `/opt/kerio`), а вот проверять чтение полезно «глазами Kerio»:

```bash
sudo -u kerio head -5 /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
```

Если команда выполнилась и показала `# KCM ...` — Kerio файл увидит. Если ответ «Permission denied» — вернитесь к `chown`/`chmod` выше.

#### SELinux (Red Hat / Alma / Rocky / CentOS)

При включённом SELinux файл, скопированный «вручную», получает неверную метку и не читается. Признак: права в порядке, а правила не работают, в `/var/log/audit/audit.log` есть `denied` для `mailserver`.

```bash
getenforce                            # Enforcing?
ls -Z /opt/kerio/mailserver/plugins/spamassassin/rules | head
restorecon -Rv /opt/kerio/mailserver/plugins/spamassassin/rules
```

Если `restorecon` не помог (Kerio стоит вне стандартных путей), скопируйте метку с соседнего штатного файла:

```bash
chcon --reference=/opt/kerio/mailserver/plugins/spamassassin/rules/*.cf       /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
```

Крайний вариант (только на время диагностики) — `setenforce 0`, проверить, заработало ли, и **вернуть** `setenforce 1`.

#### Kerio Connect в Docker

Если Kerio запущен в контейнере, файл надо класть **внутрь контейнера** (или в смонтированный том — тогда на хосте, в каталоге тома):

```bash
docker ps --format '{{.Names}}	{{.Image}}' | grep -i kerio
docker cp kerio-antispam.cf <контейнер>:/opt/kerio/mailserver/plugins/spamassassin/rules/
docker exec -u root <контейнер> chown kerio:kerio /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
docker exec -u root <контейнер> chmod 644 /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
docker restart <контейнер>
```

⚠️ `docker cp` живёт до пересоздания контейнера. Для постоянного хранения положите файл в том, который смонтирован в `/opt/kerio` (посмотрите `docker inspect <контейнер> | grep -A3 Mounts`).

#### Перезапуск и проверка

Правила `.cf` читаются **при старте** SpamAssassin, поэтому после установки:

```bash
systemctl restart kerio-connect     # или: /etc/init.d/kerio-connect restart
systemctl is-active kerio-connect   # ждём: active
```

Проверка «правило реально работает»: отправьте себе тестовое письмо с явно спамным содержимым и откройте в Kerio WebAdmin **исходное сообщение** — в заголовках должна появиться строка вида:

```
X-Spam-Status: Yes, hits=7.4 required=6.0 tests=KCM_SPAM_FROM_DOMAIN,KCM_PHISH_URL
```

Если `X-Spam-Status` есть, но без `KCM_…` — файл на месте, но не прочитан: вернитесь к правам/SELinux и перезапустите службу ещё раз.

#### Как это сделать, не заходя на сервер

Вкладка **🧰 Инструменты** → карточка **🐧 Kerio Connect на Linux**. Укажите адрес, логин и пароль (или ключ), нажмите **🛡 Установить антиспам-базу** — программа сама найдёт каталог, загрузит файл, сверит SHA-256 **на сервере**, выставит права и перезапустит службу. Подробно — [раздел 20](#20-kerio-connect-на-linux).

Если SSH недоступен: кнопка **📥 Скачать shell-скрипт** отдаёт `install-kcm-antispam.sh`, который делает всё то же самое на сервере одной командой `sudo sh install-kcm-antispam.sh`.

#### Автообновление базы на Linux (cron)

Из программы (нужен root на сервере): вкладка «Антиспам» → **✅ Включить автообновление**. Будет создан файл `/etc/cron.d/kerio-cert-manager-antispam`:

```
10 4 * * * root /opt/kerio-cert-manager/KerioCertManager --antispam-update >/dev/null 2>&1
```

Вручную то же самое:

```bash
sudo /opt/kerio-cert-manager/KerioCertManager --antispam-update
```

#### Откат

Каждая установка сохраняет предыдущую версию рядом с файлом (`kerio-antispam.cf.backup-YYYYMMDD-HHMMSS`) — вернуть можно так:

```bash
ls /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf.backup-*
sudo cp -p /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf.backup-20261024-041000            /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf
sudo systemctl restart kerio-connect
```

## 10. Вкладка 8 — Инструменты админа

### 10.1 Анализатор заголовков письма (RFC-822)

**Зачем:** понять, почему письмо шло 40 минут или попало в спам.

1. Откройте проблемное письмо в Outlook/Thunderbird/WebMail → «Свойства» / «Показать оригинал» / `View Source`.
2. Скопируйте **все служебные заголовки** (начиная с `Return-Path`/`Received`).
3. Вставьте в поле и нажмите **🔬 Разобрать маршрут письма, задержки и заголовки антиспама**.

Программа покажет:

- все узлы (`Received`) по порядку — от отправителя к получателю;
- сколько времени письмо провело на каждом узле;
- **какой узел виноват в задержке**;
- результаты `SPF / DKIM / DMARC`;
- `SpamScore` и признаки спама.

### 10.2 Конструктор DNS-зоны

**Зачем:** собрать правильные DNS-записи для почты без ошибок.

1. Укажите **почтовый домен**, **хост почтового сервера**, **внешний белый IPv4** и, если нужно, **доп. IP веб-сайта/CRM** (когда формы на сайте шлют письма с другого хостинга).
2. Выберите **режим строгости SPF**: `~all` (SoftFail — рекомендуется) или `-all` (HardFail — жёстко отклонять чужих).
3. Выберите **политику DMARC**: `p=quarantine` (в «Спам» — оптимально), `p=reject` (полная блокировка подделок) или `p=none` (мягкий мониторинг отчётов).
4. Отметьте галочками сервисы, которым разрешено отправлять письма от вашего домена (рядом показана «цена» в DNS-запросах):
   - **Kerio Connect** (MX + `mail.хост`) — +2 запроса, плюс прямой `ip4` (0 запросов);
   - **Битрикс24 CRM** — `include:spf.bitrix24.com` (~2);
   - **Яндекс 360 для бизнеса** — `include:_spf.yandex.net` (+1);
   - **VK WorkSpace / Mail.ru Бизнес** — `include:_spf.mail.ru` (+1);
   - **Google Workspace** — `include:_spf.google.com` (+4);
   - **Microsoft 365 / Exchange Online** — `spf.protection.outlook.com` (+2);
   - **UniSender** — `include:spf.unisender.com` (+2);
   - **SendPulse** — `include:mx.sendpulse.com` (+2).
5. Программа соберёт `A`, `MX`, `SPF` (с контролем лимита **не более 10 DNS-запросов**, RFC 7208), `DKIM` (куда вставить открытый ключ из Kerio), `DMARC`, `autodiscover`, `CAA`, `TLS-RPT` и предупредит, если сумма запросов превышает лимит.
6. **💾 Скачать готовый пакет DNS-записей (.txt)** — файл, по которому можно вносить записи в панель регистратора.

> ⚠️ SPF должен быть **один** на домен. Если записей две — часть получателей проигнорирует обе.

| `certs\antispam\backup\` | Резервные копии предыдущих версий базы |
| `C:\Program Files\Kerio\MailServer\plugins\spamassassin\rules\kerio-antispam.cf` | Установленная база в Kerio |
| `C:\Program Files\Kerio\MailServer\sslcert\` | Сертификаты, которые использует Kerio |

## 14. Частые проблемы и решения

| Проблема | Что делать |
|---|---|
| **Windows не запускает exe** («SmartScreen») | «Подробнее» → «Выполнить в любом случае». Либо ПКМ по файлу → Свойства → «Разблокировать» |
| **Окно пустое / белое** | Установить «Microsoft Edge WebView2 Runtime»; либо запустить с `--server-only` и открыть адрес из консоли в браузере |
| **Программа не открывается совсем** | Проверить, что антивирус не заблокировал; запустить от имени администратора; посмотреть, не занят ли порт 17840 |
| **«Недостаточно прав» при установке в Kerio** | Запустить от имени администратора Windows |
| **Порт 80 занят Kerio** | Использовать DNS-01, TLS-ALPN-01 или включить авто-остановку службы |
| **Let's Encrypt: «too many certificates»** | Подождать или потренироваться в **Staging** |
| **DNS-запись «не найдена»** | Подождать 15–60 минут (кэш DNS), проверить в публичном DNS кнопкой проверки |
| **Kerio не подключается по 4040** | Открыть `https://IP:4040/admin/` в браузере; проверить VPN/файрвол; нажать «🩺 Диагностика подключения» |
| **Kerio не принимает сертификат** | Использовать файловый метод; перевыпустить в режиме «Локальный (Kerio)» |
| **Kerio Connect 10: SSL-раздел открывается, права есть, а добавление сертификата падает** | Это не права, а другой интерфейс API: нажмите **🧪 Проверить API сертификатов**, затем повторите установку — программа выберет рабочий интерфейс. Подробно — §4.6.2 |
| **«Перезапустить службу»: ромбики, `NET HELPMSG`, `exit status 2`** | Так было до v4.9.1. Обновите программу: теперь сообщения читаемые, имя службы определяется автоматически, а при нехватке прав пишется «Нужны права администратора» |
| **Письма не уходят** | Проверить порт 25 у провайдера (часто закрыт), SMTP-тест в программе, PTR |
| **Письма в спаме у получателей** | SPF/DKIM/DMARC + PTR + RBL (вкладка «Проверка почты»), затем Delist Center |
| **`550 5.7.1 S3150` от Microsoft** | Вкладка «Выход из блэклистов» → пакет Microsoft (sender.office.com + olcsupport) |
| **Домен не виден за границей** | Вкладка «Санкции» → блок «Видимость DNS из США и Европы» |
| **Антиспам-база не ставится** | Проверить путь Kerio, права администратора, интернет/GitHub |
| **Антиспам-база не действует** | Перезапустить `KerioMailServer` или переключить SURBL + Apply |
| **После базы слишком много спама в карантине/ложных** | Снизить/повысить порог спама в Kerio, откатить базу, добавить домены в allowlist |
| **Автопродление не сработало** | Проверить задание в `taskschd.msc`; сервер должен быть включён; проверить, что exe лежит по тому же пути |
| **Антивирус ругается на exe** | Это ложное срабатывание (Go-бинарник без подписи). Добавить в исключения; собрать самому из исходников при недоверии |
| **Забыл пароль администратора Kerio** | Программа его не хранит. Сброс — через Kerio WebAdmin/службу, не через программу |
| **Кириллический домен не принимается** | Программа сама переводит в Punycode; убедитесь, что в DNS создана запись для `xn--...` |
| **Баннер обновления не появляется** | Проверка выключена, прошло меньше 6 часов или нет доступа к GitHub → «🧰 Инструменты → 🔍 Проверить сейчас» |
| **Обновление не может заменить файл** | Программа в `Program Files`, запущена без прав администратора → закройте и запустите от имени Администратора |
| **SSH: `Permission denied (publickey,password)`** | Неверный логин/ключ или вход закрыт → см. 20.4 и 20.9 |
| **SSH: `sudo: a terminal is required`** | Входите под `root` или настройте `NOPASSWD` → см. 20.9 |
| **Linux: база установлена, но нет `KCM_…`** | Права/SELinux/не перезапустили службу → см. 9.18 |

## 15. Безопасность и приватность

- **Никакой телеметрии.** Программа не отправляет «статистику» и не звонит домой.
- **Что уходит в интернет:** DNS-запросы (проверка доменов), запросы к Let's Encrypt, запросы к GitHub (база), запросы к RBL-спискам (проверка репутации IP), запросы к вашим почтовым портам.
- **Что остаётся локально:** сертификаты, настройки, история проверок, база, резервные копии.
- **Пароли в память, не на диск.** Пароль Kerio и почтового ящика не сохраняются в файлах.
- **Порт интерфейса** — только `127.0.0.1` (этот компьютер). Снаружи он недоступен.
- **Порт 4040** — только через VPN/локальную сеть. Никогда не публикуйте его в интернет.
- **Целостность базы** — каждый файл проверяется по SHA-256 перед установкой: подменённый файл не попадёт в Kerio.
- **Права:** запускайте от администратора только когда это нужно; читать отчёты можно и без него.

3. ⬜ Исправить 🔴 критическое: MX/A, PTR, порт 25, Open Relay, опасные порты.
4. ⬜ Вкладка **Инструменты → Конструктор DNS**: собрать A, MX, SPF, DMARC, autodiscover, CAA → внести в панель DNS.
5. ⬜ В Kerio WebAdmin включить DKIM, скопировать открытый ключ → добавить TXT-запись.
6. ⬜ Подождать 15–60 минут, снова **Проверить почту** — оценка должна вырасти.
7. ⬜ Вкладка **Выпуск сертификата**: домен + SAN, режим **LE Staging** (тренировка) → выпустить.
8. ⬜ Если Staging прошёл — переключить на **Let's Encrypt** → выпустить боевой.
9. ⬜ Вкладка **Установка в Kerio**: файловый метод или Admin API → установить.
10. ⬜ Открыть `https://mail.домен` — замочек зелёный; в WebAdmin проверить даты сертификата.
11. ⬜ Вкладка **Сертификаты**: включить **автопродление** (03:15 или 12 ч).
12. ⬜ Вкладка **Антиспам-база**: «Проверить обновления» → «Предпросмотр» → «Установить».
13. ⬜ Проверить письмо в dry-run, убедиться, что правила `KCM_*` появляются в `X-Spam-Status`.
14. ⬜ Включить **автообновление базы** (12 ч).
15. ⬜ Отправить тестовое письмо на Gmail/Mail.ru/Outlook — проверить доставку и отсутствие спама.

## 17. Словарик

| Термин | Простыми словами |
|---|---|
| **SSL/TLS-сертификат** | Электронный «паспорт» сервера. Доказывает, что вы — это вы, и включает шифрование |
| **CA (центр сертификации)** | Организация, которая выдаёт паспорта и проверяет документы (Let's Encrypt, DigiCert…) |
| **Let's Encrypt** | Бесплатный CA, который выдаёт сертификаты автоматически |
| **ACME** | Протокол, по которому программа общается с Let's Encrypt |
| **DNS** | Телефонная книга интернета: домен → IP |
| **A-запись** | «Домен живёт по такому-то IP» |
| **AAAA-запись** | То же для IPv6 |
| **MX** | «Кто принимает почту для домена» |
| **TXT-запись** | Свободный текст в DNS — так хранят SPF, DKIM, DMARC, подтверждения |
| **PTR** | Обратная запись: «этот IP принадлежит такому-то имени» |
| **SPF** | Список серверов, которым разрешено отправлять от вашего домена |
| **DKIM** | Цифровая подпись письма |
| **DMARC** | Правило «что делать, если SPF/DKIM не совпали» |
| **RBL/DNSBL** | Чёрные списки IP-адресов |
| **DBL** | Чёрный список доменов |
| **Open Relay** | Открытый почтовый сервер, через который может писать кто угодно — серьёзная уязвимость |
| **NAT** | Когда много устройств выходят в интернет через один IP (роутер) |
| **Порт** | «Дверь» сервера. 80 — сайт, 443 — сайт с шифрованием, 25 — почта, 4040 — админка Kerio |
| **Firewall** | Программа/устройство, которое закрывает «двери» |
| **Split-DNS** | Когда внутри сети домен ведёт на внутренний IP, а снаружи — на внешний |
| **Punycode** | Способ записать кириллический домен латиницей (`xn--...`) |
| **SHA-256** | «Отпечаток пальца» файла для проверки целостности |
| **SpamAssassin** | Антиспам-движок, который Kerio использует внутри. Правила `.cf` — его «мозги» |
| **Рабочая станция / сервер** | Ваш компьютер / машина, где стоит Kerio |

## 20. Kerio Connect на Linux

Раньше программа была «только для Windows»: она искала Kerio в `C:\Program Files\Kerio\MailServer` и перезапускала службу через `sc`. Но **большинство установок Kerio Connect в мире — Linux**, и админ часто сидит за Windows. В версии 4.6.0 это исправлено двумя способами.

### 20.1 Два способа «дружить» с Linux

| Способ | Когда подходит | Что нужно |
|---|---|---|
| **A. Программа на Windows → Kerio на Linux по SSH** | Рабочее место админа — Windows, сервер — Linux | Доступ по SSH (порт 22) с машины админа до сервера |
| **B. Программа прямо на Linux-сервере** | Сервер без Windows рядом, или хочется всё в одном месте | Сборка под Linux, запуск с `--server-only` |

Оба способа работают с теми же каталогами Kerio и той же службой `kerio-connect` — разница только в том, где запущена программа.

### 20.2 Где Kerio Connect живёт на Linux

| Что | Путь по умолчанию | Как проверить |
|---|---|---|
| Каталог установки | `/opt/kerio/mailserver` | `ls -la /opt/kerio/mailserver` |
| Альтернатива | `/usr/local/kerio/mailserver` | `ls -la /usr/local/kerio/mailserver` |
| Бинарник сервера | `/opt/kerio/mailserver/mailserver` | `ps -o user,cmd -C mailserver` |
| Правила SpamAssassin | `/opt/kerio/mailserver/plugins/spamassassin/rules` | `ls` — там лежат `*.cf` |
| Альтернатива (старые сборки) | `.../plugins/spamserver/spamassassin/rules` | `find /opt -type d -path "*spamassassin/rules"` |
| Сертификаты SSL | `/opt/kerio/mailserver/sslcert` | `ls -la .../sslcert` |
| Конфигурация | `/opt/kerio/mailserver/mailserver.cfg` | `grep -i ssl .../mailserver.cfg` |
| Логи | `/opt/kerio/mailserver/store/logs` (и `syslog`) | `tail -f /var/log/messages` |
| Служба systemd | `kerio-connect.service` | `systemctl status kerio-connect` |
| Служба init.d | `/etc/init.d/kerio-connect` | `ls -la /etc/init.d/kerio*` |

💡 На некоторых сборках служба называется `kerio` или `keriomailserver` — программа проверяет все три имени.

### 20.3 Управление службой

```bash
systemctl status kerio-connect      # состояние
sudo systemctl restart kerio-connect  # перезапуск (после новых правил/сертификата)
sudo systemctl stop kerio-connect     # остановка (на время ручной замены sslcert)
sudo systemctl start kerio-connect    # запуск
journalctl -u kerio-connect -n 100 --no-pager   # последние 100 строк лога
```

Если systemd нет (старый дистрибутив, OpenVZ-контейнер):

```bash
sudo /etc/init.d/kerio-connect restart
sudo service kerio-connect restart
```

⚠️ **Не убивайте процесс через `kill -9`.** Kerio держит состояние в памяти; жёсткое убийство может потребовать переиндексации почтовых ящиков.

### 20.4 Вариант A: управление по SSH из Windows

Откройте вкладку **🧰 Инструменты** → карточка **🐧 Kerio Connect на Linux**.

**Шаг 1. Заполнить подключение.** Сервер (IP или имя), порт (по умолчанию 22), пользователь (`root` или ваш админский), пароль **или** путь к приватному ключу. Пароль нигде не сохраняется — он живёт в памяти только на время операции.

**Шаг 2. Нажать «🔍 Проверить сервер».** Программа подключится и покажет:

- версию ОС и ядра;
- каталог Kerio и каталог правил SpamAssassin (найденные автоматически);
- имя службы и её состояние (`active` / `inactive`);
- установлена ли уже база и какого размера;
- отпечаток ключа сервера (SHA256) — при следующем подключении программа сравнит его и предупредит, если сервер подменили.

**Шаг 3. Нажать «🛡 Установить антиспам-базу».** Что произойдёт на сервере:

1. файл `kerio-antispam.cf` будет загружен в каталог правил;
2. рядом сохранится резервная копия предыдущей версии;
3. SHA-256 будет посчитан **на сервере** и сверен с локальным (защита от «битой» передачи);
4. права выставляются автоматически (`644`, владелец `kerio:kerio`);
5. служба `kerio-connect` перезапускается.

**Шаг 4. Проверить результат.** В журнале карточки будет строка вида:

```
Файл загружен: /opt/kerio/mailserver/plugins/spamassassin/rules/kerio-antispam.cf (185 432 байт), SHA-256 подтверждён на сервере.
Служба kerio-connect перезапущена — правила применены.
```

**Кнопка «🔐 Установить сертификат»** кладёт `server.crt` и `server.key` выбранного сертификата в `/opt/kerio/mailserver/sslcert` с правами `644` / `600` и владельцем `kerio:kerio`, после чего (по галочке) перезапускает службу.

**Кнопка «🔄 Перезапустить Kerio»** — просто `systemctl restart kerio-connect` (или init.d-скрипт) с понятной ошибкой, если прав не хватает.

**Кнопка «📥 Скачать shell-скрипт»** — файл `install-kcm-antispam.sh`. Он делает то же самое, но **на самом сервере**, без SSH из программы: полезно в закрытом контуре, где открыты только 80/443.

```bash
sudo sh install-kcm-antispam.sh
# или с локальным файлом (без интернета):
sudo sh install-kcm-antispam.sh ./kerio-antispam.cf
```

#### Что нужно на стороне сервера, чтобы SSH работал

```bash
# 1. SSH-сервер запущен
systemctl status ssh      # Debian/Ubuntu
systemctl status sshd     # RHEL-семейство

# 2. Вход root разрешён (или используйте обычного пользователя + sudo)
grep -E "^(PermitRootLogin|PasswordAuthentication)" /etc/ssh/sshd_config

# 3. Порт не закрыт фаерволом
firewall-cmd --list-ports            # firewalld
ufw status                           # ufw

# 4. Пользователь может sudo без пароля (если входите не root)
sudo -n true && echo "sudo без пароля работает"
```

💡 Галочка «Использовать `sudo -n`» включает режим, когда программа выполняет команды через `sudo -n` (без запроса пароля). Если на сервере `sudo` требует пароль — либо входите под `root`, либо добавьте строку в `sudoers`:

```
kcmadm ALL=(ALL) NOPASSWD: /bin/systemctl restart kerio-connect, /usr/bin/install, /bin/chown, /bin/chmod
```

### 20.5 Вариант B: программа прямо на Linux

Программа собирается под Linux без внешних зависимостей (один бинарник):

```bash
# из исходников (Go 1.22+)
git clone https://github.com/zigorminsk-debug/jiraHelp
cd jiraHelp/kerio-letsencrypt-win
go build -mod=vendor -o KerioCertManager .
sudo install -m 0755 KerioCertManager /opt/kerio-cert-manager/KerioCertManager
```

Запуск как сервиса (без окна, интерфейс — в браузере по адресу `http://127.0.0.1:17840`):

```bash
sudo /opt/kerio-cert-manager/KerioCertManager --server-only
```

Готовый unit для systemd — `/etc/systemd/system/kerio-cert-manager.service`:

```ini
[Unit]
Description=KerioCertManager (SSL + antispam for Kerio Connect)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/opt/kerio-cert-manager/KerioCertManager --server-only --listen 127.0.0.1:17840
Restart=on-failure
RestartSec=5
# сертификаты и настройки лежат рядом с бинарником
WorkingDirectory=/opt/kerio-cert-manager

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now kerio-cert-manager
systemctl status kerio-cert-manager
```

⚠️ Интерфейс слушает **только localhost**. Если нужен доступ с другого компьютера — не открывайте порт в интернет, а используйте SSH-туннель:

```bash
ssh -L 17840:127.0.0.1:17840 admin@mail.company.by
# затем в браузере на своей машине: http://127.0.0.1:17840
```

🖥️ На Linux нет WebView2-окна (оно есть только в Windows-сборке), поэтому интерфейс открывается в браузере. Это ожидаемо.

### 20.6 Сертификаты на Linux

Программа кладёт в `/opt/kerio/mailserver/sslcert` два файла:

| Файл | Что внутри | Права |
|---|---|---|
| `server.crt` | сертификат + цепочка (fullchain) | `644`, владелец `kerio:kerio` |
| `server.key` | приватный ключ (RSA 2048, PKCS#1) | `600`, владелец `kerio:kerio` |

Вручную то же самое:

```bash
sudo install -m 644 -o kerio -g kerio server.crt /opt/kerio/mailserver/sslcert/server.crt
sudo install -m 600 -o kerio -g kerio server.key /opt/kerio/mailserver/sslcert/server.key
sudo systemctl restart kerio-connect
```

Дальше в Kerio WebAdmin: **Конфигурация → SSL-сертификаты → Добавить → Импорт из файла** → выберите `server.crt` и `server.key` (либо «Использовать существующий» — Kerio подхватит файлы из `sslcert`). Подробнее про окно Kerio — [раздел 9.17](#917-включение-и-управление-базой-из-kerio-webadmin) и [раздел 4](#4-вкладка-2--установка-в-kerio-connect).

⚠️ Имя активного профиля может быть не `server`, а `cert_1` — тогда Kerio читает `cert_1.crt`/`cert_1.key`. Посмотреть активное имя:

```bash
grep -i -A3 "ssl" /opt/kerio/mailserver/mailserver.cfg | head -20
```

### 20.7 Задания по расписанию (cron)

| Задание | Файл | Когда запускается |
|---|---|---|
| Автопродление сертификатов | `/etc/cron.d/kerio-cert-manager-autorenew` | ежедневно в 03:15 |
| Обновление антиспам-базы | `/etc/cron.d/kerio-cert-manager-antispam` | ежедневно в 04:10 |

Включить/выключить можно из интерфейса (кнопки «Включить автопродление» и «Включить автообновление») либо командой:

```bash
sudo /opt/kerio-cert-manager/KerioCertManager --install-tasks   # создать оба задания
sudo /opt/kerio-cert-manager/KerioCertManager --remove-tasks    # удалить
```

Проверить, что задания есть:

```bash
ls -la /etc/cron.d/kerio-cert-manager-*
cat /etc/cron.d/kerio-cert-manager-antispam
```

Проверить, что задание реально сработало:

```bash
grep kerio-cert-manager /var/log/cron        # RHEL-семейство
grep CRON /var/log/syslog | grep kerio       # Debian/Ubuntu
```

⚠️ Файлы в `/etc/cron.d` должны принадлежать `root` и **не** быть доступны на запись группе/остальным (`644`), иначе cron их игнорирует. В конце файла обязательна пустая строка.

### 20.8 Порты и фаервол

| Порт | Зачем | Откуда должен быть доступен |
|---|---|---|
| 22 | SSH (управление из программы) | только с вашей рабочей машины |
| 80 / 443 | сайт и Let's Encrypt (HTTP-01 / TLS-ALPN-01) | из интернета |
| 25 / 465 / 587 / 993 / 995 / 143 | почта | из интернета |
| 4040 | Kerio WebAdmin / Admin API | только из вашей сети |
| 17840 | локальный интерфейс KerioCertManager | только `127.0.0.1` |

Открыть порты (примеры):

```bash
# firewalld
sudo firewall-cmd --permanent --add-service=http --add-service=https --add-service=smtp --add-service=smtps
sudo firewall-cmd --reload

# ufw
sudo ufw allow 80,443/tcp
sudo ufw allow 25,465,587,993,995/tcp
sudo ufw reload
```

Если Let's Encrypt не может достучаться по порту 80 (провайдер режет), используйте **DNS-01** — он работает без открытых портов (см. раздел 3.6).

### 20.9 Типичные ошибки на Linux

| Сообщение / симптом | Причина | Решение |
|---|---|---|
| `Permission denied (publickey,password)` | неверный логин/ключ, или вход закрыт | проверьте `sshd_config`, попробуйте `ssh -v user@host` в терминале |
| `sudo: a terminal is required to read the password` | `sudo` требует пароль | входите под `root` или настройте `NOPASSWD` (см. 20.4) |
| `sudo: sorry, you must have a tty to run sudo` | в `sudoers` стоит `requiretty` | закомментируйте `Defaults requiretty` или используйте `root` |
| `Host key verification failed` | ключ сервера изменился | если сервер не переустанавливали — проверьте, не подменён ли хост; после переустановки предупреждение ожидаемо |
| `Нет связи с host:22` | фаервол/DNS/неверный порт | `nc -vz host 22`, `firewall-cmd --list-ports` |
| `Каталог Kerio не найден` | Kerio в нестандартном месте | укажите путь вручную, например `/data/kerio/mailserver` |
| `не удалось определить каталог правил SpamAssassin` | старая сборка Kerio | укажите путь `.../plugins/spamserver/spamassassin/rules` вручную |
| Правила установлены, но `X-Spam-Status` без `KCM_…` | файл не прочитан: права/SELinux/не перезапустили | см. 9.18 и 20.6 |
| `systemctl: command not found` | нет systemd | программа автоматически пробует `/etc/init.d/kerio-connect` |
| `Job for kerio-connect.service failed` | ошибка в конфигурации Kerio | `journalctl -u kerio-connect -n 100 --no-pager` |

## 21. Установщик и автообновление программы

Начиная с версии 4.6.0 у программы есть **два способа установки** и **встроенное автообновление**.

### 21.1 Что положить рядом с программой — не нужно

Раньше программа была одним `.exe`, который можно было положить куда угодно. Такой режим остался (портативная версия), но теперь есть и настоящий установщик.

| Файл в релизе | Что это | Кому |
|---|---|---|
| `KerioCertManager-Setup-<версия>.exe` | **Установщик** (Inno Setup): ярлыки, меню «Пуск», деинсталлятор | Большинству: поставил и забыл |
| `KerioCertManager.exe` | Портативная программа (один файл) | Если нельзя ставить программы / нужна флешка |
| `KerioCertManager-Windows-x64.zip` | Архив: программа + инструкция + иконки | Для передачи коллеге целиком |

### 21.2 Установка

1. Скачайте `KerioCertManager-Setup-4.6.0.exe` со страницы релиза.
2. Запустите двойным щелчком. Установщик запросит права администратора (это нормально: программа управляет службой Kerio и заданиями Планировщика).
3. Нажмите «Далее» → «Установить». По умолчанию программа ставится в `C:\Program Files\KerioCertManager`.
4. Поставьте галочку «Создать ярлык на рабочем столе», если нужен.
5. Готово: в меню «Пуск» появится **KerioCertManager**, рядом — ярлыки на инструкцию.

**Тихая установка** (для развёртывания групповой политикой):

```bat
KerioCertManager-Setup-4.6.0.exe /S /D=C:\KerioCertManager
```

- `/S` — без вопросов и окон;
- `/D=...` — папка установки (пишется **последним**, без кавычек).

**Удаление:** «Параметры → Приложения → KerioCertManager → Удалить» (или `Uninstall` в меню «Пуск»).

⚠️ **Что удаляется, а что нет:** программа удаляется, задания Планировщика (`KerioLetsEncryptAutoRenew`, `KerioCertManager_AntiSpamDB`) снимаются автоматически, а вот папка с сертификатами и настройками (`certs`) **остаётся** — чтобы вы случайно не потеряли приватные ключи. Удалите её вручную, если она больше не нужна.

### 21.3 Автообновление: как это работает

0. **В любой момент можно проверить вручную:** кнопка **🔄 Проверить обновления** в правом верхнем углу (в шапке, она видна на любой вкладке). Один клик — свежий запрос к GitHub, итог появляется в тосте: «Обновлений нет: у вас последняя версия vX» или «Доступна версия vY», после чего страница прокручивается наверх к баннеру с кнопкой **⬇ Обновить сейчас**. Когда новая версия уже найдена, у кнопки горит **жёлтая пульсирующая точка**. Там же, в 🧰 Инструменты → «Обновления программы», есть кнопка **🔍 Проверить сейчас** и полный журнал проверки.
1. При запуске (и далее не чаще одного раза в 6 часов) программа тихо спрашивает GitHub: «какая последняя версия?».
2. Если версия новее вашей — сверху появляется **зелёный баннер**: «Вышла новая версия», список изменений и кнопки.
3. **⬇ Обновить сейчас** — программа скачивает новый `.exe`, сверяет SHA-256 с тем, что указан в релизе, и только после этого:
   - переименовывает текущий файл в `KerioCertManager.exe.old`;
   - записывает новый;
   - перезапускает себя с теми же параметрами;
   - при следующем старте удаляет `.old`.
4. **Пропустить версию** — баннер про эту версию больше не появится (но следующая, более новая, снова покажется).
5. **✕** — скрыть до следующего запуска.

| Настройка | Где | Значение по умолчанию |
|---|---|---|
| Проверять обновления автоматически | 🧰 Инструменты → «Обновления программы» | включено |
| Интервал проверки | фиксированный | 6 часов |
| Пропущенная версия | там же, кнопка «↩ Сбросить пропущенные версии» | не задана |

**Почему обновление безопасно:**

- проверяется **SHA-256** — если файл по дороге подменили или он скачался битым, обновление отменяется;
- проверяется, что скачался действительно `.exe` (сигнатура `MZ`);
- старый файл не удаляется, а переименовывается — при сбое его легко вернуть;
- сертификаты, настройки и база лежат в отдельных файлах и **не затрагиваются**.

### 21.4 Если обновление не работает

| Симптом | Причина | Решение |
|---|---|---|
| Баннер не появляется | проверка отключена, или прошло меньше 6 часов, или нет интернета | нажмите **🔄 Проверить обновления** в шапке (или 🧰 Инструменты → «🔍 Проверить сейчас») |
| «Проверка не удалась… rate limit» | GitHub ограничивает анонимные запросы (403/429) | подождите 10–60 минут, проверьте вручную на странице релизов |
| «Не удалось скачать обновление» | прокси/фаервол блокирует `github.com` | скачайте `Setup.exe` вручную с сайта релизов |
| «не удалось заменить программу (нет прав на папку)» | программа лежит в `Program Files`, а запущена без прав администратора | закройте программу и запустите от имени Администратора, либо обновитесь через `Setup.exe` |
| После обновления открылась старая версия | запустился ярлык на старый `.exe` | удалите старый файл, ярлык из установщика указывает на актуальный |
| Антивирус ругается на новый файл | эвристика на свежий неподписанный `.exe` | добавьте папку в исключения; SHA-256 из релиза подтверждает подлинность |

**Проверка версии из командной строки:**

```bat
"C:\Program Files\KerioCertManager\KerioCertManager.exe" --version
"C:\Program Files\KerioCertManager\KerioCertManager.exe" --check-update
```

Вторая команда печатает JSON с полями `latest`, `available`, `exeUrl`, `exeSha256` — удобно для скриптов мониторинга.

### 21.5 Где хранятся настройки после установки

| Путь | Что там |
|---|---|
| `C:\Program Files\KerioCertManager\KerioCertManager.exe` | сама программа |
| `C:\Program Files\KerioCertManager\certs\` | сертификаты, настройки, история, база |
| `C:\Program Files\KerioCertManager\FAQ.md`, `README.md` | инструкция рядом |
| `%ProgramData%\Microsoft\Windows\Start Menu\Programs\KerioCertManager` | ярлыки меню «Пуск» |

💡 Если нужен полный контроль над папкой сертификатов — запускайте программу с `--certs-dir D:\certs` (например, чтобы сертификаты лежали на защищённом диске).

## 22. Android-приложение: пульт и проверки с телефона

Приложение **KerioCertManager Mobile** ставится на телефон и умеет две разные вещи. Их не нужно путать — от этого зависит, что вы вообще сможете сделать с телефона.

| Вкладка | Что делает | Нужен ли компьютер |
|---|---|---|
| **📱 Пульт** | Открывает на телефоне саму программу, запущенную на компьютере: все вкладки, выпуск сертификата, установка в Kerio, инструкция | **Да**, и телефон с компьютером в одной сети Wi-Fi |
| **🔎 Проверка** | Проверяет домен прямо с телефона: SSL-сертификат, DNS (MX/SPF/DMARC), почтовые порты, спам-базы | Нет, нужен только интернет |

### 22.1 Установка APK на телефон

1. Скачайте файл **`KerioCertManager-Mobile-v4.9.2.apk`** со страницы релизов GitHub на телефон (или перекиньте файл по кабелю/Telegram и откройте его).
2. Android спросит разрешение «Устанавливать неизвестные приложения из этого источника» — разрешите для файлового менеджера или браузера (это стандартное окно: APK не из Google Play).
3. Нажмите **Установить**, затем **Открыть**.
4. Если Play Защита показывает предупреждение «приложение не проверено» — выберите **«Установить всё равно»**. APK собран из исходников этого репозитория, но не подписан платным ключом Google.

> ⚠️ **Про обновление приложения.** Если APK собран с одноразовым тестовым ключом, Android не поставит новую версию поверх старой. Удалите старое приложение, затем установите новое. Данные на телефоне при этом не теряются: приложение ничего не хранит, кроме последнего адреса пульта.

### 22.2 Режим «📱 Пульт»: управление программой с телефона

Это полноценный доступ ко всем функциям программы — просто экран маленький. Работает так: программа на компьютере открывает **второй** сетевой порт (по умолчанию 17840) и пускает в него только тех, кто знает код из 6 цифр.

**На компьютере:**

1. Откройте вкладку **2. Установка в Kerio** → карточку **📱 Android-пульт**.
2. Нажмите **«Включить пульт»**.
3. Появится **код доступа из 6 цифр** и адрес вида `192.168.1.5:17840`.
4. Если Windows спросит про доступ в сеть — разрешите для **частных сетей** (не «общедоступных»).

**На телефоне:**

1. Вкладка **📱 Пульт**.
2. Введите адрес из карточки (без `http://`, только `192.168.x.x:17840`).
3. Введите код из 6 цифр.
4. Нажмите **«Подключиться»** — откроется интерфейс программы.

**Как выключить:** на компьютере **«Выключить»** в той же карточке. После этого телефон не сможет подключиться, даже если помнит адрес.

| Кнопка в карточке | Что делает |
|---|---|
| **Включить пульт** | Открывает сетевой порт и создаёт новый код. Адрес и код показываются тут же |
| **🔄 Сменить код** | Меняет код, не выключая пульт. Уже открытая страница на телефоне перестаёт работать до повторного входа |
| **Выключить** | Закрывает порт и забывает код |

**Если не подключается:**

| Что видите | Причина | Что делать |
|---|---|---|
| «Страница недоступна» на телефоне | Телефон и компьютер в разных сетях | Оба должны быть в одной Wi-Fi сети. Мобильный интернет и гостевая Wi-Fi не подходят |
| Долго грузится и обрывается | Брандмауэр Windows блокирует порт | При первом включении пульта разрешите доступ в окне брандмауэра; вручную: «Брандмауэр Защитника Windows» → «Разрешить приложение» → KerioCertManager → «Частные сети» |
| «Неверный код доступа» | Введён старый код (после «Сменить код») | Посмотрите текущий код в карточке на компьютере |
| Открывается, но пусто | Открыт старый кэш браузера | Нажмите «Другой адрес» и подключитесь заново |
| Адрес `127.0.0.1` | Это адрес самого компьютера | Используйте адрес из карточки — вида `192.168.x.x` |

> 🔒 **Безопасность.** Пульт — это полный доступ к программе, а значит к установке сертификатов и настройкам Kerio. Код действует только пока пульт включён и меняется при каждом включении. Не включайте пульт в открытой Wi-Fi сети (кафе, аэропорт) и выключайте, когда закончили.

### 22.3 Режим «🔎 Проверка»: диагностика без компьютера

Введите домен (`mail.example.com`) и нажмите **«Проверить»**. Проверяется:

| Проверка | Что показывает |
|---|---|
| **SSL-сертификат** | до какой даты действует, сколько дней осталось, кто выдал, какие имена внутри, сколько сертификатов в цепочке |
| **DNS** | IP-адрес (A/AAAA), MX-записи (кто принимает почту), SPF, DMARC, наличие DKIM |
| **Порты** | 443, 25, 587, 465, 993, 995, 4040 — открыты или нет |
| **Спам-базы** | IP и домен в 6+ базах (Spamhaus, SpamCop, Barracuda, SORBS, CBL, DBL) |

Итог показывается сверху: **«Всё в порядке»**, **«Критичных проблем нет, замечаний: N»** или **«Найдено проблем: N»**. Кнопка **📋 Отчёт** копирует весь список в буфер обмена — удобно отправить коллеге.

**Что телефон не умеет и почему:**

- **Не выпускает сертификаты.** Для Let's Encrypt нужно подтвердить владение доменом (HTTP-01/DNS-01) и сохранить приватный ключ. Ключ должен оставаться на сервере, а не на телефоне.
- **Не устанавливает сертификаты в Kerio.** Для этого нужен доступ к Admin API изнутри сети и права администратора — это делает программа на компьютере (или режим «Пульт»).
- **Не работает с антиспам-базой и автопродлением** — это задачи ПК и Планировщика Windows.

### 22.4 Что делать по результатам проверки с телефона

| Результат | Что делать дома/в офисе |
|---|---|
| Сертификат истекает или истёк | Открыть программу на компьютере → вкладка «Выпуск сертификата» → выпустить и установить |
| MX-записи не найдены | Проверить домен у регистратора: без MX почта на домен не приходит |
| Нет SPF или DMARC | Добавить записи в DNS (в программе есть «Конструктор DNS-зоны» на вкладке «Инструменты») |
| Порт 25 закрыт | Проверить в Kerio: Logs → SMTP, и уточнить у провайдера, не блокирует ли он 25 |
| IP или домен в спам-базах | Вкладка «Выход из блэклистов» в программе — готовые заявки на удаление |
| Порт 4040 не отвечает | Это нормально снаружи: админка Kerio не должна быть видна из интернета |
