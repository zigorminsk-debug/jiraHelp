💡 Важные особенности SSL в Kerio Connect

          
    
            
  • Почему нужен Fullchain (server.crt): почтовые клиенты Outlook, Android и iOS требуют, чтобы сервер отдавал не только сертификат домена, но и промежуточный корневой сертификат Let's Encrypt (R10/R11/E5). Наш файл server.crt уже объединяет их в правильном порядке.
    • 
            
  • Почему RSA 2048 Traditional PKCS#1 (BEGIN RSA PRIVATE KEY): встроенный SSL-движок Kerio Connect гарантированно читает незашифрованные ключи RSA 2048/4096 бит на всех версиях Kerio (8.x, 9.x, 10.x).
    • 
            
  • Проверяемые почтовые протоколы после установки: HTTPS WebMail (443), SMTPS (465), SMTP STARTTLS (25 / 587), IMAPS (993), POP3S (995).

2️⃣ Обязательные настройки внутри Kerio Connect WebAdmin (https://IP:4040/admin/)

            
    
              
  • Интернет-имя SMTP (HELO): Конфигурация → Сервер SMTP → вкладка Общие → «Имя узла в сети Интернет» = mail.company.by (обязательно должно совпадать с PTR и A-записью, а НЕ быть локальным именем Windows типа WIN-SERVER.local!).
    • 
              
  • Включение подписи DKIM: Конфигурация → Домены → двойной клик по домену → вкладка Общие (внизу блок DomainKeys/DKIM) → включить галочку подписи DKIM → нажать ссылку «Показать открытый ключ...» → создать TXT mail._domainkey в DNS → подождать 3–5 мин и нажать «ОК» внизу окна домена (Kerio автоматически проверяет DNS прямо при нажатии «ОК» — если окно закрылось без предупреждения, ключ принят!).
    • 
              
  • Защита от Open Relay (пересылки чужого спама): Конфигурация → Сервер SMTP → вкладка Контроль реле (Relay Control) → разрешить релей только для 127.0.0.1 + включить галочку «Пользователи, прошедшие аутентификацию по SMTP, могут пересылать сообщения куда угодно».
    • 
              
  • Доверенный SSL с полной цепочкой (Fullchain): Конфигурация → Сертификаты SSL — активный сертификат mail.company.by должен включать промежуточный сертификат Let's Encrypt (наша кнопка на вкладке «Установка в Kerio Connect» загружает сразу полный server.crt и делает его активным!).
    • 
            

          


          

            
3️⃣ Главная ловушка на роутерах MikroTik / Kerio Control и какие порты пробрасывать снаружи

            
    
              
  • Какие TCP-порты пробросить с WAN на внутренний IP Kerio: 25 (приём внешней почты), 465 и 587 (защищённая отправка для сотрудников с телефонов/ноутбуков вне офиса), 993 (IMAPS), 443 (WebMail + ActiveSync + Autodiscover) и при выпуске HTTP-сертификата — 80. Порт админки 4040 наружу в интернет НЕ открывайте (оставьте доступным только из LAN/VPN)!
    • 
              
  • Опасная ошибка Masquerade: в правиле srcnat / masquerade на MikroTik обязательно указывайте out-interface-list=WAN (внешний интерфейс провайдера)! Если включить глобальный masquerade на все интерфейсы, все входящие спам-соединения на порт 25 будут приходить в Kerio с локальным IP роутера (например, 10.146.100.1), из-за чего не работают RBL-списки в Kerio и возникает риск Open Relay!
