## 🆕 Что нового в v4.9.1: установка SSL в Kerio Connect 10 и читаемые сообщения службы

| Что изменилось | Как теперь выглядит |
|---|---|
| **Добавление SSL-сертификата в Kerio Connect 10** | У Kerio два разных набора методов для SSL: `Certificates.*` (9.2+/10.x — его использует веб-админка новых сборок) и `ConnectCertificate.*` (8.5–9.1). Программа больше не угадывает: спрашивает сервер, какой интерфейс есть, отправляет импорт правильными параметрами (`keyId` + `name` + `type=InactiveCertificate` для нового, `id` + `password` для старого) и при ошибке «метод/параметры» пробует второй интерфейс, а не останавливается |
| **Активация и проверка результата** | После импорта сертификат делается активным (`Certificates.setActive` → `ConnectCertificate.setActive`), затем список сертификатов перечитывается: в отчёте появляется «Kerio подтвердил активный сертификат …» либо предупреждение с точным путём, где включить его вручную |
| **Никакого ложного «нет прав»** | Ответы «метод не найден», «неверные параметры», «не JSON-RPC» больше не превращаются в «у учётки нет прав на SSL». В карточке входа это предупреждение, вердикт остаётся зелёным: `Права подтверждены, но API сертификатов этой сборки Kerio отвечает непривычно` |
| **🧪 Проверить API сертификатов** | Новая кнопка рядом с «Проверить вход»: показывает, какие методы SSL реально есть на сервере, какие параметры он принимает и что ответил на каждый запрос. Отчёт копируется одной кнопкой и прикладывается к заявке без догадок |
| **Ответ Kerio виден в каждой ошибке** | В тексте ошибки теперь есть сырой ответ сервера (`Ответ Kerio: {"jsonrpc":…}`), поэтому причину видно сразу, а не по пересказу |
| **Перезапуск службы без кракозябр** | Вместо `net stop/start` с выводом в CP866 — `sc.exe` и декодирование OEM-кодировки: сообщения читаются по-русски, без `NET HELPMSG 2185` и `exit status 2`. Имя службы определяется автоматически, после команды программа ждёт фактического состояния `RUNNING`/`STOPPED` и показывает его в интерфейсе |

Покрыто тестами (`v491_test.go`, `console_text_test.go`): установка через `Certificates.*` на фальшивом Kerio 10, сохранение совместимости с 8.5–9.1, отсутствие ложного вердикта «нет прав» при ошибке метода, реальный отказ в правах по-прежнему красный, разбор `STATE : 4 RUNNING`, декодирование CP866 и очистка `NET HELPMSG`.

## Ключевые возможности

1. **Выпуск сертификатов по введённому Домену и IP-адресу:**
   - Автоматическая предпроверка **DNS A/AAAA ↔ IP**, определение NAT-маршрутизации и доступности портов `80` / `443`.
   - Поддержка кириллических IDN-доменов (`.бел`, `.рф`) с автоматическим Punycode-преобразованием.
   - Быстрое добавление почтовых SAN-поддоменов Kerio в 1 клик: `webmail.<домен>`, `autodiscover.<домен>`, `smtp.<домен>`, `imap.<домен>`, `pop3.<домен>`.
   - Поддержка **обоих профилей Let's Encrypt**:
     - **Classic (90 дней)** — стандартный доменный SSL-сертификат с проверкой привязки к указанному IP;
     - **Short-lived IP + Domain SAN (160 часов, RFC 8738)** — включение и домена, и публичного IP-адреса непосредственно в поле `Subject Alternative Name (SAN)` сертификата Let's Encrypt!
   - Три режима работы: **Let's Encrypt Production**, **Let's Encrypt Staging** (проверка без лимитов), а также **Локальный (Self-Signed для Kerio)** для мгновенной оффлайн-генерации и тестирования.

2. **4 способа прохождения проверки ACME (даже если порт 80 занят Kerio или закрыт):**
   - **HTTP-01 (Встроенный сервер, порт 80)** + опция *автоматической остановки службы `KerioMailServer` на 5–15 секунд проверки с мгновенным обратным запуском*;
   - **TLS-ALPN-01 (Встроенный сервер, порт 443, RFC 8737 `acme-tls/1`)**;
   - **HTTP-01 Webroot** (запись токена в папку запущенного IIS / веб-сервера без остановки порта 80);
   - **Интерактивный DNS-01 (`_acme-challenge` TXT)** — работает даже за закрытым файрволом без открытых портов `80`/`443`!

3. **Полная совместимость с Kerio Connect (Kerio MailServer):**
   - Генерирует незашифрованный приватный ключ **RSA 2048 / 4096 бит в классическом формате OpenSSL PKCS#1 (`-----BEGIN RSA PRIVATE KEY-----`)**, который гарантированно принимается всеми версиями Kerio Connect (`8.x`, `9.x`, `10.x`).
   - Формирует правильный файл **`server.crt` (`fullchain`)** = сертификат домена + промежуточная цепочка Let's Encrypt CA (чтобы Outlook, iOS Mail, Android и Thunderbird не выдавали ошибку недоверенной цепочки), а также отдельные `cert-only.crt`, `chain.crt`, PKCS#12 `.pfx`, `.csr`, автоустановщик `install-kerio.bat` и единый `.zip`-архив.
   - **Проверка входа под администратором** (карточка **🔐 Вход под администратором Kerio Connect** вверху вкладки 2): подтверждает логин и пароль, показывает роль и версию сервера, а при неудаче объясняет причину и даёт пошаговый план устранения — без единого изменения на сервере.
   - **3 способа установки в Kerio Connect:**
     1. Автоматическое копирование в `C:\Program Files\Kerio\MailServer\sslcert\` с авто-бэкапом старых ключей, чтением активного профиля из `mailserver.cfg` (`server` или `cert_1`/`cert_2`) и перезапуском службы `KerioMailServer`;
     2. Бесшовный онлайн-импорт через **Kerio Connect Admin JSON-RPC API (`https://127.0.0.1:4040/admin/api/jsonrpc/`)** (`Session.login` → `Certificates.import` → `Certificates.setActive`) **без остановки почтовых служб**;
     3. Ручной импорт скачанных файлов `server.crt` и `server.key` через веб-консоль Kerio Connect Administration.

4. **Автопродление через Планировщик заданий Windows (`schtasks.exe`):**
   - Регистрация системной задачи `KerioLetsEncryptAutoRenew` (`KerioCertManager.exe --renew`) в 1 клик прямо из интерфейса программы.

## Быстрый запуск на Windows Server

1. Скопируйте **`KerioCertManager.exe`** в папку на сервере (например, `C:\KerioCertManager\KerioCertManager.exe`).
2. Нажмите правой кнопкой мыши → **«Запуск от имени администратора»** *(либо нажмите кнопку повышения прав UAC прямо в верхней панели окна программы)*.
3. Введите **Доменное имя** (например, `mail.company.by`) и **IP-адрес** сервера, нажмите **«Сгенерировать ключ и выпустить сертификат»**.
4. Установите сертификат в Kerio Connect кнопкой **«Установить в Kerio Connect»** или импортируйте созданные файлы `server.crt` и `server.key` в разделе **Configuration → SSL Certificates → Import**.

## 🔎 Не нашлась папка SpamAssassin в Kerio (`v4.5.1`)

Если при установке базы программа пишет «не найден каталог SpamAssassin Kerio Connect» — нажмите на вкладке «Антиспам» кнопку **«🔎 Что проверено»**. Поиск идёт по цепочке:

1. путь, введённый вручную (в том числе сразу папка `rules` или сетевой путь `\\SERVER\c$\...`);
2. команда запуска службы `KerioMailServer` (`sc qc` + `ImagePath` из реестра) — ловит нестандартные диски (`D:\Kerio\MailServer`);
3. значения реестра Kerio (`InstallPath`, `Path`, `InstallLocation`);
4. стандартные каталоги на всех дисках (включая `Program Files (x86)` и `%ProgramFiles%`);
5. обход дерева Kerio: папка `spamassassin` (в т.ч. внутри `spamserver`) или любая папка с настоящими `*.cf`-правилами.

Отчёт показывает каждый проверенный путь, состояние службы и права администратора, а также кнопки «⤵ Подставить папку» и «⬇ Скачать .cf» — для случая, когда Kerio стоит на другом сервере или на Linux. Подробная пошаговая инструкция — в ФАК, п. 9.16 (в самой программе: вкладка **📖 ФАК**).

## 🛡️ Антиспам-база KCM с автообновлением с GitHub (`v4.4`)

Новая вкладка **«🛡️ Антиспам-база KCM (GitHub)»** ставит в Kerio Connect ежедневно обновляемую базу индикаторов спама/фишинга и следит за её актуальностью.

| Кнопка | Что делает |
|---|---|
| 🔎 Проверить обновления на GitHub | Показывает установленную и актуальную версию базы, дату сборки и количество записей |
| 👁 Предпросмотр установки (dry-run) | Скачивает файл, проверяет **SHA-256** и показывает, какие правила добавятся/исчезнут. В Kerio пока ничего не пишется |
| ⬇️ Установить / Обновить базу в Kerio | Резервная копия → запись `kerio-antispam.cf` в `plugins\spamassassin\rules\` → проверка SHA-256 → перезапуск службы |
| ⏪ Откатить | Возвращает предыдущую версию из `certs\antispam\backup` |
| 🗑 Удалить базу | Убирает правила из Kerio (копия остаётся в резервных) |
| ✅ Включить автообновление | Задание Планировщика `KerioCertManager_AntiSpamDB` (`KerioCertManager.exe --antispam-update`) каждые 6/12/24 часа |
| 🚀 Проверить и обновить сейчас | Немедленная проверка GitHub и установка новой версии |
| 🔬 Проверить письмо по антиспам-базе | Dry-run: показывает сработавшие правила и сумму очков SpamAssassin для вставленного письма |

**Группы правил и очки:** домены отправителей `+3.2`, адреса отправителей `+4.5`, мотивы в теме `+1.8`, фразы мошеннических писем `+1.5`, домены фишинговых ссылок `+2.5`, IP/CIDR источников в `Received` `+3.0`, белый список `−6.0`.

**Где смотреть результат:**

- Версия установленной базы и количество правил — в карточке статуса вкладки «🛡️ Антиспам-база KCM (GitHub)».
- В заголовках доставленных писем появятся правила `KCM_*` в `X-Spam-Status` и итоговый `X-Spam-Score` — по ним видно, какие группы базы сработали.
- Актуальный релиз базы: `https://github.com/zigorminsk-debug/jiraHelp/releases/tag/antispam-db-latest` (файл `kerio-antispam.cf` + `manifest.json` с SHA-256).

**Что важно знать:**

1. Ставится **один файл** `kerio-antispam.cf` в папку правил SpamAssassin; `mailserver.cfg` и база пользователей не меняются.
2. Новые правила применяются **после перезапуска службы** `KerioMailServer` (программа делает это автоматически, если включена галочка и запущены права Администратора). Альтернатива без перезапуска — включить/выключить SURBL в Контент-фильтре и нажать «Применить».
3. Перед записью всегда создаётся резервная копия, после записи файл проверяется по SHA-256; откат — одной кнопкой.
4. Если GitHub недоступен (закрытый контур), используйте **«Импорт файла базы»**: скачайте `kerio-antispam.cf` со страницы релиза и укажите путь.
5. Источники: Phishing.Database (MIT), OpenPhish, ShadowWhisperer BlockLists, HaGeZi TIF, Dogino, Spamhaus DROP, FireHOL level1 + курируемые списки. URLhaus (abuse.ch) требует бесплатный Auth-Key — включается секретом `ABUSECH_AUTH_KEY`; phishing.army заменён на Phishing.Database из-за Cloudflare-заглушки. Сборщик и формат — в каталоге `antispam-db/`.

## 🩺 Почему программа не подключается к Kerio и как это исправить (`v4.3`)

В версии **4.3** добавлена кнопка **«🩺 Диагностика подключения к Kerio»**, которая проходит подключение по шагам и показывает точную причину сбоя: `DNS → TCP :4040 → TLS → веб-админка → вход администратора → права → версия → сертификаты → загрузка файлов`.

### Исправленные причины сбоя установки сертификата

| Причина | Что было | Что сделано в 4.3 |
|---|---|---|
| **Неверный формат загрузки файла** | Файл отправлялся как multipart-часть `name="newFile.bin"`, Kerio её не принимал и не возвращал `fileId` → импорт ключа падал | Файл отправляется в официальном формате Kerio: часть `name="unknown"; filename="newFile.bin"` (как в *Kerio APIs Client Library for PHP 1.4.0.234*), плюс автоматический перебор альтернативных вариантов |
| **Редиректы и HTML вместо JSON** | Kerio отвечал `302` на страницу логина, Go шёл по редиректу, превращал `POST` в `GET` и возвращал HTML → ошибка «некорректный ответ Kerio API» | Редиректы больше не выполняются автоматически; ответ распознаётся как HTML и выдаётся точная причина («неверный путь/порт», «это Kerio Control») |
| **Непонятные сетевые ошибки** | Любой сбой выглядел как `dial tcp ...: i/o timeout` | Каждый слой (DNS, TCP, TLS, HTTP, JSON-RPC) диагностируется отдельно, с русским объяснением и планом исправления |
| **Импорт без активации** | Резервный путь `Certificates.*` импортировал сертификат, но не делал его активным | Добавлена активация (`ConnectCertificate.setActive` / `Certificates.setActive`) и **проверка**, что Kerio показывает активным именно установленный сертификат |
| **Скрытые ошибки прав** | Учётка-пользователь домена «входила», но импорт падал с невнятной ошибкой | После входа вызывается `Session.whoAmI` — программа явно сообщает, что учётка не администратор |
| **Автоподстановка домена** | В поле хоста подставлялся `mail.<домен>`, а порт 4040 в интернет не публикуется → таймаут | Домен больше не подставляется; добавлен поиск Kerio в сети и подсказка про внутренний IP/VPN |
| **Несовместимый TLS/HTTP2** | Старые сборки Kerio не умеют TLS 1.2/HTTP/2, соединение рвалось | Разрешён TLS 1.0+ для старых сборок, HTTP/2 отключён, keep-alive выключен (Kerio отдаёт `Connection: close`) |

### Самые частые причины и быстрые решения

1. **`Порт 4040 закрыт` / таймаут.** Порт админки Kerio **не публикуется в интернет**. Укажите внутренний IP сервера (например `10.146.100.14`) и подключитесь по VPN/из локальной сети — либо запустите программу прямо на сервере Kerio с адресом `127.0.0.1`.
2. **`Неверный логин или пароль`.** Логин мастер-администратора по умолчанию — `admin` (**без** `@домена`). Это учётка администратора Kerio Connect, а не почтовый ящик.
3. **Включена 2FA.** JSON-RPC API Kerio не поддерживает вход с одноразовым кодом. Создайте отдельного администратора без 2FA: **Configuration → Administration → Administrators → Add**.
4. **Учётка не администратор.** Пользователь домена (например `info@leend.by`) не сможет импортировать сертификат — нужен полный администратор Kerio Connect.
5. **Это Kerio Control, а не Kerio Connect.** У Kerio Control порт `4081` и другой набор методов — программа сообщит об этом явно.
6. **После неудачных попыток вход заблокирован.** Kerio включает защиту от подбора паролей — подождите 10–30 минут.

### Проверка через PowerShell (без программы)

```powershell
# 1. Открыт ли порт админки
Test-NetConnection 10.146.100.14 -Port 4040

# 2. Вход в Kerio Admin API и получение списка сертификатов
$body = '{"jsonrpc":"2.0","id":1,"method":"Session.login","params":{"userName":"admin","password":"ВАШ_ПАРОЛЬ","application":{"name":"test","vendor":"test","version":"1.0"}}}'
$r = Invoke-WebRequest -Uri "https://10.146.100.14:4040/admin/api/jsonrpc/" -Method POST -Body $body -ContentType "application/json-rpc" -SkipCertificateCheck
$token = ($r.Content | ConvertFrom-Json).result.token
Invoke-WebRequest -Uri "https://10.146.100.14:4040/admin/api/jsonrpc/" -Method POST -SkipCertificateCheck `
  -Headers @{ "X-Token" = $token } -ContentType "application/json-rpc" `
  -Body '{"jsonrpc":"2.0","id":2,"method":"Session.whoAmI"}'
```
